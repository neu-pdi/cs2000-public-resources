### Making Lists and Taking Them Apart

So far we've made lists by writing their elements between brackets, as in
`[1, 2, 3]`. While useful, this hides their true nature. Every list actually has
two parts: a _first_ element and the _rest_ of the list. The rest of the list is
itself a list, so it too has two parts... and so on.

Consider the list `[1, 2, 3]`. Its first element is `1`, and the rest of it is
`[2, 3]`. For this second list, the first element is `2` and the rest is `[3]`.
Try taking apart this third list. Its first element is `3` and the rest is
`[]`, the empty list.

Lists are an instance of _structured data_: data with component parts and a
well-defined format for the shape of the parts (tables are somewhat structured:
they have rows and columns, but different tables have different column names).
A predictable format lets us write programs based on that structure.

Languages provide built-in operations for taking apart structured data, called
_accessors_, which depend only on the structure of the data, not its contents.
For lists, we get the first element with `lst[0]` (the element at position
`0`), and the rest with `lst[1:]` (a _slice_ from position `1` to the end, as
with strings on [Day 11](/days/11)):

```python
l1 = [1, 2, 3]
e1 = l1[0]
l2 = l1[1:]
e2 = l2[0]
l3 = l2[1:]
e3 = l3[0]
l4 = l3[1:]

def test_first_and_rest():
    assert e1 == 1
    assert e2 == 2
    assert e3 == 3
    assert l2 == [2, 3]
    assert l3 == [3]
    assert l4 == []
```

Try: what are the accessors for tables?

Is there a way to also _build_ lists based on their structure? Operations for
building structured data are called _constructors_. Writing `[1, 2, 3]` doesn't
show that the rest is itself a list, but we can show it by adding a one-element
list, holding the first element, to the front of the rest. This builds the same
list:

```python
def test_building_lists():
    assert [1, 2, 3] == [1] + ([2] + ([3] + []))
```

Try: what differences do you notice between these two ways of writing lists?
Write a list of `"lychee"`, `"dates"`, `"mango"`, and `"durian"` in the second
way.

The second way is more verbose, and makes the elements harder to see: it isn't
convenient for humans, but it will prove very valuable for programs! It
highlights that there are _two different structures of lists_. A list is either:

- empty (written `[]`), or
- non-empty (written `[f] + r`, or with at least one value between the
  brackets), where _the rest is also a list_ (and so may in turn be empty or
  non-empty, ...).

So lists have two structural features, both important when writing programs:

1. Lists can be empty or non-empty
2. Non-empty lists have a first element and a rest of the list

### Some Example Exercises

Let's work through some concrete list-processing functions. Since `len` and
`sum` are built in (and PLL reports a name that hides a built-in), we'll name
ours with the prefix `my_`. As we'll see, one standard strategy works for all of
them.

### Structural Problems with Scalar Answers

We'll write examples in a very specific, stylized way. We should always have at
least two: one with `[]`, and one that is non-empty, to cover the two kinds of
lists. Then we should have more examples specific to the problem, and even more
to illustrate how we think about solving it.

#### `my_len`: Examples

What is the length of `[]`? It has _zero_ elements in it, so `my_len([])` should
be `0`. `[7]` clearly has one element, and `[7, 8, 9]` has three.

Now let's look at that last example in a different light. Its first element is
`7` and its rest is `[8, 9]`. `7` is a number, not a list, but `[8, 9]` is a
list, so we can ask for _its_ length, which is `2`. Its rest, `[9]`, has length
`1` (we asked about `[7]` before, but `[7]` isn't a _sub-list_ of `[7, 8, 9]`,
whereas `[9]` is), and the rest of that is `[]`, whose length is `0`. Putting
these together:

```python
def test_my_len():
    assert my_len([7, 8, 9]) == 3
    assert my_len([   8, 9]) == 2
    assert my_len([      9]) == 1
    assert my_len([       ]) == 0
```

Another way to write this (paying attention to the right side) is:

```python
def test_my_len():
    assert my_len([7, 8, 9]) == 1 + 2
    assert my_len([   8, 9]) == 1 + 1
    assert my_len([      9]) == 1 + 0
    assert my_len([       ]) ==     0
```

Where did the `2`, `1`, and `0` come from? They are the lengths of the rest of
each input list. Let's replace them with the `my_len` calls that produce them:

```python
def test_my_len():
    assert my_len([7, 8, 9]) == 1 + my_len([8, 9])
    assert my_len([   8, 9]) == 1 + my_len([   9])
    assert my_len([      9]) == 1 + my_len([    ])
    assert my_len([       ]) == 0
```

Maybe you can start to see a pattern. For an empty list, the length is `0`. For
a non-empty list, it's `1` (the first element's "contribution") plus the length
of the rest of the list: we can use the result of `my_len` on the rest of the
list to compute the answer for the whole list.

Try: we have now claimed that `my_len([7, 8, 9])` is `3`, `1 + 2`,
`1 + my_len([8, 9])`, and `1 + my_len([7, 8, 9][1:])`. Check that you agree
with each, and see how each comes from the one before it.

#### `my_sum`: Examples

Let's repeat this for a function that adds up a list of numbers. Setting aside
the empty list for a moment:

```python
def test_my_sum():
    assert my_sum([7, 8, 9]) == 7 + 8 + 9
    assert my_sum([   8, 9]) ==     8 + 9
    assert my_sum([      9]) ==         9
```

which (by substitution) is the same as

```python
def test_my_sum():
    assert my_sum([7, 8, 9]) == 7 + my_sum([8, 9])
    assert my_sum([   8, 9]) == 8 + my_sum([   9])
    assert my_sum([      9]) == 9 + my_sum([    ])
```

From this, we can see that `my_sum([])` must be `0` (zero is the _additive
identity_: adding it to any number gives you that number). Again, we can use
`my_sum` of the rest of the list to compute the result for the whole list.

#### From Examples to Code

To handle _any_ list, not just our examples, we look for patterns in them. Here
are the `my_len` examples with the rest written using `[1:]`, and the empty case
(which looks different) separated from the others:

```python
def test_my_len():
    assert my_len([7, 8, 9]) == 1 + my_len([7, 8, 9][1:])
    assert my_len([   8, 9]) == 1 + my_len([   8, 9][1:])
    assert my_len([      9]) == 1 + my_len([      9][1:])

    assert my_len([       ]) == 0
```

With this separation (which follows a structural feature of lists), a pattern
emerges: for a non-empty list `some_list`, the length is
`1 + my_len(some_list[1:])`. So `my_len` needs to run different code depending
on whether its input is empty. As with conditional data on
[Day 19](/days/19), we use `match`. For lists, it looks like:

```python
match e:
    case []:
        ...
    case [f, *r]:
        ...  # can use f and r here
```

where `e` is an expression whose value is a list (like a variable holding one),
and `f` and `r` are names for its first and rest. You can choose any names you
like (one that fits the problem, like `price` for a list of prices, can help).
The `*` means that `r` is the list of _all_ the remaining elements, rather than
a single one. Python evaluates `e`, then examines what _kind_ of list it is. If
it's empty, it runs the code under `case []:`. Otherwise, the list has a first
and rest: Python adds `f` and `r` to the program directory, holding those two
parts, and runs the code under `case [f, *r]:`.

Now let's use `match` to define `my_len`:

```python
def my_len(lst: list) -> int:
    """computes the number of elements in lst"""
    match lst:
        case []:
            return 0
        case [f, *r]:
            return 1 + my_len(r)
```

This follows from our examples: when the list is empty, `my_len` returns `0`;
otherwise, we add one to the length of the rest of the list. While our examples
said `[1:]`, here we just use `r`, which `match` has already defined to be the
rest of `lst`. Try calling `my_len(5)`, with a number instead of a list, and see
what happens!

Similarly, let's define `my_sum`:

```python
def my_sum(lst: list[float]) -> float:
    """adds up the numbers in lst"""
    match lst:
        case []:
            return 0
        case [f, *r]:
            return f + my_sum(r)
```

Notice how similar they are, and how readily the structure of the data suggests
a structure for the program. This is a pattern you will get very used to soon!

**Strategy: Developing Functions Over Lists.**

- Pick a concrete list with (at least) three elements. Write a sequence of
  examples for the entire list and each suffix of it (including the empty list).
- Rewrite each example to express its expected answer in terms of the first and
  rest of its input list (you don't have to write `[0]` and `[1:]`, but you
  should see the first and rest _values_ in the answer).
- Look for a pattern across the answers, and use it to write the code: a
  `match`, with the code under each `case` based on your examples.

This strategy applies to structured data in general, using the parts of each
piece of data rather than specifically a first and rest.

## Intro (20 mins)

- Lists, like `[1, 2, 3]`, can be thought of as made up of two parts: a first
  element `1` and a "rest of the list" `[2, 3]`.
- If we have:
  ```python
  lst = [1, 2, 3]
  ```
  Then `lst[0]` is `1` and `lst[1:]` (using slicing, as we did with strings on [Day 11](/days/11)) is `[2, 3]`
- `lst[1:][1:]` is `[3]`. What about `lst[1:][1:][1:]`? It is `[]`, the empty list.
- Going the other way, we can build the above list out of first elements and rests, as:
  `[1] + ([2] + ([3] + []))`
- This may be more verbose, but it shows the structure of the list.
- We can notice now, that lists are _conditional_ data -- which are either
  empty (`[]`), or have a first element and a rest, which is itself a list.
- This intuition ends up being very helpful for programming -- let's say we wanted to add
  up numbers in a list, until the first 0 (or all numbers if there were no zeros).
- We can write test cases for this, initially leaving the body with just the placeholder `0`.
  ```python
  def add_till_zero(lst: list[float]) -> float:
      return 0

  def test_add_till_zero():
      assert add_till_zero([7, 3, 0, 5]) == 10
      assert add_till_zero([   3, 0, 5]) == 3
      assert add_till_zero([      0, 5]) == 0
      assert add_till_zero([])           == 0
  ```
- We can rewrite these tests as:
  ```python
  def add_till_zero(lst: list[float]) -> float:
      return 0

  def test_add_till_zero():
      assert add_till_zero([7, 3, 0, 5]) == 7 + 3 + 0
      assert add_till_zero([   3, 0, 5]) ==     3 + 0
      assert add_till_zero([      0, 5]) ==         0
      assert add_till_zero([])           == 0
  ```
- And now, looking at the next row, we can see that we can rewrite this as:
  ```python
  def add_till_zero(lst: list[float]) -> float:
      return 0

  def test_add_till_zero():
      assert add_till_zero([7, 3, 0, 5]) == 7 + add_till_zero([3, 0, 5])
      assert add_till_zero([   3, 0, 5]) ==     3 + add_till_zero([0, 5])
      assert add_till_zero([      0, 5]) ==         0
      assert add_till_zero([])           == 0
  ```
- i.e., each test is the first plus the function called on the rest of
  the list, unless the first is zero in which case the result is zero.
- We can use this insight to make these tests even closer to code:
  ```python
  def add_till_zero(lst: list[float]) -> float:
      return 0

  def test_add_till_zero():
      assert add_till_zero([7, 3, 0, 5]) == [7, 3, 0, 5][0] + add_till_zero([7, 3, 0, 5][1:])
      assert add_till_zero([3, 0, 5]) == [3, 0, 5][0] + add_till_zero([3, 0, 5][1:])
      assert add_till_zero([0, 5]) == 0
      assert add_till_zero([]) == 0
  ```
- Now, since we know a list is conditional data, we can use `match` (as we did
  on [Day 19](/days/19)) to start writing the code. For lists, the two cases are
  written `case []:`, for the empty list, and `case [f, *r]:`, for a list with a first element,
  which here we name `f`, and a rest, which here we name `r` (the `*` means that `r` is
  the list of _all_ the remaining elements, rather than a single element):
  ```python
  def add_till_zero(lst: list[float]) -> float:
      match lst:
          case []:
              ...
          case [f, *r]:
              ...

  def test_add_till_zero():
      assert add_till_zero([7, 3, 0, 5]) == [7, 3, 0, 5][0] + add_till_zero([7, 3, 0, 5][1:])
      assert add_till_zero([3, 0, 5]) == [3, 0, 5][0] + add_till_zero([3, 0, 5][1:])
      assert add_till_zero([0, 5]) == 0
      assert add_till_zero([]) == 0
  ```
- We know that if we are given an empty list, we return 0 (this is our last test case). In the case with a first and a rest, we
  have to figure out if `f` is zero (this is our second to last test case, and also means we return 0), and otherwise we add the first to calling the
  function on the rest, just as our tests show us.
  ```python
  def add_till_zero(lst: list[float]) -> float:
      match lst:
          case []:
              return 0
          case [f, *r]:
              if f == 0:
                  return 0
              else:
                  return f + add_till_zero(r)

  def test_add_till_zero():
      assert add_till_zero([7, 3, 0, 5]) == [7, 3, 0, 5][0] + add_till_zero([7, 3, 0, 5][1:])
      assert add_till_zero([3, 0, 5]) == [3, 0, 5][0] + add_till_zero([3, 0, 5][1:])
      assert add_till_zero([0, 5]) == 0
      assert add_till_zero([]) == 0
  ```

## Wrap-up (5 mins)

- Lists are structured / conditional data.
- By examining concrete examples we can figure out a recursive definition.
- Certain patterns of code are easier to express recursively, but others are not.
