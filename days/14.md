### Operating on Lists

#### Built-In Operations on Lists in General

Some of our questions involve the `Discount Code` column, which contains strings
rather than numbers. Here are the discount codes that were used:

```python
codes = cleaned_data.column("Discount Code")
# -> ['BIRTHDAY', 'none', 'STUDENT', 'none', 'STUDENT', 'none', 'STUDENT']
```

But `"none"` isn't an actual discount code: we introduced it while cleaning the
table. To remove it, recall that with tables, we used `filter` to keep only the
rows that meet some criterion; Python (like most languages) provides filtering
on lists, too:

```python
def real_code(c: str) -> bool:
    """determines whether c is an actual discount code (not none)"""
    return not (c == "none")

def test_real_code():
    assert real_code("STUDENT")
    assert not real_code("none")

list(filter(real_code, codes))  # -> ['BIRTHDAY', 'STUDENT', 'STUDENT', 'STUDENT']
```

For lists, `filter` takes the function first and the list second, and we wrap
its result in `list(...)` to get an ordinary list. `filter` can check any
characteristic of an element, not just whether it equals a particular value: we
could as easily have removed all the strings that were entirely lowercase.

Try: write a function that takes a list of words and removes those in which all
letters are lowercase. (Hint: combine `lower` and `==`.)

#### An Aside on Naming Conventions

Our plural name `codes`, for the values in the `Discount Code` column
(singular), is deliberate: a list contains multiple values, while a column name
names the single value in a particular row, which supports thinking about
looking up a value in one row.

#### Getting Elements By Position

A new question: to see whether an advertising campaign on `web.com` paid off,
the events company wants to know how many sales were made to people with
`web.com` email addresses. Propose a task plan ([Day 12](/days/12)) before
reading on. Here's one, annotated with how we might implement each part:

1. Get the list of email addresses (with `column`).
2. Keep those that came from `web.com` (with `filter`).
3. Count how many remain (with `len`, which works on lists as well as strings).

For the second task, we need to determine whether an email address ends in
`@web.com`. We could look at its last 8 characters, or use `split`
([Day 12](/days/12)), which splits a string into a list of pieces around a
separator:

```python
"this-has-hyphens".split("-")  # -> ['this', 'has', 'hyphens']
"bonnie@pyret.org".split("@")  # -> ['bonnie', 'pyret.org']
```

Splitting an email address around the `@` sign, we can check whether the
second piece is `"web.com"`. To get an element out of a list, we write its
position in square brackets: `"bonnie@pyret.org".split("@")[1]` is
`"pyret.org"`. Why `1`, for the second item? Here's the complete program:

```python
def web_com_address(email: str) -> bool:
    """determines whether email is from web.com"""
    return email.split("@")[1] == "web.com"

def test_web_com_address():
    assert not web_com_address("bonnie@pyret.org")
    assert web_com_address("parrot@web.com")

emails = ["parrot@web.com", "bonnie@pyret.org", "polly@web.com"]
len(list(filter(web_com_address, emails)))  # -> 2
```

Try it on the events data, with `emails = cleaned_data.column("Email")`. What
happens with an email address that doesn't contain an `@` (like Ernie's,
`"ernie.mail.com"`), and why? What could you do about that?

#### Transforming Lists

Now say we had a list of email addresses, but wanted just the usernames (useful
in other contexts, like sorting messages into folders named by username): from
`["parrot@web.com", "bonnie@pyret.org"]`, we want `["parrot", "bonnie"]`. Are
`filter` or `len` useful for this? Think about their outputs: `filter` produces
elements _from_ the input list, not transformed ones, and `len` produces a
number. Transforming elements is like `transform_column` on tables; the
corresponding operation on lists is `map` (which, like `filter`, is wrapped in
`list(...)`):

```python
def extract_username(email: str) -> str:
    """extracts the portion of an email address before the @ sign"""
    return email.split("@")[0]

def test_extract_username():
    assert extract_username("bonnie@pyret.org") == "bonnie"
    assert extract_username("parrot@web.com") == "parrot"

list(map(extract_username, ["parrot@web.com", "bonnie@pyret.org"]))  # -> ['parrot', 'bonnie']
```

#### Recap: Summary of List Operations

If `lst` is a `list[T]` (a list whose elements all have some type `T`):

- `list(filter(keep, lst))`, where `keep` is a function from `T` to `bool`,
  produces a `list[T]` of the elements on which `keep` returns `True`.
- `list(map(f, lst))`, where `f` is a function from `T` to some type `R`,
  produces a `list[R]` of the results of calling `f` on each element.
- `len(lst)` produces the number of elements, an `int`.
- `x in lst` determines whether `x` is an element of `lst` (as `in` checks
  whether one string contains another): `"rice" in ["rice", "lentils"]` is
  `True`.

A _type variable_ like `T` stands for some unspecified type, and shows
_relationships_ between types: the output of `filter` has elements of the same
type as its input, while the output of `map` could have a different type. Many
useful computations combine these operations.

### Combining Lists and Tables

The table methods we've studied mostly process rows, while these list functions
mostly process columns. If an analysis involves only some rows and some columns,
we'll combine both. Try: given the events table, produce a list of the names of
all the people who will pick up their tickets, and the average number of tickets
ordered by people with email addresses ending in `".org"`.

Sometimes there is more than one way to do a computation. Propose several task
plans for "how many people with `.org` email addresses bought more than 8
tickets?", before reading on. Here are some options:

1. Keep the rows with more than 8 tickets (with `filter`), then those with
   `.org` addresses (another `filter`), then count the rows (with `length`).
2. Keep the rows with more than 8 tickets _and_ an `.org` address (with one
   `filter`, checking both conditions), then count the rows (with `length`).
3. Keep the rows with more than 8 tickets (with `filter`), extract their email
   addresses (with `column`), keep those ending in `.org` (with the list
   `filter`), then count them (with `len`).

Which do you like best, and why? There's no single correct answer, but
consider: are any intermediate results useful for other computations? (The
second option filters only once, but the company may have other uses for the
large orders, or their email addresses.) Do you want a discipline of working on
table rows, extracting lists only for computations that tables don't provide?
Does one approach use fewer resources? (Filtering a table doesn't actually use
more than filtering one column's list; we'll return to this later.) Teams
sometimes set design standards for such decisions; otherwise, consider multiple
approaches, then pick one: thinking flexibly about approaches is a useful skill
in any form of design.

So far, we've only used built-in functions on lists; soon, we'll write our own,
and these functions will no longer seem quite so magical.

## Intro (20 mins)

- Last time we saw built-in operations on lists of numbers, and ones from [statistics](https://docs.python.org/3/library/statistics.html). Today we are going to dive into many more [built-in operations](https://docs.python.org/3/library/functions.html) on lists.
- Imagine a list of discount codes used by a magazine:
  ```python
  discount_codes = ["NEWYEAR", "student", "NONE", "student", "VIP", "none"]
  ```
- Which may have come from a column of a table. We have operations on lists that are similar to operations you saw
  previously on tables. For example, as part of data cleaning, we can `filter` to remove codes that
  represent no discount (in this case, "none", written in upper or lower case).
  ```python
  def is_real_code(code: str) -> bool:
      return not (code.lower() == "none")

  real_codes = list(filter(is_real_code, discount_codes))
  ```
  Note that `filter` takes the function first, and the list second, and that we have to wrap the result of `filter` with `list(...)`: `filter` produces a special value that computes its elements only as they are needed, and `list` turns that into an ordinary list.
- Like how tables have `.row`, lists have a way of getting an element by position, by writing the position in square brackets after the list:
  ```python
  first_code = real_codes[0]
  ```
- For tables, we had a few ways of transforming the existing data -- adding a
  new column with `add_column`, or transforming a single column with
  `transform_column`. Since lists have only a single value, there is only one
  version, called `map`, which, like `filter`, needs to be wrapped with `list(...)`.
- We can use this to, e.g., get lowercase versions of each discount code:
  ```python
  lower_codes = list(map(lambda code: code.lower(), real_codes))
  ```
