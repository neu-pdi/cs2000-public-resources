## Reading

### Strings

What if we wanted to write a program that used information other than numbers,
such as someone's name? For names and other text-like data, we use what are
called _strings_: characters written between double quotes. Here are some examples:

```python
"Paws"
"Go Huskies!"
"CS2000"
"Ell, Carl S."
```

Strings can contain spaces, punctuation, and numbers: we use them to capture
textual data. For flags, we'll use strings to name colors: `"red"`, `"blue"`,
etc. Note that strings are _case-sensitive_, meaning that capitalization
matters: `"Red"` and `"red"` are different strings.

### Images

We have seen two kinds of data: numbers and strings. For flags, we'll also need
images, which are different from both (you can't describe an entire image with a
single number!). Python doesn't have images built in, but PLL adds them. Try each
of these at the interactions prompt, to see what they produce:

```python
circle(30, "solid", "red")
circle(30, "outline", "blue")
rectangle(20, 10, "solid", "purple")
```

Each of these names the shape to draw, then configures the shape in the
parentheses that follow: first the shape's dimensions (the radius for circles,
the width and height for rectangles, both measured in screen pixels), then a
string saying whether to make a solid shape or just an outline, then a string
with the color to draw it in.

#### Combining Images

Any time you get a new kind of data in programming, you should ask what
operations you have for working with it. For images, these include the ability
to rotate them, scale them, flip them, put two of them side by side, place one
on top of the other, and more. Try these:

```python
rotate(45, rectangle(20, 30, "solid", "red"))

overlay(circle(25, "solid", "yellow"),
        rectangle(50, 50, "solid", "blue"))

above(circle(25, "solid", "red"),
      rectangle(30, 50, "solid", "blue"))
```

What does the `45` represent? (Try some different numbers to confirm your
guess.) Can you describe what `overlay` does? And what kind of value -- a number,
a string, or an image -- do you get from `rotate` or `above`?

We have simple values, like numbers and strings, and _operations_ or
_functions_ that combine values, like `+` or `rotate` ("functions" is the term
more commonly used in computing). Every function produces a value, which can be
used as input to another function. For example, we can take the image that
`above` produces, and rotate it:

```python
rotate(45,
       above(circle(25, "solid", "red"),
             rectangle(30, 50, "solid", "blue")))
```

Using the output of one function as input to another is known as
_composition_. Most interesting programs arise from composing the results of one
computation with another, so getting comfortable with composing expressions is
an essential first step in learning to program. Try to create: a blue triangle
(`triangle` takes a side length, fill style, and color) inside a yellow
rectangle; a triangle at an angle; and a bullseye with 3 circles, one inside the
other. Then, try making the flag of Armenia, which has three horizontal stripes:
red on top, blue in the middle, and orange on the bottom.

### Types, Errors, and Documentation

#### Types and Contracts

As we compose functions to build more complicated expressions, we have to keep
track of which combinations make sense. What would you expect this to produce?

```python
8 * circle(25, "solid", "red")
```

Multiplication is meant to work on numbers, but this asks Python to multiply a
number and an image, which doesn't make sense, so Python reports an error (a
`TypeError`). In programming, values are organized into _types_ -- so far we've
seen `int` and `float` (numbers), `str` (strings), and `Image`. Types describe
what kind of inputs a function works with, and what kind of result (or output) it
produces: for example, `*` expects two numbers, and returns a number. The
required types of a function's inputs, and the promised type of its output, are
called its _contract_. In Python, they are written with _type annotations_, like
this:

```
circle(radius: float, mode: str, color: str) -> Image
rotate(angle: float, image: Image) -> Image
```

Look at the contract for `rotate`. It tells us that there is a function called
`rotate`, that it takes two inputs (the parts within the parentheses): the angle,
which is a number, and the image to rotate, which has type `Image`, and that its
output (which follows the `->`) is an `Image`. In general, we read the colon
(`:`) as "has the type", and the arrow (`->`) as "returns".

Whenever you compose smaller expressions into bigger ones, the types produced
by the smaller expressions have to match the types required by the function you
are using to compose them. A contract also says _how many_ inputs a function
expects: `circle` expects three, so if we forgot the style, as in
`circle(100, "purple")`, that is an error too -- not because of the types of the
inputs, but because of how many there are. Try some expressions that give a
function the wrong type of input, and some that give it the wrong number of
inputs, and notice what their error messages have in common, so you can
recognize them if they come up while you are programming.

#### Format and Notation Errors

A third kind of mistake is with the punctuation of programming. Can you spot the
error in each of these?

```python
circle(50 "solid" "red")
circle(50, "solid,  "red")
circle(50, "solid," "red")
circle 50, "solid," "red")
```

While you can leave out a comma and still turn in an essay, Python can't run an
expression that has a punctuation error. Some of the rules we've seen so far:
when we use a function, we put a pair of parentheses around the inputs, and
separate the inputs with commas; and if we start a string with a double
quotation mark, we need another one to end it. The rules for writing proper
expressions are called _syntax_. Making syntax mistakes is common at first; in
time, you'll internalize the rules, so don't get discouraged!

#### Finding Other Functions: Documentation

Every programming language comes with _documentation_, where you find out what
operations and functions are available, and your options for configuring them.
Documentation can be overwhelming at first, because it contains a lot of detail
that you don't need yet. For images, look at the [PLL Images reference](/pll/images):
it lists the functions for making shapes, and then the ones for combining and
changing images, each with its contract and a description of what it does. For
strings, and the rest of Python, see the [Python documentation](https://docs.python.org/3/).

### Data for text

- Last time we showed how to use numbers in Python -- today we are going to introduce two new types of data, and operations on them.
- The first is text -- i.e., words, sentences, paragraphs, etc. These are called "strings", and are written as either `"hello cs2000!"` (i.e., double quotes around characters; single quotes, as in `'hello cs2000!'`, work too), or if you want the string to be able to cross multiple lines, you can write it with three double quotes on each side:

```python
"""
Hello
There!
"""
```

- Like numbers, there are operators on strings. `+` takes two strings and creates a new string with the second one put after the first, which is sort of a string version of "adding", but there are also operations that don't have analogs to numbers, e.g., `len(s)` returns the number of characters in the string `s`, and `s * n`, assuming `s` is a string and `n` is a non-negative integer, returns a new string that contains the string `s` repeated `n` times.

### Data for Images

- Just like numbers and strings, we also have images. They aren't built into Python, but PLL adds them, so you don't have to do anything to use them.
- We can create basic shapes with functions like `circle`, `rectangle`, `triangle`, e.g.,
  ```python
  circle(30, "solid", "blue")
  rectangle(40, 20, "solid", "green")
  triangle(50, "outline", "black")
  ```
- Like with numbers and strings, there are operations on images -- e.g., `overlay(i1, i2)` creates a new image that has the first image on top of the second (so if the first image is larger, you will not see the second image at all), vs. `above(i1, i2)` composes the images by creating a new image that includes the two inputs adjacent, one above the other, and `beside(i1, i2)` creates a new image that has the two images provided side by side.
