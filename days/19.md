### A First Peek at Conditional Data

There are also times when we want to represent different _kinds_ of data under
a single, collective umbrella. A traffic light can be red, yellow, or green:
collectively, a new type called a traffic light state. A zoo has many kinds of
animals: collectively, a new type called an animal. A social network has pages
for people, places, and organizations; a notification app reports emails,
reminders, instant messages, and package deliveries, each with its own details.

We call these "conditional" data because they represent an "or": a traffic
light is red _or_ yellow _or_ green. Sometimes we care exactly which kind of
thing we're looking at: a driver behaves differently on different colors, and a
zookeeper feeds each animal differently. At other times we don't: to count the
animals in the zoo, or the unread notifications, their details don't matter.

### Defining and Creating Conditional Data

We define conditional data with one dataclass for each option, and a name for
the type that is any one of them. A traffic light's colors have no further
information, so each class's body is just `pass`:

```python
from dataclasses import dataclass

@dataclass
class Red:
    pass

@dataclass
class Yellow:
    pass

@dataclass
class Green:
    pass

TLColor = Red | Yellow | Green
```

Each `|` (read "or") introduces another option. You make traffic light colors by
calling the classes with no arguments: `Red()`, `Yellow()`, `Green()`. A more
interesting and common example is when each option has some structure:

```python
@dataclass
class Boa:
    name: str
    length: float

@dataclass
class Armadillo:
    name: str
    liveness: bool

Animal = Boa | Armadillo

b1 = Boa("Ayisha", 10)
b2 = Boa("Bonito", 8)
a1 = Armadillo("Glypto", True)
```

We call the different options _variants_. Try: how would you annotate `b1`,
`b2`, and `a1`? (`b1: Boa` works, but to say it is an animal, write
`b1: Animal = Boa("Ayisha", 10)`: then the distinction between boas and
armadillos is lost in the annotation.) Structured data like `ITunesSong` (from
[Day 18](/days/18)) is really just the special case with only one variant.

### Telling Apart Variants of Conditional Data

To tell apart variants, we use `match`, with one `case` for each variant. To
compute advice for a driver based on a traffic light's color, we might write:

```python
def advice(c: TLColor) -> str:
    """returns advice for a driver at a light of color c"""
    match c:
        case Red():
            return "wait!"
        case Yellow():
            return "get ready..."
        case Green():
            return "go!"
```

Try leaving out the `()` in `case Red():`. What happens? What if you leave out
the `Red` case, then try both `advice(Yellow())` and `advice(Red())`?

### Processing Fields of Variants

If a variant has fields, its `case` lists names for them, in order, and Python
adds those names to the program directory while running that case, so you don't
need the `.` notation to get the field values. (The names don't have to match
the fields': conventionally, the fields get longer, descriptive names, and the
case gets short ones.) To get the name of any animal:

```python
def animal_name(a: Animal) -> str:
    """returns the name of any animal"""
    match a:
        case Boa(n, l):
            return n
        case Armadillo(n, l):
            return n

def test_animal_name():
    assert animal_name(b1) == "Ayisha"
    assert animal_name(b2) == "Bonito"
    assert animal_name(a1) == "Glypto"
```

To evaluate `animal_name(Boa("Bonito", 8))`, Python adds `a` to the program
directory, as the value `Boa("Bonito", 8)`. Next, it determines which case
matches the data (the first one), and adds `n` (as `"Bonito"`) and `l` (as `8`)
while running that case, which returns `n`: the result is `"Bonito"`.

## Intro (15 mins)

- Sometimes, rather than data being composed of different parts, as we saw [last
  time](/days/18), data comes in multiple, incompatible, forms.
- For example, a payment system might need to track the source of payment, which
  could be:
  - Cash, with no further information
  - Check, with the bank account number and routing number (and possibly more information -- account number, check number, etc)
  - Credit Card, with the credit card number (and possibly more information -- expiration date, security code, etc)
- This doesn't fit into the pattern of structured data, since different
  alternatives have different, incompatible, components. A security code makes
  no sense for a check, and a check number has no bearing on a credit card, and
  all of the extra fields make no sense for cash.
- Instead, **this type of data is conditional -- data that takes the shape of
  exactly one of several variants.**
- We can define the above using the same `@dataclass` mechanism, with one class for each variant (a
  class with no fields has `pass` as its body, which means "nothing here"), and
  then a name for the type that is any one of them (the `|` means "or", as we saw on [Day 12](/days/12)):
  ```python
  from dataclasses import dataclass

  @dataclass
  class Cash:
      pass

  @dataclass
  class Credit:
      card_number: str
      expiry: str

  @dataclass
  class Checking:
      bank_account: str
      routing: str
      check_number: int

  PaymentMethod = Cash | Credit | Checking
  ```
- Note that there is _one_ data type `PaymentMethod`, but _three_ ways of
  constructing it -- `Cash`, `Credit`, and `Checking`.
- We create examples of this data similarly to how we did with structured data (note that
  even though `Cash` has no fields, we still have to call it, with `()`, to construct it):
  ```python
  payment_1 = Cash()
  payment_2 = Credit("1111-2222-3333-4444", "09/26")
  payment_3 = Checking("987654321", "111", 55)
  ```
- As long as we know exactly which variant of the data type we have, we can use the dot notation, like with structured data, to access one of the variant-specific fields. For example: `payment_2.expiry` or `payment_3.check_number`
- However, given a `PaymentMethod` for which we don't know the variant we have,  **we can't use the dot notation for field lookup**, since
  the field might not exist (a `Cash` has no `expiry`!). Instead, we use a
  new language feature called `match`, which allows you to write down what to do in each possible case
  of the data. Each `case` names a variant, and then gives names for the fields of
  that variant, in order (these can be any names you choose), which are added to the program directory while running that case:
  ```python
  def display_payment(p: PaymentMethod) -> str:
      match p:
          case Cash():
              return "Paid in cash"
          case Credit(cn, exp):
              return "Paid by credit card expiring on " + exp
          case Checking(acc, rout, num):
              return "Paid by check from account " + acc
  ```
- Python has a simple form of this kind of data built in: the special value `None`, which means "no value". A
  type like `str | None` means "either a string, or `None`" -- we'll use this on [Day 23](/days/23).

## Class Exercises (40 mins)

1. Define a `Vehicle` data type with three variants: `Bike` (no fields), `Car`
  (with `make` and `year` fields), and `Truck` (with `make`, `year`, and
  `capacity` fields). Create one example of each variant.
1. Write a function `vehicle_age` that takes a `Vehicle` and the current year,
  and returns the age in years. For bikes, return 0.
1. Define a `Grade` data type with variants: `Letter` (with a string field for
  A/B/C/D/F), `Percent` (with a number field), and `PassFail` (with a boolean
  field). Create examples of each.
1. Write a function `grade_to_gpa` that converts any `Grade` to a 4.0 scale
  number. Use: `A=4.0, B=3.0, C=2.0, D=1.0, F=0.0`; percentages: `90+=4.0, 80-89=3.0, 70-79=2.0, 60-69=1.0, <60=0.0`; pass-fail: `pass=4.0, fail=0.0`.
1. Write a function `payment_summary` that takes a `PaymentMethod` and returns a
  string: "Cash payment", "Card ending in XXXX" (last 4 digits), or "Check
  #NNNN" (check number).
1. Define a `WeatherReport` with variants: `Sunny` (temperature only), `Rainy`
  (temperature and precipitation amount), and `Snowy` (temperature,
  precipitation, and wind speed). Write a function `is_severe` that returns
  `True` if: rainy with >2 inches, snowy with >30 mph wind, or sunny above 95°F.

## Wrap-up (5 mins)

- Conditional data represents information that can take one of several different forms.
- Use `match` to process conditional data, handling each possible variant.
- Different variants can have different numbers and types of fields.
