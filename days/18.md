### A First Peek at Structured Data

There are times when a datum has many _attributes_, or parts, that we need to
keep together, and sometimes take apart. For instance, an iTunes entry has a
song's name, singer, length, genre, and so on; and Gmail has, for each message,
its sender, subject line, conversation, body, and more.

In examples like these, we need _structured_ data: a single datum made of a
_fixed_ number of pieces, possibly of different kinds, some of which might even
be other structured data (a date has at least a day, month, and year). The parts
of a structured datum are called its _fields_.

### Defining and Creating Structured Data

Here's a simplified version of what iTunes might store about a song, written
as a dataclass:

```python
from dataclasses import dataclass

@dataclass
class ITunesSong:
    name: str
    singer: str
    year: int
```

This introduces a _new type of data_, called `ITunesSong` (the names of types we
define begin with a capital letter), and we make one by calling `ITunesSong`
with a value for each field, in order. Always follow a data definition with a
few concrete examples, to make sure you know how to make data of that form, and
name them, so you can use them later:

```python
lver = ITunesSong("La Vie en Rose", "Édith Piaf", 1945)
so = ITunesSong("Stressed Out", "twenty one pilots", 2015)
wnkkhs = ITunesSong("Waqt Ne Kiya Kya Haseen Sitam", "Geeta Dutt", 1959)
```

In the program directory, structured data are no different from simple data:
each of these definitions adds an entry, for a name and its `ITunesSong` value.

### Annotations for Structured Data

The data definition annotates each field with its type, making information
we'd otherwise record informally a formal part of the program. We can also
annotate the names of examples. What type goes in the blank in
`lver: ___ = ITunesSong(...)`? Annotations take names of types, and our new type
is called `ITunesSong`, so we could define `lver` as:

```python
lver: ITunesSong = ITunesSong("La Vie en Rose", "Édith Piaf", 1945)
```

Try annotating it as a `str` instead, and familiarize yourself with the error.

### Extracting Fields from Structured Data

Let's write a function that tells us how old a song is. It consumes an
`ITunesSong` and produces an `int`, and its body must be roughly
`2026 - <get the song year>`. We get the year with _field access_: a `.` and a
field's name, after the name holding the structured datum. So `s.year` is the
`year` field of `s`, and, with some examples, the whole function is:

```python
def song_age(s: ITunesSong) -> int:
    """returns how many years old the song is"""
    return 2026 - s.year

def test_song_age():
    assert song_age(lver) == 81
    assert song_age(so) == 11
    assert song_age(wnkkhs) == 67
```

## Intro (10 mins)

- Many pieces of information consist of multiple parts that should be kept together.

- e.g., in tables, the row consists of several values. But, this same idea is useful outside of tables.

- Consider, for example, a record of a book used by a library program -- which has a title, author, and number of pages.

- We can define a new type of data for a `BookRecord` using two language features, `@dataclass` and `class`
  (to use `@dataclass`, your file needs the line `from dataclasses import dataclass`, near the top):
  ```python
  from dataclasses import dataclass

  @dataclass
  class BookRecord:
      title: str
      author: str
      pages: int
  ```

- This defines both the type of data (`BookRecord`), for use in type
  annotations, and a way of constructing it -- `BookRecord` is also a function of
  three arguments (`title`, `author`, and `pages`, in that order) that returns a new piece of
  data of type `BookRecord`. Functions like this are known as constructors.

- For example, we can create three `BookRecord`s as:
  ```python
  the_dispossessed = BookRecord("The Dispossessed", "Ursula K. Le Guin", 387)
  to_the_lighthouse = BookRecord("To the Lighthouse", "Virginia Woolf", 209)
  brave_new_world = BookRecord("Brave New World", "Aldous Huxley", 268)
  ```

- The field names are used to access the parts of the `BookRecord`, using the
  dotted "field access" notation:
  ```python
  the_dispossessed.pages  # evaluates to 387
  ```

## Wrap-up (5 mins)

- Structured data groups multiple fields together.
- We define structured types using `@dataclass` and `class`, and create instances by calling the constructor.
- Fields are accessed with the dot notation.
