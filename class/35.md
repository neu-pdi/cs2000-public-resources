### Pictures Made of Smaller Copies

A **fractal** is a picture made of smaller copies of itself. The Sierpinski
triangle is three copies of itself, each half as big, one above the other two:

![A Sierpinski triangle: a purple triangle made of three smaller triangles, each made of three smaller ones, and so on, five times over](/img/class35-sierpinski.svg)

The four questions, for a picture:

1. **What's trivial?** A picture so small that its copies wouldn't show: here,
   under 10 pixels across, where it's drawn as a plain triangle.
2. **How do you make smaller problems?** The same picture, smaller: half the
   size.
3. **How do you combine their answers?** The image functions: one copy
   `above` the other two, `beside` each other.
4. **Why does it end?** The size is half as big at each call, so it gets below
   10.

```python
def sierpinski(side: float) -> Image:
    """a Sierpinski triangle with sides side pixels long: three copies of it,
    each half as big, one above the other two. It ends because side is half as
    big in each recursive call, so it gets below 10."""
    if side < 10:
        return triangle(side, "solid", "purple")
    else:
        half = sierpinski(side / 2)
        return above(half, beside(half, half))

sierpinski(200)
```

- `half` is made once, and used three times: the three copies are the same
  picture.
- The size doesn't need to be a whole number: halving 200 gives 100, 50, 25,
  12.5, and then 6.25, which is under 10. So `sierpinski(200)` is five levels of
  copies, and 3 × 3 × 3 × 3 × 3 = 243 triangles.
- Each level triples the number of triangles. `sierpinski(800)` has 7 levels,
  and 2,187 triangles: the trivial size decides how much work there is.

### Why It Ends, for Pictures

The termination statement depends on two things, and each can go wrong:

- **The copies must be smaller.** With `sierpinski(side)` as the copy, each call
  asks for the same picture again, forever.
- **The trivial case must be reachable.** With `side < 0` as the question,
  halving never makes a size below 0, so no call is ever trivial.

Either way, PLL stops it, with a RecursionError: `sierpinski` kept calling
itself and never stopped.

### Copies and Gaps

The Sierpinski carpet is eight copies of itself, each a third as big, around a
gap of the same size:

![A Sierpinski carpet: a teal square with a square hole in the middle, surrounded by eight smaller copies of itself, each with its own hole, three times over](/img/class35-carpet.svg)

```python
def carpet(side: float) -> Image:
    """a Sierpinski carpet, side pixels across: eight copies of it, each a
    third as big, around a gap of the same size. It ends because side is a
    third as big in each recursive call, so it gets below 10."""
    if side < 10:
        return square(side, "solid", "teal")
    else:
        third = carpet(side / 3)
        gap = square(side / 3, "solid", "white")
        return above(beside(third, third, third),
                     beside(third, gap, third),
                     beside(third, third, third))

carpet(243)
```

- The gap is a white square, the same size as a copy. A smaller one would leave
  the middle row shorter than the others, and `above` would center it.
- `beside` and `above` take any number of images, so a row of three is one call.
