## Reading (Done Before Class)
To do a computation for each element of a list, we will use the following
pattern, which has two new language features:

```python skip
def func(lst: list) -> ...:
    result = ...  # what to return if the input list is empty
    for item in lst:
        # combine item with the result so far
        result = ... item ... result
    return result
```

### Variables that can change

First, note that `result` is given a value, and then given new ones inside the
`for`: it can _vary_.

So far, a variable in the program directory could never change: once we define
`x`, we can't define it again:

```python error
x = 10
# ...
x = 20  # PLL reports a reassignment, and doesn't run the file
```

Python allows this, but PLL's `beginner` level doesn't, since it is a common
cause of bugs. At `#level intermediate`, we can change (or _mutate_) a
variable, as long as it is defined _inside a function_, by using `=` again:

```python
def my_function() -> int:
    x = 10
    # ... x points to 10 in the directory
    x = 20
    # ... x now points to 20 in the directory
    return x
```

Changing a variable defined at the top level of the file is still reported
(we'll see why on [Class 17](/class/17)).

### How `for` works

A `for` loop runs its body (the lines indented under it) once for each element
of the list, in order, adding an entry to the program directory for the element
each time (above, `item`). The loop doesn't produce a value itself, so it relies
on changing variables to compute something. Consider summing a list of numbers
(whose type is written `list[float]`), following our pattern:

```python
def sum_list(lst: list[float]) -> float:
    """adds up the numbers in lst"""
    run_total = 0
    for item in lst:
        run_total = item + run_total
    return run_total

def test_sum_list():
    assert sum_list([5, 1, 7, 3]) == 16
```

On the test input `[5, 1, 7, 3]`, the loop runs four times: with `item` set to
`5`, then `1`, then `7`, and finally `3`. The `for` saves us from writing the
common code several times, and handles lists of any length (so we couldn't
know how many times to write it). It is as if the body of `sum_list` were:

```python skip
    run_total = 0
    run_total = 5 + run_total
    run_total = 1 + run_total
    run_total = 7 + run_total
    run_total = 3 + run_total
    return run_total
```

Try adding a test for the empty list: what should `sum_list([])` be, and which
line of `sum_list` decides it?

<Aside title="When Indentation Changes the Answer">

[Class 5](/class/5) warned that indentation mistakes would not always announce
themselves. This is where that begins, and it arrives together with the extra
room `#level intermediate` gives us: now that a variable can change inside a
function, a line's indentation decides _how many times_ it runs, not merely
which body it belongs to.

Indent `return` one level further and it moves inside the loop:

```python
def sum_list(lst: list[float]) -> float:
    """adds up the numbers in lst"""
    run_total = 0
    for item in lst:
        run_total = item + run_total
        return run_total
```

This is not a syntax error, and on any non-empty list it does not fail: the
`return` simply runs on the _first_ trip through the loop, so
`sum_list([5, 1, 7, 3])` is `5` rather than `16`. The function quietly answers
the wrong question, and only the test tells you. (On the empty list you _do_
get an error, for the reason you just worked out above: the body never runs, so
the function ends without returning the `float` it promised.)

So read the left edge of a loop body as carefully as the code in it -- and note
how much work the test did here.

</Aside>

## Recap (15 mins)

- To design our own list processing functions, we need a way to do computations
  for each element in the list. There are multiple ways to do that, today we will show
  iteration with `for` loops.
- This requires being able to change the value of a variable, which, as we saw on
  [Class 3](/class/3), PLL's `beginner` level does not allow. From today on, the
  first line of our files will be:
  ```python
  #level intermediate
  ```
  The `intermediate` level allows changing the value of a variable _inside a function_ (but still not
  at the top level of the file -- we'll see why on [Class 17](/class/17)).
- The pattern is:
  ```python skip
  def my_function(my_list: list) -> ...:
      my_var = initial_value
      for my_elt in my_list:
          # code
          # to
          # handle
          # my_elt
          # and update
          # my_var
      return my_var  # final result
  ```
  The body of the loop (the part indented under the `for`) runs once for each
  element of the list, in order, with `my_elt` being that element.
- Example: while `sum` is built in, we could have designed it ourselves as
  follows (note that the type of a list of numbers is written `list[float]`, and the type of a list of strings `list[str]`):
  ```python
  def my_sum(num_list: list[float]) -> float:
      total = 0
      for n in num_list:
          total = total + n
      return total

  def test_my_sum():
      assert my_sum([0, 1, 2, 3]) == 6
  ```

## Class Exercises (40 mins)

1. Design your own `product` function that takes a list of numbers and returns
  their product (multiply all of them together).
1. Design a function `sum_even_numbers` that takes a list of integers and adds up only
  the even numbers -- the rest should be ignored (`%`, which computes the remainder after dividing, may be helpful)!
1. Design a function `my_length` that takes a list of any value and returns the number
  of elements in the list.
1. Design a function `any_negative` that takes a list of numbers and returns `True`
  if there is at least one negative number in the list, `False` otherwise.
1. Design a function `all_short_words` that takes a list of strings and returns
  `True` if every word has 4 or fewer characters, `False` otherwise.
1. Design a function `reverse_list` that takes a list and returns a new list with
  all the elements in reverse order. You'll need to build up the result by adding
  each element to the front of your accumulator list.
1. Design a function `concat_all` that takes a list of strings and concatenates them
  all together into one string (with no separator between them).

## Wrap-up (5 mins)

- At `#level intermediate`, variables inside functions can be updated with `=`.
- `for` loops can run code for each element of a list; combined with variables that
  change, this allows writing custom list operations.
