## Notes (review before class)
### Strings

A **string** is text: characters between double quotes (single quotes, as in
`'CS2000'`, work too). Three double quotes on each side make a string that can
cross lines:

```python
"Go Huskies!"
"Ell, Carl S."
"""Hello
There!"""
```

- Strings can contain spaces, punctuation, and digits. For flags, strings name
  colors: `"red"`, `"blue"`.
- Strings are **case-sensitive**: `"Red"` and `"red"` are different strings.

Strings have operations too:

```python
"Go" + " Huskies!"
len("Go Huskies!")
"ha" * 3
```

- `+` puts the second string after the first: `"Go Huskies!"`.
- `len(s)` is the number of characters in `s`: `11`.
- `s * n` (`n` a non-negative `int`) is `s` repeated `n` times: `"hahaha"`.

### Images

Python doesn't have images built in, but PLL adds them:

```python
circle(30, "solid", "red")
circle(30, "outline", "blue")
rectangle(20, 10, "solid", "purple")
```

- Each names a shape, then gives its size in screen pixels (a circle's radius; a
  rectangle's width, then height; a `triangle`'s side length), then `"solid"` or
  `"outline"`, then a color.

### Combining Images

For any new kind of data, ask what operations work on it. Images can be rotated,
scaled, flipped, and combined:

```python
rotate(45, rectangle(20, 30, "solid", "red"))

overlay(circle(25, "solid", "yellow"),
        rectangle(50, 50, "solid", "blue"))

above(circle(25, "solid", "red"),
      rectangle(30, 50, "solid", "blue"))
```

- `rotate(45, i)` is the image `i` turned 45 degrees (counter-clockwise).
- `overlay(i1, i2)` puts `i1` on top of `i2`, centered: if `i1` is bigger, `i2`
  can't be seen.
- `above(i1, i2)` puts `i1` above `i2`; `beside(i1, i2)` puts them side by side.

### Functions and Composition

Operations like `+` and `rotate` are **functions**. Every function produces a
value, which can be the input to another function:

```python
rotate(45,
       above(circle(25, "solid", "red"),
             rectangle(30, 50, "solid", "blue")))
```

- Using one function's output as another's input is **composition**. Most
  programs are built by composing, so it is an essential first skill.
- Try: make a bullseye of 3 circles, one inside the other; then the flag of
  Armenia: horizontal stripes of red (top), blue, and orange (bottom).

### Types and Contracts

```python error
8 * circle(25, "solid", "red")
```

- A `TypeError`: `*` expects two numbers (and returns a number), not a number
  and an image.
- Values have **types**. So far: `int` and `float` (numbers), `str` (strings),
  and `Image`.
- A function's **contract** is the types of inputs it requires and the type of
  output it promises, written with **type annotations**:

```
circle(radius: float, mode: str, color: str) -> Image
rotate(angle: float, image: Image) -> Image
```

- Read `:` as "has the type" and `->` as "returns": `rotate` takes a number and
  an `Image`, and returns an `Image`.
- When composing, the types the inner expressions produce must match the types
  the outer function requires.
- A contract also says _how many_ inputs: `circle(100, "purple")` is an error,
  since `circle` takes three.
- Try: give a function the wrong type of input, then the wrong number of inputs,
  and notice what the error messages have in common.

### Syntax Errors

Can you spot the mistake in each of these?

```python error
circle(50 "solid" "red")
circle(50, "solid,  "red")
circle(50, "solid," "red")
circle 50, "solid," "red")
```

- The rules for writing proper expressions are the **syntax**. Python can't run
  an expression with a syntax error.
- So far: a function's inputs go in parentheses, separated by commas; a string
  that starts with a double quote needs one to end it.
- Syntax mistakes are common at first: you'll internalize the rules in time.

### Strings and Images

Here is a `2.py` with some string expressions, and some image expressions that
draw trees. Read it, and predict what PLL will show, before running it:

```python
#level beginner

"hello" + " " + "cs2000!"
len("hello cs2000!")
"go " * 3

above(triangle(50, "solid", "green"),
      rectangle(10, 30, "solid", "brown"))

beside(above(triangle(50, "solid", "green"),
             rectangle(10, 30, "solid", "brown")),
       above(triangle(30, "solid", "green"),
             rectangle(6, 18, "solid", "brown")))

overlay(circle(5, "solid", "red"),
        triangle(50, "solid", "green"))
```

- What are the values of the first three expressions, and what is the type of
  each? What would `"hello cs" + 2000` do instead, and why?
- The `beside` expression makes two trees: which one is on the left, and which
  is smaller? To make every trunk gray, how many places in the file would you
  have to change?
- In the last expression, which shape is on top? What would you see if the
  circle's radius were `40` instead of `5`?

## Wrap-up (10 mins)

- Did anyone get errors while they were working on these exercises? (Get someone
  to share -- likely is a type error, either passing the wrong number of arguments or passing the wrong
  type of input to one of the functions).
- In Python, all values have types -- what we've seen so far are: `int`, `float`, `str` (strings), and `Image`.
- Further, operations have types that they take in, and types that they produce. These are usually written down in the documentation with _type annotations_, e.g.:
  ```
  len(s: str) -> int
  circle(radius: float, mode: str, color: str) -> Image
  ```
- This captures both the number of arguments (one for `len`, three for `circle`) and the *type* of the arguments (in the parentheses, after the `:`) and what it produces (after the arrow, written `->`), so if you make a mistake in either, Python can report that.
- When we get to writing our own operations, we will write down types for them, so that similarly, PLL can report if our operations are not used correctly!
