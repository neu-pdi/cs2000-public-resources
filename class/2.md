## Notes (review before class)
### Strings

A **string** is text: characters between double quotes (single quotes, as in
`'tree'`, work too). Three double quotes on each side make a string that can
cross lines:

```python
"green"
"Hello, Boston!"
"""one line,
and another"""
```

- Strings can hold spaces, punctuation, and digits. For our trees, strings name
  colors: `"green"`, `"brown"`.
- Strings are **case-sensitive**: `"Green"` and `"green"` are different strings.

Strings have operations too:

```python
"hello" + " " + "cs2000!"
len("hello cs2000!")
"go " * 3
```

- `+` puts the second string after the first: `"hello" + " " + "cs2000!"` is `"hello cs2000!"`.
- `len(s)` is the number of characters in `s`: `len("hello cs2000!")` is `13`.
- `s * n` (`n` a non-negative `int`) is `s` repeated `n` times: `"go " * 3` is `"go go go "`.

### Images

Python doesn't have images built in, but PLL adds them. Here are the pieces of a
tree, and an apple:

```python
triangle(50, "solid", "green")
rectangle(10, 30, "solid", "brown")
circle(5, "solid", "red")
```

- Each names a shape, then gives its size in screen pixels (a triangle's side
  length; a rectangle's width, then height; a circle's radius), then `"solid"`
  or `"outline"`, then a color.

### Combining Images

With any new kind of data, ask what you can do with it. Images can be stacked,
layered, and turned:

```python
above(triangle(50, "solid", "green"),
      rectangle(10, 30, "solid", "brown"))

overlay(circle(5, "solid", "red"),
        triangle(50, "solid", "green"))

rotate(90, rectangle(10, 30, "solid", "brown"))
```

- `above(i1, i2)` puts `i1` above `i2`, centered: a tree. `beside(i1, i2)` puts
  them side by side.
- `overlay(i1, i2)` puts `i1` on top of `i2`, centered: an apple on the tree. If
  `i1` were bigger, it would hide `i2`.
- `above`, `beside`, and `overlay` take any number of images, not just two:
  `beside(circle(10, "solid", "red"), circle(10, "solid", "orange"), circle(10, "solid", "yellow"))`
  is three circles in a row.
- `rotate(90, i)` is `i` turned 90 degrees counter-clockwise: e.g., the last becomes a fallen trunk (how else could you have done that?).

### Functions and Composition

Operations like `+` and `above` are **functions**. Every function produces a
value, and that value can be the input to another function:

```python
beside(above(triangle(50, "solid", "green"),
             rectangle(10, 30, "solid", "brown")),
       above(triangle(30, "solid", "green"),
             rectangle(6, 18, "solid", "brown")))
```

- Two trees side by side, the second smaller. Feeding one function's result to
  another is **composition**, and nearly every program is built that way.
- To make both trunks gray, how many places would you have to change? (The next
  class fixes that.)
- Try: a snowman of three outlined circles, the smallest on top; then the apple
  tree from the [Class 1](/class/1) picture.

### Types and Contracts

```python error
triangle(50, "solid", "green") + rectangle(10, 30, "solid", "brown")
```

- A `TypeError`: `+` joins two numbers or two strings (and later, some other data), not two images. (PLL's
  message suggests what to use instead.)
- Values have **types**. So far: `int` and `float` (numbers), `str` (strings),
  and `Image`.
- A function's **contract** says what types of input it needs, and what type of
  output it gives back. Documentation writes it with **type annotations**. This line is what we refer to as a function **signature**:

```
triangle(side: float, mode: str, color: str) -> Image
len(s: str) -> int
```

- `side: float` says that the input `side` must be a `float`; `-> Image` says
  that what comes back is an `Image`.
- When composing, each inner expression must produce the type that the outer
  function needs: `len(triangle(50, "solid", "green"))` breaks `len`'s contract.
- A contract also says _how many_ inputs: `triangle(50, "green")` is an error,
  since `triangle` takes three.
- Try: `len(42)`, then `rectangle(10, "brown")`. What does each message tell you
  about the contract you broke?

### Syntax Errors

What's wrong with each of these?

```python error
triangle(50 "solid" "green")
triangle(50, "solid, "green")
above(triangle(50, "solid", "green") rectangle(10, 30, "solid", "brown"))
triangle 50, "solid", "green")
```

- The rules for how expressions are written are the language's **syntax**.
  Python can't run a program with a syntax error in it.
- So far: a function's inputs go in parentheses, separated by commas, and a
  string that starts with a double quote ends with one.
- Everyone makes these mistakes at first; the rules become habits.

### Documentation

- Every language documents its functions. It's usually more detail than you

- The [PLL Images reference](/pll/images) has the functions for making shapes,

- For strings, and the rest of Python: the
  [Python documentation](https://docs.python.org/3/).
