### Functions over Rows

A coffee cart records the time and amount of each order:

```python
orders = table(
    ["time", "amount"],
    [
        ["08:00", 10.50],
        ["09:30", 5.75],
        ["10:15", 8.00],
        ["11:00", 3.95],
        ["14:00", 4.95],
        ["16:45", 7.95],
    ],
)
```

A function can ask a question about a row: is an order high-value, with an
amount of at least 8? Design it with the recipe; today's new step is the
template for a row:

<DesignRecipe focus="Template" />

- **Data definition**: a row of `orders` has a `time` (a `str`, like `"09:30"`)
  and an `amount` (a `float`, in dollars). Rows are `dict`s, so that's the
  annotation for the input. `orders.row(2)` (8.00) and `orders.row(3)` (3.95)
  are examples of it.
- **Template**: a row's parts are its columns, so the template for a row of
  `orders` has a line for each column the body could use
  ([templates for rows](/class/recipe#template-rows)):

```python
def _order_row_temp(r: dict) -> ...:
    ...
    r["time"]
    ...
    r["amount"]
    ...
    return ...
```

- **Signature** and **Docstring**, with `...` for the body:

```python
def is_high_value(r: dict) -> bool:
    """whether the order in row r is high-value: an amount of at least 8"""
    ...
```

- **Examples**: tests, with the example rows as inputs. `orders.row(2)` is a
  good one: at exactly 8.00, it's on the boundary.

```python
def test_is_high_value():
    assert is_high_value(orders.row(2))
    assert not is_high_value(orders.row(3))
```

- **Body**: copy the template's body into `is_high_value`. This question only
  needs `amount`, so the `r["time"]` line goes:

```python
def is_high_value(r: dict) -> bool:
    """whether the order in row r is high-value: an amount of at least 8"""
    return r["amount"] >= 8
```

- A function that returns a boolean can be tested by `assert`ing its result
  directly, or `assert not`, to check that it's `False`.
- Taking a row, rather than a position (`is_high_value(2)`), is more flexible:
  it works on a row from _any_ table with an `"amount"` column, not just
  `orders`.
- Try: write `under_5`, whether an order's amount is less than 5, and
  `small_afternoon`, whether it's an order under 5 at `"12:00"` or later
  (`<` and `>=` compare strings character by character, so `"14:00" >= "12:00"`
  is `True`). Write each one's Signature (with `...`), Docstring and Examples,
  and run them, before its Body. Then show how the directory evolves as one of
  your tests runs.

### Finding Rows: `filter`

- To find every high-value order, we could check `orders.row(0)`, then
  `orders.row(1)`, and so on. But a busy cart has hundreds of orders a day, and
  we want all the matches, not the first one.
- Instead, write the question as a function from a row to a boolean (we just
  did), and give it to the table method **`filter`**, which calls it on each
  row, one at a time, and keeps the rows where it says `True`:

```python
high_value_orders = orders.filter(is_high_value)

def test_high_value_orders():
    assert high_value_orders == table(
        ["time", "amount"],
        [
            ["08:00", 10.50],
            ["10:15", 8.00],
        ],
    )
```

- No parentheses after `is_high_value`: we aren't calling it, we're giving it to
  `filter`, which calls it.
- `filter` produces a _table_ of all the matching rows, in their order, which we
  can name, and test like any other value.
- This is the first shape of the **table template**
  ([templates for tables](/class/recipe#template-tables)): a function whose
  answer is a table with _fewer rows_ is a `filter`, and needs a helper from a
  row to a `bool`. The template knows that much, so it has the helper as a local
  function (a `def` inside the `def`), whose body is the row's template. Fill it
  in where it is, or, like `is_high_value`, design it as a function of its own
  and pass that. The other two shapes come in [Class 9](/class/9).

```python
def _keep_rows_temp(t: Table) -> Table:
    def keep(r: dict) -> bool:
        ...
        r
        ...
        return ...
    return t.filter(keep)
```

- Try: if "high-value" meant an amount of at least 7.95, which lines would
  change, and how?

### Ordering Rows: `order_by`

- `filter` checks each row on its own, so it can't answer questions that compare
  rows, like _which high-value order was the smallest?_
- **`order_by`** sorts the rows by a column: `ascending=True` from smallest to
  largest, `ascending=False` from largest to smallest. It makes a new table,
  without changing `high_value_orders`:

```python
high_value_orders.order_by("amount", ascending=True)  # 10:15, then 08:00
```

- Combine operations to answer a question: find rows (`filter`), order them
  (`order_by`), take a row (`row`), then a cell (`[...]`), as we combined image
  operations. All at once, or naming each step (adding names to the directory):

```python
high_value_orders.order_by("amount", ascending=True).row(0)["time"]  # -> '10:15'

sorted_high = high_value_orders.order_by("amount", ascending=True)
smallest_high = sorted_high.row(0)
smallest_high["time"]  # -> '10:15'
```

- Try: what is the last line with `ascending=False`?
