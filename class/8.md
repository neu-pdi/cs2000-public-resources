## Notes (review before class)
### Functions over Rows

A function can ask a question about a row. Does a month's row show at least
1000 riders? Design it with the recipe; today's new step is the template for a
row:

<DesignRecipe focus="Template" />

- **Data definition**: a row of `shuttle` has a `month` (a `str`) and `riders`
  (an `int`). Rows are `dict`s, so that's the annotation for the input.
  `shuttle.row(2)` (1087 riders) and `shuttle.row(3)` (999) are examples of it.
- **Template**: a row's parts are its columns, so the template for a row of
  `shuttle` has a line for each column the body could use
  ([templates for rows](/class/recipe#template-rows)):

```python
def _shuttle_row_temp(r: dict) -> ...:
    ...
    r["month"]
    ...
    r["riders"]
    ...
    return ...
```

- **Signature** and **Docstring**, with `...` for the body:

```python
def cleared_1k(r: dict) -> bool:
    """determine whether given row has at least 1000 riders"""
    ...
```

- **Examples**: tests, with the example rows as inputs:

```python
def test_cleared_1k():
    assert cleared_1k(shuttle.row(2))
    assert not cleared_1k(shuttle.row(3))
```

- **Body**: copy the template's body into `cleared_1k`. This question only needs
  `riders`, so the `r["month"]` line goes:

```python
def cleared_1k(r: dict) -> bool:
    """determine whether given row has at least 1000 riders"""
    return r["riders"] >= 1000
```

- A function that returns a boolean can be tested by `assert`ing its result
  directly, or `assert not`, to check that it's `False`.
- Taking a row, rather than a position (`cleared_1k(2)`), is more flexible: it
  works on a row from _any_ table with a `"riders"` column, not just `shuttle`.
- Try: write `is_winter`, whether a row's `"month"` is `"Jan"`, `"Feb"`, or
  `"Mar"`, and `low_winter`, whether it's a winter row with fewer than 1050
  riders. Write each one's Signature (with `...`), Docstring and Examples, and
  run them, before its Body. Then show how the directory evolves as one of your
  tests runs.

### Finding Rows: `filter`

- Checking rows one position at a time
  (`if shuttle.row(0)["riders"] < 1000: ... elif shuttle.row(1)...`) is
  painful for thousands of rows, finds only one match, and has no clear answer
  when nothing matches.
- Instead, write the question as a function from a row to a boolean, and give it
  to the table method **`filter`**, which calls it on each row, one at a time:

```python
def below_1k(r: dict) -> bool:
    """determine whether row has fewer than 1000 riders"""
    return r["riders"] < 1000

def test_below_1k():
    assert not below_1k(shuttle.row(2))
    assert below_1k(shuttle.row(3))

shuttle.filter(below_1k)
```

- No parentheses after `below_1k`: we aren't calling it, we're giving it to
  `filter`, which calls it.
- This is the first shape of the **table template**
  ([templates for tables](/class/recipe#template-tables)): a function whose
  answer is a table with _fewer rows_ is a `filter`, and needs a helper from a
  row to a `bool`, designed with the recipe like `cleared_1k`, in place of the
  `...`. The other two shapes come in [Class 9](/class/9).

```python
def _keep_rows_temp(t: Table) -> Table:
    return t.filter(...)
```

- `filter` produces a _table_ of all the matching rows, which we can name:

<!-- python setup
# (the exercise above)
def is_winter(r: dict) -> bool:
    """whether the row is for a winter month"""
    return r["month"] == "Jan" or r["month"] == "Feb" or r["month"] == "Mar"
-->

```python
winter = shuttle.filter(is_winter)  # the Jan, Feb, and Mar rows
```

### Ordering Rows: `order_by`

- `filter` checks each row on its own, so it can't answer questions that compare
  rows, like _which winter month had the fewest riders?_
- **`order_by`** sorts the rows by a column: `ascending=True` from smallest to
  largest, `ascending=False` from largest to smallest. It makes a new table,
  without changing `winter`:

```python
winter.order_by("riders", ascending=True)  # Feb, then Mar, then Jan
```

- Combine operations to answer a question: find rows (`filter`), order them
  (`order_by`), take a row (`row`), then a cell (`[...]`), as we combined image
  operations. All at once, or naming each step (adding names to the directory):

```python
winter.order_by("riders", ascending=True).row(0)["month"]  # -> 'Feb'

sorted_winter = winter.order_by("riders", ascending=True)
least_row = sorted_winter.row(0)
least_row["month"]  # -> 'Feb'
```

## Recap (15 mins)

A coffee cart records the time and amount of each order. Read through the
program, which finds the high-value orders (an amount of at least 8):

```python
orders = table(
    ["time", "amount"],
    [
        ["08:00", 10.50],
        ["09:30", 5.75],
        ["10:15", 8.00],
        ["11:00", 3.95],
        ["14:00", 4.95],
        ["16:45", 7.95],
    ],
)

def is_high_value(r: dict) -> bool:
    """returns whether the amount column is >= 8"""
    return r["amount"] >= 8.0

def test_is_high_value():
    assert is_high_value(orders.row(2))
    assert not is_high_value(orders.row(3))

high_value_orders = orders.filter(is_high_value)

def test_high_value_orders():
    assert high_value_orders == table(
        ["time", "amount"],
        [
            ["08:00", 10.50],
            ["10:15", 8.00],
        ],
    )

smallest_high_time = high_value_orders.order_by("amount", ascending=True).row(0)["time"]
```

- Why is `orders.row(2)` a good row for `test_is_high_value` to check?
- What is `smallest_high_time`? What would it be with `ascending=False`?
- If "high-value" meant an amount of at least 7.95, which lines would change,
  and how?
- `is_high_value`'s template lists which columns? Which one does its body use?
- `high_value_orders` has fewer rows than `orders`: which shape of the table
  template made it?
