## Notes (review before class)
### Tables

- A **table** has **rows** that share the same attributes, its **columns**: a
  workout journal, a recipe index, a library catalog.
- Tables are values: they can be named, passed to functions, and returned. PLL
  provides them; there's nothing to import.
- Code that works with tables follows their structure of rows and columns.

### Literal Tables

A **literal** table is written out with `table`, given the column names, in
order, and then a list of rows:

```python
people = table(
    ["name", "age"],
    [
        ["Alicia", 30],
        ["Meihui", 40],
        ["Jamal", 25],
    ],
)
```

- Each row has one value per column, in order. (Try: remove a value or a comma,
  and read the error.)
- The directory gets just `people`, for the whole table: no column names.
- Tables are equal only if their columns _and_ rows are in the same order. A
  test function can check a fact, rather than a function (`!=` is "not equal"):

```python
def test_column_order_matters():
    assert people != table(
        ["age", "name"],
        [[30, "Alicia"], [40, "Meihui"], [25, "Jamal"]],
    )
```

<Aside title="Lists">

Square brackets make a **list**: values, in order, separated by commas, like
`[30, 40, 25]`. `table` is given a list of column names and a list of rows, each
itself a list. More in [Class 13](/class/13).

</Aside>

### Loading Tables from CSV Files

- `load_table` loads a **CSV** ("comma-separated values") file, which any
  spreadsheet can save, from a URL or a file in your program's folder:
  `load_table("riders.csv")`. The column names come from its first line.
- **Every value loaded from a CSV is a string**, even `"4"`. Convert numeric
  columns, into a new table, with `transform_column` ([Class 9](/class/9)) and
  `int` (`"4"` to `4`) or `float` (`"4.5"` to `4.5`):
  `riders = riders_raw.transform_column("riders", int)`.
- Table operations like this are **methods** (like the string methods of
  [Class 2](/class/2)): written after the table, with a dot.

### Rows and Cells

`t.row(n)` is row `n`, counting from 0 at the top (so the last is one less than
the number of rows). A row is a `dict`: a column's name, a string, in square
brackets gives its value.

```python
shuttle = table(
    ["month", "riders"],
    [
        ["Jan", 1123],
        ["Feb", 1045],
        ["Mar", 1087],
        ["Apr", 999],
    ],
)

shuttle.row(2)            # -> {'month': 'Mar', 'riders': 1087}
shuttle.row(2)["riders"]  # -> 1087
march_row = shuttle.row(2)
march_row["riders"]       # -> 1087
```

- Values work in any computation: `shuttle.row(2)["riders"] >= 1000`.
- Without quotes, `shuttle.row(2)[riders]` is an error: `riders` isn't in the
  directory.
- Only the named version adds an entry, `march_row`, to the directory.
- Running a table's name shows it (its first rows, if it is long).
- The columns, and the type of each, describe the table's data: every row of
  `shuttle` has a `month` (a `str`) and `riders` (an `int`). Every function on
  its rows relies on that description, which is the
  [design recipe](/class/recipe)'s **Data definition** step (in words, for now).

<Aside title="Dictionaries">

A **dictionary** (`dict`), written `{key: value, ...}`, maps **keys** to
**values**: you look up a value by its key, not its position.

```python
capitals = {"France": "Paris", "Japan": "Tokyo", "Peru": "Lima"}
capitals["Japan"]   # -> 'Tokyo'
```

- Each key appears once. Keys needn't be strings: `{411: "Pauline"}` maps a room
  number to a person.
- So a row's values are looked up by column _name_; a table's rows, by position.
- A missing key, like `capitals["Chile"]`, is an error, not a quiet nothing.

</Aside>

### Summarizing Columns

`sum`, `mean`, `min`, and `max` give a column's total, average, smallest, and
largest value (more in [Tables](/pll/tables)): `shuttle.max("riders")` is `1123`.

## Recap (15 mins)

A workout journal is small enough to type in as a table; a recipe index is a CSV
file on the web. Read through the program:

```python
workouts = table(
    ["date", "activity", "duration"],
    [
        ["2025-04-01", "Running", 30],
        ["2025-04-02", "Yoga", 45],
        ["2025-04-03", "Cycling", 60],
    ],
)

def test_row_order_matters():
    assert workouts != table(
        ["date", "activity", "duration"],
        [
            ["2025-04-03", "Cycling", 60],
            ["2025-04-01", "Running", 30],
            ["2025-04-02", "Yoga", 45],
        ],
    )

second_workout = workouts.row(1)
second_activity = second_workout["activity"]
average_duration = workouts.mean("duration")

recipes_raw = load_table("https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/5-recipes.csv")
recipes_with_servings = recipes_raw.transform_column("servings", int)
recipes = recipes_with_servings.transform_column("prep time", int)
average_prep_time = recipes.mean("prep time")
```

- What are `second_activity` and `average_duration`? What expression would
  give the date of the first workout?
- Why does `test_row_order_matters` pass?
- Why does the program compute `average_prep_time` from `recipes`, rather than
  from `recipes_raw`? How are those two tables different?
