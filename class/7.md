## Reading (Done Before Class)
### Creating Tabular Data

The simplest way to create a table is to write it directly in a program (and,
like numbers, strings, and images, we can give it a name):

```python
people = table(
    ["name", "age"],
    [
        ["Alicia", 30],
        ["Meihui", 40],
        ["Jamal", 25],
    ],
)
```

`table` is given the names of the columns, in their desired order, and then a
list of rows. Each row must contain as many values as there are columns, in the
same order. Try changing parts of this example -- remove a value from a row, add
an extra one, remove a comma -- and see what errors you get.

In a table, the order of columns matters: two tables that are otherwise
identical, but with different column orders, are not equal (`!=`), so this test
passes:

```python
def test_column_order_matters():
    assert people != table(
        ["age", "name"],
        [[30, "Alicia"], [40, "Meihui"], [25, "Jamal"]],
    )
```

We call tables written out like this _literal_ tables. We can also load a table
from a CSV file, which any spreadsheet program can save, with `load_table` (see
below). So you might make a spreadsheet on your own or with friends, find data
on the web, or collect the responses to a form: once the data are in Python, it
doesn't matter where they came from.

Tables are our first _structured data_: data that _contain other (smaller)
pieces of data_, organized in a structured way (here, rows and columns). Just as
our code for images reflected the structure of the image, code that works with
tables will follow the structure of the data.

### Extracting Rows and Cell Values

Given a table, we sometimes want to look up the value of a particular cell.
Take this table of the number of riders on a shuttle service:

```python
shuttle = table(
    ["month", "riders"],
    [
        ["Jan", 1123],
        ["Feb", 1045],
        ["Mar", 1087],
        ["Apr", 999],
    ],
)
```

If you run this, what will be in the program directory? Just `shuttle`, bound
to the entire table: the column names don't get entries of their own, since we
never wrote `month = ...`.

Say we want the number of riders in March (`1087`). Tables are organized as
collections of rows with shared columns, so we first isolate the row, and then
get the cell. Rows are numbered from the top, starting at 0 (as positions are in
most programming languages), so March is row 2:

```python
shuttle.row(2)  # -> {'month': 'Mar', 'riders': 1087}
```

A row is a new type of data, a `dict`, which shows each column's name with its
value in that row. To get one column's value, write the column's name (a string)
in square brackets after the row. Here are two equivalent ways of getting the
riders in March:

```python
shuttle.row(2)["riders"]
```

```python
march_row = shuttle.row(2)
march_row["riders"]
```

What names are in the program directory with each of these? Once we have the
value (here, a number), we can use it in any other computation:
`shuttle.row(2)["riders"] >= 1000` checks whether there were at least 1000
riders in March. What would happen if you forgot the quotation marks, and wrote
`shuttle.row(2)[riders]`? Why?

## Recap (15 mins)

**Goal** Learn about tabular data, creating tables literally, importing data, extracting rows and cell values.

- Many everyday pieces of data -- like a workout journal, recipe index, or
  library catalog — are naturally represented as **tables**, a type of data
  where there are many **rows** where each row has the same set of attributes,
  called **columns**.

- Tables are values, just like numbers, strings, images, and booleans. Like
  images, they aren't built into Python, but PLL adds them, so there is nothing
  you need to import to use them. Small ones can be directly typed in as:

  ```python
  workouts = table(
      ["date", "activity", "duration"],
      [
          ["2025-04-01", "Running", 30],
          ["2025-04-02", "Yoga", 45],
          ["2025-04-03", "Cycling", 60],
      ],
  )
  ```

- Note that `table` is given two things, each written in square brackets
  (we'll learn more about square brackets, which create _lists_, in a few weeks). First, the names
  of the columns. Second, a sequence of rows, each in its own square brackets, that each must have
  exactly one value for each of the columns mentioned at the beginning.

- Since tables are values, they can be the input and output of functions, and
  can be used in examples. An important detail: when comparing tables for
  equality (like in test cases) the order of rows matters! Similarly, the order of the columns matters (see reading).

- Test functions don't have to be about a particular function: we can write one, with a name that describes what it checks, and use that to see (`!=` means "not equal"):

  ```python
  def test_row_order_matters():
      assert table(
          ["date", "activity", "duration"],
          [
              ["2025-04-01", "Running", 30],
              ["2025-04-02", "Yoga", 45],
              ["2025-04-03", "Cycling", 60],
          ],
      ) != table(
          ["date", "activity", "duration"],
          [
              ["2025-04-03", "Cycling", 60],
              ["2025-04-01", "Running", 30],
              ["2025-04-02", "Yoga", 45],
          ],
      )
  ```

- To deal with external files, we can load tables represented as "comma
  separated values" (CSV) files using `load_table`, rather than `table`, and
  rather than listing the rows, specifying where the CSV is: either its URL, or
  the name of a file that is in the same folder as your program. The names of
  the columns come from the first line of the CSV.

  ```python
  recipes = load_table("https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/5-recipes.csv")
  ```

- **IMPORTANT:** all values loaded from a CSV are strings; to convert numeric data to numbers, we can use `transform_column`. We will talk more about this operation in [Class 9](/class/9), but for any CSV that has numeric columns, you should initially load the raw version, and then create a new table where you have transformed the columns using functions that convert to the right data type, like `int` (which converts a string like `"4"` to the whole number `4`) or `float` (which converts a string like `"4.5"` to `4.5`):

  ```python
  recipes_raw = load_table("https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/5-recipes.csv")
  recipes_with_servings = recipes_raw.transform_column("servings", int)
  recipes = recipes_with_servings.transform_column("prep time", int)
  ```

- Operations on tables, like `transform_column`, are _methods_ (like the string
  methods we saw on [Class 2](/class/2)), written after the table, with a dot.

- In addition to printing the whole table (or a prefix, if the table is long),
  you can extract a row from it by writing `table_identifier.row(N)` for some `N`.
  The first row is numbered `0`, the last is one minus the number of rows in the table.

  ```python
  second_workout = workouts.row(1)
  # -> {'date': '2025-04-02', 'activity': 'Yoga', 'duration': 45}
  ```

- From a row, you can extract a column's value by writing the column name in square brackets after it, e.g.,

  ```python
  second_workout["activity"]  # -> "Yoga"
  # or all at once:
  workouts.row(1)["duration"]  # -> 45
  ```

- There are also built-in methods that compute results -- e.g., `mean` takes a column name, and
  returns the average of all values in that column. Others, like `sum`, `min`, and `max`, exist as well (see [Tables](/pll/tables) reference page for more details.)

  ```python
  workouts.mean("duration") # -> 45.0
  ```
