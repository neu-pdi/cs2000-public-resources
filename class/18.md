## Notes (review before class)
### Changing Variables Only Inside Functions

- The [loop template](/class/recipe#template-loops) ([Class 16](/class/16))
  changes only variables made inside the function. Each call makes its own, in
  its own directory, removed when the call returns, so no two calls share one.
- `#level intermediate` allows changing a variable only inside a function.

### Shared Variables

`every_third_element` returns the first, fourth, seventh, ... elements of a
list, keeping track of the position in `count`. This version keeps `count`
_outside_ the function:

```python
#level advanced

count = 0

def every_third_element(lst: list) -> list:
    """returns the first, fourth, seventh, ... elements of lst"""
    global count
    output = []
    for elt in lst:
        if count % 3 == 0:
            output = output + [elt]
        count = count + 1
    return output

def test_every_third_element():
    assert every_third_element([]) == []
    assert every_third_element([1, 3, 5]) == [1]
    assert every_third_element([1, 3, 5, 7, 11]) == [1, 7]
```

- **`global count`** lets the function change the outside `count`; without it,
  assigning to `count` would make a new, local variable. PLL only allows `global`
  at `#level advanced`, which skips our levels' extra checks.
- `%` is the remainder after dividing, so `count % 3 == 0` is true at 0, 3,
  6, ...: every third position.
- The test passes. But add the line `every_third_element([1, 3])` at the end of
  the file, and it fails: `every_third_element([1, 3, 5])` gives `[3]`, not
  `[1]`. PLL runs the tests after the rest of the file, and that call left
  `count` at 2.
- The directory has one `count`, **shared** by every call and never reset: a
  call's result depends on every call before it, which the code doesn't show.
  (The test passed only because each of its lists happened to leave `count` at
  a multiple of 3.)
- So two steps of the design recipe can't be done. The **Docstring** can't say
  what the function gives for a list, since the answer also depends on earlier
  calls; and an **Example** can't say what a call should give, for the same
  reason. Keeping changes inside the function is what makes those steps
  possible.

Following the loop template, `count` is made inside, so every call starts
fresh, and the file runs at `#level intermediate`:

```python skip
#level intermediate

def every_third_element(lst: list) -> list:
    """returns the first, fourth, seventh, ... elements of lst"""
    count = 0
    output = []
    for elt in lst:
        if count % 3 == 0:
            output = output + [elt]
        count = count + 1
    return output
```

Try: trace `count` through the first version's test, with the extra call at the
end, to see where `[3]` comes from. For which version is the Docstring true?

### Side Effects

- A function that changes something outside itself has a **side effect**. Side
  effects make code hard to test and to understand, and so prone to bugs, often
  ones that appear only when calls happen in some rare order.
- They're sometimes needed, but almost all code can do without them, and is more
  reliable for it.

## Practice

For these exercises, use `#level advanced`, since they all use `global`.

1. What does each call return? (Trace very carefully through the execution order):
    ```python
    #level advanced

    score = 10

    def bonus_points(amt: int) -> int:
        global score
        score = score + amt
        return penalty_check()

    def penalty_check() -> int:
        global score
        if score > 15:
            score = score - 3
        return score

    bonus_points(2)
    bonus_points(4)
    bonus_points(1)
    ```
1. Trace through these function calls. What does `process_data` return each time?

    ```python
    dta = [1, 2, 3]
    position = 0

    def advance() -> int:
        global dta, position
        result = dta[position]
        position = position + 1
        if position >= len(dta):
            position = 0
            dta = [0] + dta
        return result

    def process_data() -> int:
        first = advance()
        second = advance()
        return first + second

    process_data()
    process_data()
    process_data()
    ```

1. Trace execution. What does `calculate` return for each call?

    ```python
    multiplier = 1
    base = 5

    def update_multiplier(n: int) -> int:
        global multiplier, base
        multiplier = multiplier + n
        if multiplier % 3 == 0:
            base = base - 1
            multiplier = 1
        return multiplier

    def calculate(x: int) -> int:
        update_multiplier(x)
        return x*multiplier + base

    calculate(2)
    calculate(1)
    calculate(4)
    calculate(2)
    ```
