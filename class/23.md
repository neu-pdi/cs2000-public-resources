## Notes (review before class)
### The List Template

From [Class 22](/class/22): a list is self-referential data. It is either empty,
`[]`, or a first element on top of the rest, which is itself a list. Its
template has a `case` for each, and a recursive call on the rest:

```python
def _list_temp(lst: list) -> ...:
    match lst:
        case []:
            return ...
        case [f, *r]:
            ...
            f
            ...
            _list_temp(r)
            ...
            return ...
```

### Examples That Extend Each Other

`insert_sorted` puts a number into its place in a list of numbers that is in
order, smallest first. Its Signature and Docstring:

```python skip
def insert_sorted(n: float, lst: list[float]) -> list[float]:
    """lst, in order smallest first, with n added in its place"""
    ...
```

For the Examples, take a list and each of its rests, down to `[]`, lined up, so
that each input extends the one below it:

```python skip
def test_insert_sorted():
    assert insert_sorted(3, [1, 2, 4, 5]) == [1, 2, 3, 4, 5]
    assert insert_sorted(3, [   2, 4, 5]) == [   2, 3, 4, 5]
    assert insert_sorted(3, [      4, 5]) == [      3, 4, 5]
    assert insert_sorted(3, [         5]) == [      3,    5]
    assert insert_sorted(3, [          ]) == [      3      ]
```

Now read each line against the one below it, which is what the recursive call
gives for the rest:

- For `[1, 2, 4, 5]`, the answer is `1` on top of the next line's answer:
  `[1] + insert_sorted(3, [2, 4, 5])`. So is `[2, 4, 5]`'s, with `2`. There, the
  first element is smaller than `3`, so it stays in front, and `3` goes
  somewhere in the rest.
- For `[4, 5]`, it isn't: `3` goes in front, and the rest isn't needed at all.
  The answer is `[3] + [4, 5]`, not anything built from the next line. So is
  `[5]`'s.
- For `[]`, the answer is just `[3]`.

That's two kinds of non-empty example: the body's `case [f, *r]` needs an `if`,
to tell them apart. Copy the template, and fill it in:

```python
def insert_sorted(n: float, lst: list[float]) -> list[float]:
    """lst, in order smallest first, with n added in its place"""
    match lst:
        case []:
            return [n]
        case [f, *r]:
            if n <= f:
                return [n] + lst
            else:
                return [f] + insert_sorted(n, r)

def test_insert_sorted():
    assert insert_sorted(3, [1, 2, 4, 5]) == [1, 2, 3, 4, 5]
    assert insert_sorted(3, [2, 4, 5]) == [2, 3, 4, 5]
    assert insert_sorted(3, [4, 5]) == [3, 4, 5]
    assert insert_sorted(3, [5]) == [3, 5]
    assert insert_sorted(3, []) == [3]
    assert insert_sorted(4, [4, 5]) == [4, 4, 5]
```

- In the `if`, the recursive call isn't needed: when `n` goes in front, the
  answer is ready. A template's parts are what a function _may_ use, not what it
  must.
- The last test is the Test and revise step: what should happen when `n` is
  already in the list? `n <= f` puts it in front of the one that's equal, and
  `n < f` would put it after. Either is in order; the test pins down which this
  function does.
- `n` is passed along unchanged to the recursive call: the number being inserted
  is the same at every step, and only the list gets shorter.

### A Choice in the Body

We want to add up the numbers in a list, up to the first `0` (or all of them, if
there is no `0`). Again, a list and each of its rests, lined up:

```python
def add_till_zero(lst: list[float]) -> float:
    """adds up the numbers in lst, up to the first 0 (or all, if there is no 0)"""
    match lst:
        case []:
            return 0
        case [f, *r]:
            if f == 0:
                return 0
            else:
                return f + add_till_zero(r)

def test_add_till_zero():
    assert add_till_zero([7, 3, 0, 5]) == 10
    assert add_till_zero([   3, 0, 5]) == 3
    assert add_till_zero([      0, 5]) == 0
    assert add_till_zero([         5]) == 5
    assert add_till_zero([          ]) == 0
```

- Most answers are the first number plus the next line's answer: `10` is
  `7 + 3`, and `5` is `5 + 0`.
- One example is different: `add_till_zero([0, 5])` is `0`, not `0 +` anything.
  That example is the reason for the `if f == 0:`: the non-empty case has two
  cases of its own, decided by the first element.
- Which lines of the body are the same as in `total_boxes`
  ([Class 22](/class/22)), and which came from this function's own examples?

### Every Template So Far

The rule behind the template for self-referential data is the one behind each
template since [Class 5](/class/5): **one part of the body for each part of the
data**, plus a recursive call on each field of the type being defined:

| Data | The template | From |
| --- | --- | --- |
| a number split into intervals | an `if` branch per interval | [Class 5](/class/5) |
| a row | a line for each column: `r["col"]` | [Class 8](/class/8) |
| a table, made into a new one | fewer rows (`filter`), a new column (`add_column`), or a changed column (`transform_column`) | [Class 9](/class/9) |
| a fixed set of strings | an `if` branch per value, and an `else` | [Class 11](/class/11) |
| a list, with built-ins | fewer elements (`filter`), each one changed (`map`), or one value (`sum`) | [Class 14](/class/14) |
| a list, with a loop | a `for`, combining, building, or checking | [Class 16](/class/16) |
| a dataclass | a line for each field: `s.field` | [Class 20](/class/20) |
| a union | a `case` per variant, with a line for each of its fields | [Class 21](/class/21) |
| self-referential data, like a stack or a list | a `case` per variant, with a line for each of its fields, and a recursive call on each field of its own type | [Class 22](/class/22) |

Each is on the [Design Recipe](/class/recipe#templates) page.

   ```
   1, 2, 3, 0, 4, 5, 6, 0, 7, 8, 9  →  1, 2, 3, -4, -5, -6
   ```

   It's easiest as _two_ functions: one for before the first 0, and one for
   after it.
