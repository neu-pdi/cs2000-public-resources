## Notes (review before class)
### Libraries, `**`, and `pytest.approx`

- A **library** is a collection of extra functions: `import` it at the top of
  the file (after the `#level` line), then use its name and a dot: `math.sqrt(9)`
  is `3.0`. More in [Class 13](/class/13).
- `**` is exponentiation: `n ** 2` is `n` squared.
- `float`s are mostly approximate ([Class 1](/class/1)), so results like
  `math.sqrt(2)` may be very slightly off. Test them with **`pytest.approx`**,
  which checks that a number is _very close_ to what we expect:

```python
import math
import pytest

def test_sqrt_2_squared_is_not_exact():
    assert math.sqrt(2) ** 2 != 2  # it's 2.0000000000000004

def test_sqrt_2_squared_is_approximately_2():
    assert math.sqrt(2) ** 2 == pytest.approx(2)
```

### Adding Columns: `add_column`

In a fantasy game, a table holds the items near the player, with coordinates
measured from the player, who is at the origin:

```python
ITEMS = table(
    ["item", "x-coordinate", "y-coordinate"],
    [
        ["Sword of Dawn",           23,  -87],
        ["Healing Potion",         -45,   12],
        ["Dragon Shield",           78,  -56],
        ["Magic Staff",             -9,   64],
        ["Elixir of Strength",      51,  -33],
        ["Cloak of Invisibility",  -66,    5],
        ["Ring of Fire",            38,  -92],
        ["Boots of Swiftness",     -17,   49],
        ["Amulet of Protection",    82,  -74],
        ["Orb of Wisdom",          -29,  -21],
    ],
)
```

The player can only pick up items that are close, so we want each item's
distance. **`add_column`** copies a table with a new column at the right end,
given the column's name and a function from a row to the column's value, which
it calls on every row:

```python
def calc_distance(r: dict) -> float:
    """the distance from the player to the item in row r"""
    return math.sqrt(r["x-coordinate"] ** 2 + r["y-coordinate"] ** 2)

def test_calc_distance_row_0():
    assert calc_distance(ITEMS.row(0)) == pytest.approx(math.sqrt(23 ** 2 + (-87) ** 2))

def test_calc_distance_row_3():
    assert calc_distance(ITEMS.row(3)) == pytest.approx(math.sqrt((-9) ** 2 + 64 ** 2))

ITEMS_WITH_DIST = ITEMS.add_column("distance", calc_distance)
```

- The helper takes the whole row, not `calc_distance(23, -87)`, so `add_column`
  can call it on each row, rather than our calling it ten times.
- `ITEMS_WITH_DIST` has four columns, and `add_column` called `calc_distance`
  ten times, once per row. The tests use `pytest.approx`, since a square root is
  rarely exact.
- This is the second shape of the **table template**: an answer with a _new
  column_ is an `add_column`. Its helper's template is the row template from
  [Class 8](/class/8), with a line for each column: `r["item"]`,
  `r["x-coordinate"]`, and `r["y-coordinate"]`.

### Changing a Column: `transform_column`

**`transform_column`** is given an existing column's name, and a function from a
value in that column to its new value. When the player takes a step in the
increasing x direction, every item's x-coordinate is 1 smaller:

```python
def subtract_1(n: float) -> float:
    """subtracts 1 from n"""
    return n - 1

def test_subtract_1_from_10():
    assert subtract_1(10) == 9

def test_subtract_1_from_0():
    assert subtract_1(0) == -1

def test_subtract_1_from_a_negative():
    assert subtract_1(-3.5) == -4.5

MOVED_ITEMS = ITEMS.transform_column("x-coordinate", subtract_1)
```

- Like all table operations, it makes a _new_ table, leaving the original intact:
  `MOVED_ITEMS.row(1)["x-coordinate"]` is `-46`, but
  `ITEMS.row(1)["x-coordinate"]` is still `-45`. So a mistake can't lose the
  original. Name the new table you want.
- `subtract_1`'s tests don't need `pytest.approx`: subtracting 1 from these
  numbers is exact.

A function on tables can be designed around one of these. A store takes 20% off
every price under 100:

```python
PRICES = table(
    ["item", "price"],
    [
        ["scarf", 50],
        ["boots", 120],
        ["hat", 80],
        ["gloves", 40],
    ],
)

def discount_price(price: float) -> float:
    """reduces price by 20%, if it is below 100"""
    if price < 100:
        return price * 0.8
    else:
        return price

def test_discount_price_under_100():
    assert discount_price(50) == 50 * 0.8

def test_discount_price_at_100():
    assert discount_price(100) == 100

def test_discount_price_over_100():
    assert discount_price(120) == 120

def apply_discounts(t: Table) -> Table:
    """the table t, with 20% off each price below 100"""
    return t.transform_column("price", discount_price)
```

- The type annotation for tables is `Table`.
- `apply_discounts(PRICES)` gives a new table in which the scarf costs `40.0`,
  and the boots still cost `120`.

### The Table Template

`filter` ([Class 8](/class/8)), `add_column`, and `transform_column` are the
three shapes of the **table template**
([templates for tables](/class/recipe#template-tables)). For a function that
makes a new table from a table, ask: does the answer have _fewer rows_, a _new
column_, or a _changed column_? The answer picks the template, and the template
fixes its helper's Signature, so each has its helper as a local function:

```python
def _keep_rows_temp(t: Table) -> Table:
    def keep(r: dict) -> bool:
        ...
        r
        ...
        return ...
    return t.filter(keep)

def _add_column_temp(t: Table) -> Table:
    def compute(r: dict) -> ...:
        ...
        r
        ...
        return ...
    return t.add_column(..., compute)

def _change_column_temp(t: Table) -> Table:
    def change(v: ...) -> ...:
        ...
        v
        ...
        return ...
    return t.transform_column(..., change)
```

- `keep` takes a row and gives a `bool`. `add_column` needs the new column's name
  (the `...`), and `compute`, from a row to the new value. `transform_column`
  needs the column's name, and `change`, from one of its values to the new value.
- Fill in the helper where it is, or design it as a function of its own, with
  its own tests, and pass that, as `calc_distance` and `discount_price` are.
- `calc_distance` takes a row (a `dict`), because a new column's value can use
  any of the row's columns. `discount_price` takes a value (a `float`), because
  a changed column's new value comes from its old one, and nothing else.
- `apply_discounts` is designed in two levels, each with the recipe:
  - `apply_discounts` itself: its input is a table, so its Template is one of
    the three table templates, and its Signature is from `Table` to `Table`. Its
    Examples, for a function that makes a table, are next class. The answer has
    a changed column, `price`, so its Body starts from `_change_column_temp`: a
    `transform_column`, whose `change` goes from a price to a price. It's
    designed as a function of its own, `discount_price`.
  - `discount_price`, the helper, gets the whole recipe on its own: its data is
    a price, split at 100, so the interval template from [Class 5](/class/5)
    (under 100, or not); then a Signature from `float` to `float`, a Docstring,
    Examples (`test_discount_price_under_100`, and its two neighbors), and the
    Body.
- Try: which shape of the table template makes each of these: only the items
  within 50 of the player; a column saying whether each item is within 50;
  every item's name in capitals?

    in latitudes times `KPDLAT`, the east-west distance the difference in
    longitudes times `KPDLON`, and the distance between the points is the
    hypotenuse of a right triangle with those two sides. Its first test is your
    two places, 1 mile apart:


    `pytest.approx(1, abs=0.1)` accepts any number from 0.9 to 1.1, since
    calculations with `float`s are rarely exact.
