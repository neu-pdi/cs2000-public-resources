## Reading (Done Before Class)
### Adding New Columns

Sometimes we want a new column whose values are based on existing columns. For
instance, from this table of employees' hourly wages and hours worked:

```python
employees = table(
    ["name", "hourly-wage", "hours-worked"],
    [
        ["Harley", 15, 40],
        ["Obi", 20, 45],
        ["Anjali", 18, 39],
        ["Miyako", 18, 40],
    ],
)
```

we might want a fourth column, `"total-wage"`, holding `15 * 40`, `20 * 45`,
`18 * 39`, and `18 * 40`. For a computation done several times, we write a
helper function. Try proposing one; perhaps:

```python
def compute_wages(wage: float, hours: float) -> float:
    """compute total wages based on wage and hours worked"""
    return wage * hours
```

which we could use in each row: `["Harley", 15, 40, compute_wages(15, 40)]`.
Better, since the wage and hours are in the same row, it could take the row
itself, but we'd still be calling it in every row! Instead, the table method
`add_column` is given the new column's name, and a function that computes its
value from each row, so we change `compute_wages` to take a row:

```python
def compute_wages(r: dict) -> float:
    """compute total wages based on wage and hours worked"""
    return r["hourly-wage"] * r["hours-worked"]

def test_compute_wages():
    assert compute_wages(employees.row(0)) == 15 * 40
    assert compute_wages(employees.row(2)) == 18 * 39

employees.add_column("total-wage", compute_wages)
```

This copies the table, adding the new column at the right end.

### Calculating New Column Values

Sometimes we just want new values for an existing column. For instance, to give
a 10% raise to everyone making less than 20 an hour:

```python
def new_rate(rate: float) -> float:
    """raise rates under 20 by 10%"""
    if rate < 20:
        return rate * 1.1
    else:
        return rate

def test_new_rate():
    assert new_rate(20) == 20
    assert new_rate(10) == 11
    assert new_rate(0) == 0

def give_raises(t: Table) -> Table:
    """give a 10% raise to anyone making under 20"""
    return t.transform_column("hourly-wage", new_rate)
```

`transform_column` takes the name of an existing column, and a function that
takes a value in that column and returns its new value. Try
`give_raises(employees)`: afterwards, what wage will show for `"Miyako"` in
`employees`? Why?

Like all table operations, `transform_column` produces a new table, leaving the
original intact: if it changed the original, and you made a mistake, how would
you get it back? Making new tables, and naming the one you want, is less
error-prone.

## Recap (15 mins)

- Let's say we were designing a fantasy game, and had a table of items that were
  near the current player.
  ```python
  items = table(
      ["item", "x-coordinate", "y-coordinate"],
      [
          ["Sword of Dawn",           23,  -87],
          ["Healing Potion",         -45,   12],
          ["Dragon Shield",           78,  -56],
          ["Magic Staff",             -9,   64],
          ["Elixir of Strength",      51,  -33],
          ["Cloak of Invisibility",  -66,    5],
          ["Ring of Fire",            38,  -92],
          ["Boots of Swiftness",     -17,   49],
          ["Amulet of Protection",    82,  -74],
          ["Orb of Wisdom",          -29,  -21],
      ],
  )
  ```
- If we wanted to know the distance from the player to each item because, for
  example, if the distance were below a certain amount the player was able to
  pick the item up, we might want to add a new column, to create a table with
  four columns. We can do this using `add_column`.
- First, we need a function that takes a row and calculates the value for the
  new column. This function will be called once for _every row in the table_. But since the numbers we are producing are usually not exact,
  we need to use a different comparison for our tests, `pytest.approx`, which checks that a number is _very close_ to what we expect, rather than exactly equal. If you recall from [Class 1](/class/1), `float`s can only represent most numbers approximately. Since square root may return a number that cannot be represented exactly (the square root of 2 is a good example!), `math.sqrt` produces a `float`, which may be very slightly off from the true answer.
- Both `pytest` and `math` are _libraries_: collections of extra functions that we have to `import` at the top of our file (after the `#level` line) before we can use them. We'll talk more about libraries on [Class 13](/class/13). `**` is the exponentiation operator, so `n ** 2` is `n` squared.
  ```python
  import math
  import pytest

  def calc_distance(r: dict) -> float:
      """finds distance to origin from fields 'x-coordinate' and 'y-coordinate'"""
      return math.sqrt(r["x-coordinate"]**2 + r["y-coordinate"]**2)

  def test_calc_distance():
      assert calc_distance(items.row(0)) == pytest.approx(math.sqrt(23**2 + (-87)**2))
      assert calc_distance(items.row(3)) == pytest.approx(math.sqrt((-9)**2 + 64**2))
  ```
- Now we can add a column to create a new table:
  ```python
  items_with_dist = items.add_column("distance", calc_distance)
  ```
- Let's say, instead, we wanted to move the player one unit of distance in the increasing
  `x` direction. This would mean that the origin shifts by 1, and so the
  `x-coordinate` field in the table should have 1 subtracted from it, since
  items that were to the right are now closer, and the left ones (the negative
  coordinates) are now further.
- We can do this by using `transform_column`, which takes a function that
  transforms a single column, here the value of the `x-coordinate`. So let's
  write one:
  ```python
  def subtract_1(n: float) -> float:
      """subtracts 1 from input"""
      return n - 1

  def test_subtract_1():
      assert subtract_1(10) == 9
      assert subtract_1(0) == -1
      assert subtract_1(-3.5) == -4.5
  ```
- Now we can construct a shifted table:
  ```python
  moved_items = items.transform_column("x-coordinate", subtract_1)
  ```

## Class Exercise (40 mins)

1. Imagine all the items were pulled closer to the player by scaling both the x and y coordinates down by 10% (this doesn't make the distance 10% less, but is simpler). Create a new table that has
   new x & y coordinates for all the items.
2. Extract the name of the item that is closest to the player.
3. You want to "obfuscate" the list of items, displaying, rather than the name, a
   string that is a sequence of "X"s of the same length. i.e., "Sword of Dawn"
   becomes `"XXXXXXXXXXXXX"`. Create a new table that is so transformed.
4. Get a dataset from the [City of Boston Employee Earnings Report](https://data.boston.gov/dataset/employee-earnings-report), and load it via the CSV url.
5. Calculate the total earnings _excluding_ the "DETAIL" column, since that is _private_
   compensation (police & fire employees hired for private events). You might notice, in doing this, that the columns are not numbers, they are strings! With commas! Furthermore, some of the data has no values for certain rows which are loaded as empty strings `""`. That means `float` by itself won't work: it causes an error for strings like `"1,234"` or `""`. For now you can use `transform_column` with this helper (you don't need to understand how `try` and `except` work yet: `float` causes an error, called a `ValueError`, when given a string that isn't a number, and `try` / `except ValueError` means "if that error happens, do this instead"):
   ```python
   def earnings_to_number(s: str) -> float:
       """Converts a possibly comma-formatted earnings string to a number, using 0 if empty or invalid"""
       try:
           return float(s.replace(",", ""))
       except ValueError:
           return 0

   def test_earnings_to_number():
       assert earnings_to_number("1234") == 1234
       assert earnings_to_number("1,234") == 1234
       assert earnings_to_number("-1.3") == -1.3
       assert earnings_to_number("hello") == 0
   ```
6. Now sort by your new total compensation to see the highest paid employees in
   the city. Sort the other way to see who is the lowest paid.

## Wrap-up (5 mins)

- Transforming data is key to programming with tables. The original source of
  data may not have what you need in the right format, but we can use operations
  like `add_column` or `transform_column` to create new tables that do.
