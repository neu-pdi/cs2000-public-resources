## Notes (review before class)
### Updating Variables

At `#level advanced`, `=` can give any variable a new value, even at the top
level of the file (outside any function), and functions can use `global`. Here
is a game's score, added up over its rounds at the top level, as a
[Class 16](/class/16) loop would inside a function:

```python
#level advanced

score = 0
for points in [3, 0, 4]:
    score = score + points
```

- Basic data (numbers, strings, booleans) have no internal structure, so they are
  stored right in the directory. (Structured data, like lists, are stored in a
  separate place, the **heap**: [Class 26](/class/26).)
- `=` on a name that already has a value **updates** its directory entry.
- A `for` loop adds its name (`points`) to the directory, and updates it to each
  element in turn.

The directory as it runs (each column is one moment):

| | after `score = 0` | loop starts | after `score = score + points` | next element | ... | loop ends |
| -- | -- | -- | -- | -- | -- | -- |
| `score` | `0` | `0` | `3` | `3` | ... | `7` |
| `points` | | `3` | `3` | `0` | ... | `4` |

Try drawing the directory as this runs:

```python
misses = 0
shots = ["hit", "miss", "miss", "hit"]
for shot in shots:
    if shot == "miss":
        misses = misses + 1
```

### Local and Global Variables

Names defined at the top level are in the **global** directory; each function
call has its own **local** directory ([Class 5](/class/5)).

```python
y = 20
z = 100

def f() -> int:
    y = 30      # a new local y: the global y is unchanged
    return y

def g() -> None:
    global z    # in g, z means the global z
    z = 200

print(f())      # 30
print(y)        # 20
g()
print(z)        # 200
```

- Assigning to a name inside a function creates a **local** variable, even if a
  global one has the same name: in the function, the name means the local one
  (it **shadows** the global one), and the global one is unchanged.
- `global z`, at the start of a function, makes `z` there mean the global `z`, so
  assigning to it changes the global entry (as on [Class 18](/class/18)).

### Whose Variable?

A game keeps track of the best score so far, and of the last score:

```python
best = 0
last = 0

def game_score(rounds: list[int]) -> int:
    """the total points scored over the rounds of one game"""
    score = 0
    for points in rounds:
        score = score + points
    return score

def test_game_score():
    assert game_score([]) == 0
    assert game_score([3, 0, 4]) == 7

def record(score: int) -> None:
    """records score as the last score, and as the best score if it is higher"""
    global best
    last = score
    if score > best:
        best = score

record(game_score([5, 6]))
record(game_score([2, 2]))
print(best, last)
score = 50
print(game_score([1]), score)
```

- The first `print` shows `11 0`: `record`'s `global best` makes its `best`
  the global one, but `last = score` makes a new, local `last`, gone when the
  call returns. With `global last` too, it would show `11 4`.
- The second shows `1 50`: `game_score`'s `score` is local to each call, so the
  global `score` is a different variable. Just before `game_score([5, 6])`
  returns, its local directory has `score` as `11` and `points` as `6`.
- `game_score` has Examples, but `record` doesn't: an example would have to say
  what the global directory holds before and after a call, and the Docstring
  can't say what a call does without knowing every call before it. That's the
  problem with `global` from [Class 18](/class/18).
