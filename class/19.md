## Notes (review before class)
### Structured Data

- Some data has several _attributes_ that belong together: a song has a name,
  singer, and year; an email has a sender, subject, and body.
- **Structured data**: a single datum made of a _fixed_ number of parts, called
  **fields**, which can have different types (and can themselves be structured: a
  date has a day, month, and year).

### Defining Structured Data

Until now, the recipe's **Data definition** step was in words: "a number of
tickets", "a row with `month` and `riders` columns". From today it is code, and
it comes before any function on the data:

<DesignRecipe focus="Data definition, Template" />

A **dataclass** defines a new type, with a type annotation for each field
(PLL gives every file `dataclass`; in plain Python, the file must have
`from dataclasses import dataclass` near the top):

```python
@dataclass
class SpotifySong:
    name: str
    singer: str
    year: int
```

- The names of types we define start with a capital letter.
- `SpotifySong` is also a **constructor**: a function that takes a value for each
  field, in order, and returns a new `SpotifySong`.
- Always follow a data definition with a few named examples, which the
  Examples step of every function on the data uses again:

```python
lver = SpotifySong("La Vie en Rose", "Édith Piaf", 1945)
so = SpotifySong("Stressed Out", "twenty one pilots", 2015)
wnkkhs = SpotifySong("Waqt Ne Kiya Kya Haseen Sitam", "Geeta Dutt", 1959)
```

- In the directory, each example is a name for an `SpotifySong` value, like any other.
- The new type can be used in annotations: `lver: SpotifySong = SpotifySong(...)`.
  (Try annotating it as `str` instead, to see the error.)

### Field Access

`s.year` is the `year` field of `s`. A function on songs, with the recipe:

- **Data definition**: `SpotifySong`, and its examples, above.
- **Signature** and **Docstring**:

```python
def song_age(s: SpotifySong) -> int:
    """returns how many years old the song is"""
    ...
```

- **Examples**: tests, with the data definition's examples as inputs:

```python
def test_song_age():
    assert song_age(lver) == 81
    assert song_age(so) == 11
    assert song_age(wnkkhs) == 67
```

- **Template**: a dataclass's parts are its fields, so the template lists them
  ([templates for structured data](/class/recipe#template-fields)), as the row
  template listed a row's columns ([Class 8](/class/8)):

```python
# def song_age(s: SpotifySong) -> int:
#     ... s.name ... s.singer ... s.year ...
```

- **Body**: the age only needs the year:

```python
def song_age(s: SpotifySong) -> int:
    """returns how many years old the song is"""
    return 2026 - s.year
```

## Recap (10 mins)

A library program keeps a record of each book: its title, author, and number of
pages. Read through the program:

```python
@dataclass
class BookRecord:
    title: str
    author: str
    pages: int

the_dispossessed = BookRecord("The Dispossessed", "Ursula K. Le Guin", 387)
to_the_lighthouse = BookRecord("To the Lighthouse", "Virginia Woolf", 209)
brave_new_world = BookRecord("Brave New World", "Aldous Huxley", 268)

def pages_left(b: BookRecord, pages_read: int) -> int:
    """how many pages of b are left to read, after reading pages_read of them"""
    return b.pages - pages_read

def test_pages_left():
    assert pages_left(the_dispossessed, 0) == 387
    assert pages_left(to_the_lighthouse, 9) == 200
```

- What is `brave_new_world.author`? What is `pages_left(brave_new_world, 68)`?
- What would `BookRecord("Brave New World", 268, "Aldous Huxley")` do? Why?
- If the library also recorded the year each book was published, which lines would change?
- Which fields does `pages_left`'s template list? Which does its body use? Where
  did its examples' inputs come from?

## Wrap-up (5 mins)

- Structured data groups multiple fields together.
- We define structured types using `@dataclass` and `class`, and create instances by calling the constructor.
- Fields are accessed with the dot notation.
- Template of the day: [structured data](/class/recipe#template-fields): the
  template lists the fields, as a row's template lists its columns.
