## Notes (review before class)
### Lists: First and Rest

- Every non-empty list has a **first** element and a **rest**, which is itself a
  list. A cart's orders, as numbers of boxes, `[2, 4, 1]`, have first `2` and
  rest `[4, 1]`; that has first `4` and rest `[1]`; that has first `1` and rest
  `[]`, the **empty list**.
- So lists are **structured data**: parts in a fixed format, which programs can
  follow. (Tables are less so: every table has its own column names.)

### Accessors and Constructors

**Accessors** take structured data apart, by its structure alone, whatever it
holds: `lst[0]` is the first element, and `lst[1:]` is the rest (a _slice_ from
position `1` to the end, as with strings in [Class 11](/class/11)):

```python
three_orders = [2, 4, 1]

def test_first_and_rest():
    assert three_orders[0] == 2
    assert three_orders[1:] == [4, 1]
    assert three_orders[1:][0] == 4
    assert three_orders[1:][1:] == [1]
    assert three_orders[1:][1:][1:] == []
```

**Constructors** build structured data. Putting a one-element list, holding the
first element, in front of the rest builds the same list:

```python
def test_building_lists():
    assert [2, 4, 1] == [2] + ([4] + ([1] + []))
```

- It's long, and harder for people to read, but it shows the structure that
  programs use. A list is either:
  - **empty**, written `[]`, or
  - **non-empty**, written `[f] + r` (or with at least one value between the
    brackets): a first `f`, and a rest `r` that is _also a list_ (so it is empty
    or non-empty, ...).
- So lists are conditional data (as in [Class 21](/class/21)).
- Try: write `["cookies", "brownies", "lemon bars"]` this way.

### Examples over a List and Its Suffixes

- `len` and `sum` are built in, so let's write our own, for orders:
  `count_orders` (how many orders there are) and `total_boxes` (how many boxes,
  in all). One strategy works for both.
- Always write at least two examples, one with `[]` and one non-empty; then more
  for the problem, and more to show how you think about solving it.
- Use a list and each of its **suffixes**, lined up. (A suffix is what's left
  after taking elements off the front: `[1]` is a suffix of `[2, 4, 1]`, the
  rest of its rest, but `[2]` is not.)

# (written below)
def count_orders(orders: list[int]) -> int:

```python
def test_count_orders():
    assert count_orders([2, 4, 1]) == 3  # 1 + 2
    assert count_orders([   4, 1]) == 2  # 1 + 1
    assert count_orders([      1]) == 1  # 1 + 0
    assert count_orders([       ]) == 0
```

Each answer is `1` (for the first order) plus the count of the rest, which is
the answer on the next line. Replace those counts with the calls that produce
them:

```python
def test_count_orders():
    assert count_orders([2, 4, 1]) == 1 + count_orders([4, 1])
    assert count_orders([   4, 1]) == 1 + count_orders([   1])
    assert count_orders([      1]) == 1 + count_orders([    ])
    assert count_orders([       ]) == 0
```

The same for `total_boxes`: `total_boxes([2, 4, 1])` is `2 + 4 + 1`, which is
`2 + total_boxes([4, 1])`:

```python
def test_total_boxes():
    assert total_boxes([2, 4, 1]) == 2 + total_boxes([4, 1])
    assert total_boxes([   4, 1]) == 4 + total_boxes([   1])
    assert total_boxes([      1]) == 1 + total_boxes([    ])
```

- The last line forces `total_boxes([])` to be `0`: adding `0` to a number
  leaves it unchanged, so the total of no orders must be `0`.
- In both, the answer for a list uses the function's answer for its rest.
- Try: `count_orders([2, 4, 1])` is `3`, and `1 + 2`, and
  `1 + count_orders([4, 1])`, and `1 + count_orders([2, 4, 1][1:])`. Check that
  each follows from the one before it.

### From Examples to Code: `match` on Lists

Written with `[1:]`, each non-empty example has the same shape,
`count_orders(some_list) == 1 + count_orders(some_list[1:])`; only the empty
one differs. To run different code for the two kinds of lists, use `match`:

```python skip
match e:
    case []:
        ...
    case [f, *r]:
        ...  # can use f and r here
```

- Python evaluates `e` (any expression whose value is a list), then:
  - if it is empty, runs the code under `case []:`;
  - otherwise, adds `f` (the first) and `r` (the rest) to the program directory,
    and runs the code under `case [f, *r]:`.
- The `*` makes `r` the list of _all_ the remaining elements, not a single one.
- Any names will do, and names that fit the problem help: for orders, `boxes`
  (the first order's) and `others`.

Each `case` comes straight from the examples:

```python
def count_orders(orders: list[int]) -> int:
    """the number of orders in orders"""
    match orders:
        case []:
            return 0
        case [boxes, *others]:
            return 1 + count_orders(others)

def total_boxes(orders: list[int]) -> int:
    """the total number of boxes in orders"""
    match orders:
        case []:
            return 0
        case [boxes, *others]:
            return boxes + total_boxes(others)
```

- `others` is already the rest of `orders`, so there's no `[1:]`.
- The two are nearly the same: the structure of the data suggests the structure
  of the program.
- `count_orders(others)` is trusted to do what its Docstring says, the number of
  orders in `others`, just as the examples said. Reading the body that way, as
  "1, plus the number of the other orders", is all it takes to see that it's
  right; there's no need to follow the calls one inside another.
- `orders: list[int]` makes an argument that isn't a list, like
  `count_orders(5)`, an error.

### A Choice in the Body

We want to add up the numbers in a list, up to the first `0` (or all of them,
if there is no `0`). Here are its examples, for a list and each of its
suffixes, rewritten in terms of first and rest, and the function they lead to:

```python
def add_till_zero(lst: list[float]) -> float:
    """adds up the numbers in lst, up to the first 0 (or all, if there is no 0)"""
    match lst:
        case []:
            return 0
        case [f, *r]:
            if f == 0:
                return 0
            else:
                return f + add_till_zero(r)

def test_add_till_zero():
    assert add_till_zero([7, 3, 0, 5]) == 7 + add_till_zero([3, 0, 5])
    assert add_till_zero([   3, 0, 5]) == 3 + add_till_zero([   0, 5])
    assert add_till_zero([      0, 5]) == 0
    assert add_till_zero([         5]) == 5 + add_till_zero([       ])
    assert add_till_zero([          ]) == 0
```

- One example is different: `add_till_zero([0, 5])` is `0`, not `0 +` anything.
  That example is the reason for the `if f == 0:`: the non-empty case has two
  cases of its own, decided by the first element.
- Try: write each test's right side as a plain number, starting from the
  bottom, using each line's answer in the one above it. What is
  `add_till_zero([7, 3, 0, 5])`? Which lines are the same as in `total_boxes`,
  and which came from this function's own examples?

### Strategy: Developing Functions Over Lists

This strategy is the recipe's **Examples** and **Body** steps, for a list. The
Signature and Docstring come before them, as always (and the Template for a
list, which comes before those, is next class):

<DesignRecipe focus="Examples, Body" />

1. **Examples**: choose a list with at least three elements, and write an
   example for it and for each of its suffixes, down to `[]`.
2. Write each answer using the first element and the answer for the rest,
   which is the next line's answer. (Seeing the first and rest values is
   enough; `[0]` and `[1:]` needn't be written.)
3. **Body**: turn the pattern you see into a `match`, with a `case` for the
   empty list and one for the rest, each from its examples.

The same strategy works for any structured data, with its own parts in place
of first and rest.

Every function today has the same shape: a `case []`, and a
`case [f, *r]` whose answer uses `f` and the function's own answer on `r`. That
shape is the **template** for a list
([templates for recursive data](/class/recipe#template-recursive)). Next class,
it comes straight from the data definition, before any examples, by the rule
behind every template so far: one part of the body for each part of the data.
