### Data Design Problem: Ancestry Data

Imagine managing ancestry information for a medical research study: people's
birthyears, eye colors, and genetic parents. Here's a sample table, with one row
per person (`""` is an unknown parent):

```python
ancestors = table(
    ["name", "birthyear", "eyecolor", "female-parent", "male-parent"],
    [
        ["Anna", 1997, "blue", "Susan", "Charlie"],
        ["Susan", 1971, "blue", "Ellen", "Bill"],
        ["Charlie", 1972, "green", "", ""],
        ["Ellen", 1945, "brown", "Laura", "John"],
        ["Bill", 1946, "blue", "", ""],
        ["John", 1922, "brown", "", "Robert"],
        ["Laura", 1922, "brown", "", ""],
        ["Robert", 1895, "blue", "", ""],
    ],
)
```

We want to answer questions such as: Who are a person's genetic grandparents?
How frequent is each eye color? Is one person an ancestor of another? How many
generations do we have information for?

Try: how would you compute a list of a person's known grandparents? (Assume
names are unique, and make a task plan.) Our plan: find the person's parents,
then each of their parents. Both steps compute the known parents from a name,
so we make a helper for that, `parents_of`.

#### Computing Genetic Parents from an Ancestry Table

To find someone's parents, we filter the table to find the person, extract the
names of the female and male parents, and make a list of them:

```python
def parents_of(anc_table: Table, who: str) -> list[str]:
    """returns a list of the names of the known parents of who"""
    matches = anc_table.filter(lambda r: r["name"] == who)
    if matches.length() > 0:
        person_row = matches.row(0)
        return [person_row["female-parent"], person_row["male-parent"]]
    else:
        return []

def test_parents_of():
    assert parents_of(ancestors, "Anna") == ["Susan", "Charlie"]
    assert parents_of(ancestors, "Paws") == []
```

Try: are you satisfied with this program, and its tests? There are arguably
some issues:

- The tests are weak: none consider people missing a parent.
- For an unknown parent, the list includes `""`, which isn't a name, and could
  cause problems in a later computation (such as finding grandparents).
- Without the `""`s, `"Robert"` (who is in the table) would get the same result
  as `"Paws"` (who is not): fundamentally different cases, which arguably
  demand different outputs.

To fix these, we remove the `""`s, and, since any list we return for a missing
name could be confused with a valid list of names, we cause an error instead:
`raise ValueError("No such person " + who)` stops the program with a
`ValueError` (the kind `float` causes for a string that isn't a number) and our
message. In a test, `with pytest.raises(ValueError):` checks that the code under
it causes that error (see [Tests](/pll/testing)):

```python
import pytest

def parents_of(anc_table: Table, who: str) -> list[str]:
    """returns a list of the names of the known parents of who"""
    matches = anc_table.filter(lambda r: r["name"] == who)
    if matches.length() > 0:
        person_row = matches.row(0)
        names = [person_row["female-parent"], person_row["male-parent"]]
        return list(filter(lambda n: n != "", names))
    else:
        raise ValueError("No such person " + who)

def test_parents_of():
    assert parents_of(ancestors, "Anna") == ["Susan", "Charlie"]
    assert parents_of(ancestors, "John") == ["Robert"]
    assert parents_of(ancestors, "Robert") == []
    with pytest.raises(ValueError):
        parents_of(ancestors, "Paws")
```

#### Computing Grandparents from an Ancestry Table

Grandparents are the parents of the parents, so, with
`plist = parents_of(anc_table, who)`, we could return
`parents_of(anc_table, plist[0]) + parents_of(anc_table, plist[1])`. Try: for
which people in the table would that work? Only for those with both parents in
the table: otherwise `plist` has fewer than two names, and `plist[1]` (if not
`plist[0]`) causes an error. So we check the number of parents first:

```python
def grandparents_of(anc_table: Table, who: str) -> list[str]:
    """returns a list of the known grandparents of who in the table"""
    plist = parents_of(anc_table, who)
    if len(plist) == 2:
        return parents_of(anc_table, plist[0]) + parents_of(anc_table, plist[1])
    elif len(plist) == 1:
        return parents_of(anc_table, plist[0])
    else:
        return []

def test_grandparents_of():
    assert grandparents_of(ancestors, "Anna") == ["Ellen", "Bill"]
    assert grandparents_of(ancestors, "Laura") == []
    assert grandparents_of(ancestors, "John") == []
    with pytest.raises(ValueError):
        grandparents_of(ancestors, "Paws")
```

Finding all of someone's ancestors would need recursion (we don't know how many
generations there are), and be expensive, filtering the whole table over and
over. But in a family tree picture, with a line from each person to each
parent, we just follow a line from a person to their mother or father. A data
definition can do the same.

#### Creating a Datatype for Ancestor Trees

A person has a name, birthyear, eye color, mother, and father, suggesting a
dataclass `Person` that turns a row into a person value. But what type should
`mother` and `father` have: `str`, `Person`, `list[Person]`, a new datatype?
With `str`, we're back to the table row, with no easy way to get from one person
to another; a parent is a person too, so we use `"Person"` (in quotes, as on
[Class 21](/class/21)).

Try writing Anna's tree with that definition. Did you get stuck? When we run out
of known people, we need an option for people we know nothing about, making an
ancestor tree conditional data:

```python
from dataclasses import dataclass

@dataclass
class NoInfo:
    pass

@dataclass
class Person:
    name: str
    birthyear: int
    eye: str
    mother: "AncTree"
    father: "AncTree"

AncTree = NoInfo | Person
```

Here's Anna's tree:

```python
anna_tree = Person("Anna", 1997, "blue",
                   Person("Susan", 1971, "blue",
                          Person("Ellen", 1945, "brown",
                                 Person("Laura", 1922, "brown", NoInfo(), NoInfo()),
                                 Person("John", 1922, "brown",
                                        NoInfo(),
                                        Person("Robert", 1895, "blue", NoInfo(), NoInfo()))),
                          Person("Bill", 1946, "blue", NoInfo(), NoInfo())),
                   Person("Charlie", 1972, "green", NoInfo(), NoInfo()))
```

Naming each person's tree first (e.g., `robert_tree`, then
`john_tree = Person("John", 1922, "brown", NoInfo(), robert_tree)`) would give
pieces to use as other examples, but lose the structure visible in the
indentation. We can also get to pieces by digging into the data:

```python
ellen_tree = anna_tree.mother.mother
```

Here's `parents_of` for an `AncTree` (a bit more complicated if a parent is
`NoInfo()`, which has no `name`):

```python
def parents_of_tree(tr: AncTree) -> list[str]:
    """returns a list of the names of the parents at the root of tr"""
    match tr:
        case NoInfo():
            return []
        case Person(n, y, e, m, f):
            return [m.name, f.name]
```

### Programs to Process Ancestor Trees

How would we determine whether anyone in a tree has a particular name? We start
with the header, `def in_tree(at: AncTree, name: str) -> bool:`, and examples,
checking both variants of `AncTree`:

```python
def test_in_tree():
    assert in_tree(anna_tree, "Anna")
    assert in_tree(anna_tree, "Ellen")
    assert not in_tree(ellen_tree, "Anna")
    assert not in_tree(NoInfo(), "Ellen")
```

What next? As for lists (on [Class 21](/class/21)), we write the _template_, which
names the pieces of each variant, and makes recursive calls on the pieces that
have the same type:

```python
# def in_tree(at: AncTree, name: str) -> bool:
#     match at:
#         case NoInfo():
#             ...
#         case Person(n, y, e, m, f):
#             ... in_tree(m, name) ... in_tree(f, name)
```

Then we fill in the `...`s. A `NoInfo()` tree has no people, so the answer is
`False`. For a `Person`, the name could be this person's, or in the mother's
tree, or in the father's tree. The recursive calls already ask about the
parents' trees, so we combine the three with `or`:

```python
def in_tree(at: AncTree, name: str) -> bool:
    """returns whether name is in the tree"""
    match at:
        case NoInfo():
            return False
        case Person(n, y, e, m, f):
            # n is the same as at.name, and m is the same as at.mother
            return name == n or in_tree(m, name) or in_tree(f, name)
```

## Recap (20 mins)

- Today we introduce **trees**—a way to represent hierarchical data where each item can have sub-items.
- Real-world example: a river network, where streams merge into larger streams and rivers.
- Tables can't easily represent this branching structure—each merge point connects to exactly two upstream sources.
- We can model this as a **binary tree** (which are the simplest form of tree), where each node has two sub nodes. Trees are similar to lists, in that they are conditional data where one case is the end (or base) and the other is a recursive case, but unlike lists, the recursive case has _multiple_ self-referential fields -- below, `left` and `right`.
- River network as conditional data:
  ```python
  from dataclasses import dataclass

  @dataclass
  class Merge:
      width: float
      left: "River"
      right: "River"

  @dataclass
  class Stream:
      flow_rate: float

  River = Merge | Stream

  # Example: A small river network
  stream_a = Stream(5)
  stream_b = Stream(8)
  stream_c = Stream(3)
  merge_1 = Merge(12, stream_a, stream_b)
  main_river = Merge(15, merge_1, stream_c)
  ```
- As with `NumList`s from [Class 21](/class/21), we can also come up with a template for designing functions with `River`s:
  ```python
  # def river_fun(r: River) -> ...:
  #     match r:
  #         case Merge(width, left, right):
  #             ... width ...
  #             ... river_fun(left) ...
  #             ... river_fun(right) ...
  #         case Stream(flow):
  #             ... flow ...
  ```
- Example function: calculate total flow in a river network
  ```python
  def total_flow(r: River) -> float:
      match r:
          case Merge(width, left, right):
              return total_flow(left) + total_flow(right)
          case Stream(flow):
              return flow

  def test_total_flow():
      assert total_flow(stream_a) == 5
      assert total_flow(main_river) == 16
  ```
- Example function: count merge points in a river network
  ```python
  def count_merges(r: River) -> int:
      match r:
          case Merge(width, left, right):
              return 1 + count_merges(left) + count_merges(right)
          case Stream(flow):
              return 0

  def test_count_merges():
      assert count_merges(stream_a) == 0
      assert count_merges(main_river) == 2
  ```

## Wrap-up (5 mins)

- Binary trees naturally represent branching structures like river networks.
- Recursive data definitions with multiple variants capture tree structure.
- Recursive functions use `match` to handle each variant appropriately.
- Tree processing often follows patterns: reductions (sum, count) and transformations (map-like operations).
