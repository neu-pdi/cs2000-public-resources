### Computing New Columns

Lifting computes a whole column at once. If every box cost \$9, each order's
price before discounts would be:

```python
BOX_PRICE = 9.0
bake["total"] = bake["boxes"] * BOX_PRICE
```

A mask and `.loc` update just some rows, e.g. 10% off with the `"bake10"` code:

```python
bake10_mask = bake["code"] == "bake10"
bake.loc[bake10_mask, "total"] = bake["total"] * 0.90
```

- The same notation adds a column or updates one (unlike PLL's `add_column`
  and `transform_column`): pandas creates the column if there is none by that
  name.

### Applying a Function

When lifting isn't enough, **`apply`** calls a function (a `lambda` or a named
one) on each value of a Series, or, with `axis=1`, on each row of a DataFrame:

```python
bake["valid_email"] = bake["email"].apply(lambda e: "@" in e)
bake["contact"] = bake.apply(lambda r: r["name"] + " <" + r["email"] + ">", axis=1)
```

- A Series' `apply` passes single values, like `transform_column`.
- With `axis=1`, the function gets a whole row, so a column can be computed (or
  recomputed) from several of its cells, which `transform_column` can't do.
- So, as for PLL's table template, which job it is decides the helper's
  Signature: a value for a Series' `apply`, a row for `axis=1`. A named helper
  gets the whole recipe.

The boxes actually have different prices, by item. A row's price needs two of
its cells, so it's an `axis=1` helper, designed with the same recipe as PLL
table functions (the recipe doesn't depend on the library):

<DesignRecipe />

- **Data definition**: a row of `bake`, a `pd.Series`, with `name`, `email`,
  `boxes`, `item`, `code`, `delivery`, and `zip`.
- **Template**: the row template, with a line for each column it can use.
- **Signature** and **Docstring**: from a `pd.Series` to a `float`, the order's
  price.
- **Examples**: tests on rows of `first_orders`, with prices worked out by
  hand.
- **Body**: the price needs only `boxes` and `item`, so the other lines go.

```python
PRICES = {"cookies": 8.0, "brownies": 10.0, "lemon bars": 12.0}

def order_total(r: pd.Series) -> float:
    """the price of order r: its boxes times its item's price"""
    return r["boxes"] * PRICES[r["item"]]

def test_order_total():
    assert order_total(first_orders.iloc[0]) == 16.0   # 2 boxes of cookies
    assert order_total(first_orders.iloc[2]) == 48.0   # 4 boxes of lemon bars

# PLL: bake.add_column("total", order_total), but this replaces the column
bake["total"] = bake.apply(order_total, axis=1)
```

- Why does `bake.apply(order_total, axis=1)` need `axis=1`, while
  `bake["email"].apply(...)` doesn't? Which of these two `apply`s could be
  written with lifting instead?

A function whose answer has fewer rows is the `filter` shape of the table
template, done the pandas way, with a mask:

```python
def delivery_only(t: pd.DataFrame) -> pd.DataFrame:
    """the delivery orders in t"""
    # PLL: t.filter(lambda r: r["delivery"] == "delivery")
    return t[t["delivery"] == "delivery"]

def test_delivery_only():
    assert len(delivery_only(first_orders)) == 2
    assert delivery_only(first_orders).iloc[0]["name"] == "Marcus Bell"
```

- It's tested on `first_orders`, not `bake`: `bake` has changed several times
  since it was loaded, and still has `Delivery` and `delivry`.

### Sorting

```python
bake.sort_values("boxes")                   # fewest boxes first
by_boxes = bake.sort_values("boxes", ascending=False)  # most boxes first
```

- Like PLL's `order_by`: it makes a new DataFrame (`bake` doesn't change), in
  which each row keeps its label.
- So `by_boxes.iloc[0]["name"]` is `"Kiran"`, the first row by position, but
  `by_boxes.loc[0]["name"]` is `"Priya Raman"`, the row labeled 0.

### Aggregating and Grouping

```python
bake["boxes"].sum()    # total number of boxes ordered: 35
bake["boxes"].mean()   # average number of boxes per order: 3.5
```

To summarize one column for each value of another (a spreadsheet's "pivot
table"), use **`groupby`**, rather than filtering to each value and summing:

```python
bake.groupby("code").count()            # how many orders had each code
bake.groupby("code")["boxes"].sum()     # boxes ordered with each code
bake.groupby("item")["total"].sum()     # each item's sales, in dollars
```

- `groupby` takes the column whose values group the rows, and returns a
  `GroupBy`: select a column of it, and an operation on it is done per group.
- The second line is a Series labeled by promo code: 21 boxes with no code
  (`""`), 8 with `"bake10"`, 6 with `"friend"`. The third: brownies \$60,
  cookies \$136, lemon bars \$144.
- The pandas documentation lists many more `GroupBy` operations (means, other
  statistics, ...).
