## Notes (review before class)
### The Loop Template

To compute with each element of a list, we use the **loop template**
([templates for loops](/class/recipe#template-loops)):

```python
def _list_loop_temp(lst: list) -> ...:
    result = ...  # the answer if the input list is empty
    for item in lst:
        ...
        item
        ...
        result
        ...
        result = ...  # item, combined with the result so far
    return result
```

It is filled in in three usual ways:

- **combining** the elements into one value: a sum, a product, a count;
- **building** a new list, element by element: the loop version of `map`, or of
  `filter` (with an `if`);
- **checking** something about the elements: whether any is negative, whether
  all are short.

### Variables That Can Change

Until now, a name in the directory could never be defined again:

```python error
score = 10
# ...
score = 20  # PLL reports a reassignment, and doesn't run the file
```

- Python allows it, but PLL's `beginner` level ([Class 3](/class/3)) doesn't:
  it is a common cause of bugs.
- At `#level intermediate` (from now on, the first line of our files), a
  variable defined _inside a function_ can be changed (**mutated**) with `=`
  again: its name then points to the new value in the directory.
- At the top level of the file, it is still reported (why:
  [Class 18](/class/18)).

### How `for` Works

- A **`for` loop** runs its **body** (the lines indented under it) once per
  element of the list, in order, each time naming the element in the
  directory (here, `minutes`).
- The loop produces no value; it computes by changing variables.
- A list of numbers has type `list[float]`; of strings, `list[str]`.

`total_minutes`, the total time of a week's practice sessions, designed with the
recipe:

<DesignRecipe focus="Template" />

- **Data definition**: a list of session lengths, in minutes, a `list[float]`.
- **Template**: the loop template, `_list_loop_temp`, above.
- **Signature** and **Docstring**:

```python
def total_minutes(sessions: list[float]) -> float:
    """the total length, in minutes, of the practice sessions"""
    ...
```

- **Examples**: one test, for now (the Try after the Body asks for another):

```python
def test_total_minutes():
    assert total_minutes([25, 40, 15, 30]) == 110
```

- **Body**: copy the template's body into `total_minutes`. It's the combining
  filling: `result` is the total so far, so we name it `total`, and the
  template's `item` is a session's `minutes`. The first `...` starts the total,
  and the last adds `minutes` to the total so far; the lines that only name
  `minutes` and `total`, and the `...`s around them, go:

```python
def total_minutes(sessions: list[float]) -> float:
    """the total length, in minutes, of the practice sessions"""
    total = 0
    for minutes in sessions:
        total = total + minutes
    return total
```

On `[25, 40, 15, 30]`, the body runs four times, as if `total_minutes`'s body
were:

```python skip
    total = 0
    total = total + 25
    total = total + 40
    total = total + 15
    total = total + 30
    return total
```

The loop writes this repetition for us, for a list of any length.

Try: what should `total_minutes([])` be, and which line decides it? Add a test.

The building filling makes a list, one element at a time: the loop version of
`filter` (with an `if`), or of `map`. The sessions of 30 minutes or more:

```python
def long_sessions(sessions: list[float]) -> list[float]:
    """the sessions of 30 minutes or more, in order"""
    result = []
    for minutes in sessions:
        if minutes >= 30:
            result = result + [minutes]
    return result

def test_long_sessions():
    assert long_sessions([]) == []
    assert long_sessions([25, 40, 15, 30]) == [40, 30]
```

- `result` starts as the empty list, the answer for an empty input.
- `result + [minutes]` is a new list, with `minutes` after the elements of
  `result`; `=` then points `result` at it. Without the `if`, this would copy
  the list, and with `minutes / 60` in place of `minutes`, it would be a `map`.

<Aside title="When Indentation Changes the Answer">

As [Class 5](/class/5) warned, indentation mistakes don't always announce
themselves; now, indentation can decide _how many times_ a line runs:

```python error
def total_minutes(sessions: list[float]) -> float:
    """the total length, in minutes, of the practice sessions"""
    total = 0
    for minutes in sessions:
        total = total + minutes
        return total
```

- With `return` in the loop, it runs on the _first_ trip:
  `total_minutes([25, 40, 15, 30])` is `25`, not `110`. It's not a syntax
  error; only the test catches it, so read the left edge of a loop body
  carefully.
- On `[]`, the body never runs, so the function ends without returning the
  `float` it promised: an error.

</Aside>
