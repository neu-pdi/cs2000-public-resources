### Questions About a Column

So far, table operations have worked _by rows_ and produced tables. But many
questions are basic statistics (maximum, minimum, average, median, ...) over a
_single column_, possibly after filtering rows: the biggest bake-sale order, the
average or most common number of boxes, the most used promo code. Their answers
aren't tables, so they aren't any shape of the
[table template](/class/recipe#template-tables): they **summarize** a column,
into one value.

We'll use a cleaned copy of the bake-sale orders from [Class 11](/class/11) and
[Class 12](/class/12). Copy the contents of https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/python/static/support/bake-sale-cleaned.csv into a new file,
`bake-sale-cleaned.csv`, in your `cs2000-scratch` repository:

```python
cleaned_raw = load_table("bake-sale-cleaned.csv")

```

### Extracting a Column

`select_columns` produces a table, and no table method does these computations:

```python
cleaned_data.select_columns(["Boxes"])
```

The `column` method produces just the values, as a **list**:

```python
cleaned_data.column("Boxes")  # -> [2, 1, 4, 12, 3, 1, 3, 2, 2, 5]
```

### Lists

- A **list** is a sequence of values outside of a table. Like a one-column
  table, it has an order (first, ..., last), and its elements should all have
  the same type.
- Unlike a column, a list has no name of its own: `[2, 1, 4]` could be numbers
  of boxes, or ages, or quiz scores. The program, not the data, says what it
  holds, and a table's column names are the exception.
- That makes a list easy to misread, but it also means one operation works on
  any list, whatever it holds (**genericity**). Some need numbers (an average);
  others work on anything that can be compared, like strings (a maximum).
- Lists are written in square brackets (as table rows have been since
  [Class 7](/class/7)), and can be named. `[]` is the **empty list**.

```python
[2, 1, 4]
["Priya", "Marcus", "Ana"]
menu = ["cookies", "brownies", "lemon bars"]
```

### Statistics on Lists of Numbers

`max`, `min`, and `sum` are built into Python; more come from Python's
`statistics` **library**, which we `import` (as we did `math` in
[Class 9](/class/9)):

```python
import statistics as S

box_counts = cleaned_data.column("Boxes")

max(box_counts)       # 12, the largest number in the list
sum(box_counts)       # 35, the sum of its numbers
S.mean(box_counts)    # 3.5, their mean (average)
S.median(box_counts)  # 2.5, their median: the middle value, once sorted
```

- Each of these summarizes a list: many values in, one value out. Next class,
  that's one of the three ways of working on a list, the
  [list template](/class/recipe#template-lists).
- The mean is higher than the median because of Kiran's order of 12: one large
  value moves the mean, but hardly the median.
- `import statistics as S` names the library `S` (our choice), so `S.mean` is
  its `mean`, which can't be confused with built-in functions or yours.
- With no `as` (like `import math`), use the full name: `statistics.mean`.
- `from statistics import *` adds the library's functions to the directory
  under their own names (`mean(box_counts)`). We usually avoid it: you can't
  tell where a name came from, and a library name can hide one of yours.
- Try: find the function in the
  [`statistics` documentation](https://docs.python.org/3/library/statistics.html)
  that gives the most common number of boxes. Does it work on the promo codes,
  too?

### Summaries Inside Functions

A summary can be used in a helper, too. A small cafe records the drinks it sold
each day, and wants the days that were busier than average:

```python
cafe_data = table(
    ["day", "drinks-sold"],
    [
        ["Mon", 45],
        ["Tue", 30],
        ["Wed", 55],
        ["Thu", 40],
        ["Fri", 60],
    ],
)

sales = cafe_data.column("drinks-sold")
average_sales = S.mean(sales)

def busier_than_average(drinks: int) -> bool:
    """whether a day with drinks sold was busier than the average day"""
    return drinks > average_sales

def test_busier_than_average():
    assert busier_than_average(60)
    assert not busier_than_average(30)
    assert not busier_than_average(46)

busy_days = cafe_data.filter(lambda r: busier_than_average(r["drinks-sold"]))
```

- `average_sales` is `46`, so the test with `46` is at the edge: a day exactly
  as busy as average isn't busier. `busy_days` has Wednesday and Friday.
- `busy_days` is the `filter` shape of the table template; `S.mean(sales)` is
  the line that summarizes a column.
- But if Wednesday's sales were 25, `average_sales` would be 40, and the `46`
  test would fail, though `busier_than_average`'s body hadn't changed. Its
  examples depend on the data, not just on its input. A helper that takes the
  average as a parameter (`busier_than(drinks, average)`) has examples that
  stand on their own.
