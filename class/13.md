## Reading (Done Before Class)
So far, our table operations have all worked _by rows_, and have all produced
tables. Now we'll see how to ask questions about an entire column, and compute
other kinds of data, using an important new type of data.

### Basic Statistical Questions

There are many more questions we might ask of the events data from the
[Class 11](/class/11) and [Class 12](/class/12) readings, such as:

- the most frequently used discount code
- the average number of tickets per order
- the largest ticket order
- the most common number of tickets in an order
- which school led to the most orders with a `"STUDENT"` discount

These involve the maximum, minimum, average, median, and other basic
statistics. How would you express them with the operations you've seen? Each
needs a _computation on a single column of data_ (even the last: we would filter
the table to the `"STUDENT"` rows, then compute over the `Email` column), so we
need to extract a column from the table. We'll use a cleaned copy of the events
data:

```python
cleaned_data_raw = load_table("https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/dcic-events-cleaned.csv")
cleaned_data = cleaned_data_raw.transform_column("Num Tickets", int)
```

### Extracting a Column from a Table

A table method we haven't used yet, `select_columns`, produces a table with only
certain columns:

```python
cleaned_data.select_columns(["Num Tickets"])
```

But the numbers of tickets are still a column _in a table_, and no table method
does the computations we want over them: we want the numbers on their own. An
extracted column is a more basic kind of data called a _list_, which represents
a sequence of data outside of a table. The `column` method produces one:

```python
cleaned_data.column("Num Tickets")  # -> [2, 1, 5, 0, 3, 10, 3]
```

Now we have only the values from the column's cells, but they're still bundled
up, in square brackets. What is that?

### Understanding Lists

A list has much in common with a single-column table: its elements have an
order (so there is a "first", "second", and "last" element), and are all
expected to have the same type. The crucial difference is that a list has no
column name: it is _anonymous_. By itself, a list does not describe what it
represents; our program does that.

#### Lists as Anonymous Data

This isn't actually a new idea. In one setting, `3` may be an age, and in
another a play count; is `"project"` a noun or a verb? Tables have been the
exception, with descriptions built into the data rather than provided by a
program.

This _genericity_ is both a virtue and a problem. Since a list doesn't say how
to interpret it, we can accidentally misinterpret its values; but we can also
use the same data in several contexts, and one operation in many settings. Our
questions above use operations -- maximum, minimum, average, and so on -- that
make sense for a list no matter what it represents (heights, ages, play counts).
Some are specific to numbers (like average), while others (like maximum) work on
any values that can be compared (like strings).

#### Creating Literal Lists

We can also write lists directly, in square brackets (as we have for the rows of
tables since [Class 7](/class/7)), and, since lists are values, name them:

```python
[1, 2, 3]
[-1, 5, 2.3, 10]
["This", "is", "a", "list", "of", "words"]
shopping_list = ["muesli", "fiddleheads"]
```

Based on these examples, can you figure out how to write an empty list? It's
`[]`.

### Operating on Lists

#### Built-In Operations on Lists of Numbers

We can already answer most of our questions. Some functions, like `max`, `min`,
and `sum`, are built into Python; others come from Python's `statistics`
library, which we `import` (as we did `math` on [Class 9](/class/9)):

```python
import statistics as S

ticket_counts = cleaned_data.column("Num Tickets")

max(ticket_counts)       # largest number in a list
sum(ticket_counts)       # sum of numbers in a list
S.mean(ticket_counts)    # mean (average) of numbers in a list
S.median(ticket_counts)  # median of numbers in a list
```

`S.mean` means "the function `mean` inside the library `S`": the `import` line
gave the name `S` to the `statistics` library. Try: find the function in the
[`statistics` documentation](https://docs.python.org/3/library/statistics.html)
that gives the most common number of tickets.

## Recap (25 mins)

- Consider you have a small cafe that tracks daily sales, where each row has the
  number of drinks sold:

  ```python
  cafe_data = table(
      ["day", "drinks-sold"],
      [
          ["Mon", 45],
          ["Tue", 30],
          ["Wed", 55],
          ["Thu", 40],
          ["Fri", 60],
      ],
  )
  ```

- There are many basic statistical questions we might want to ask -- e.g., what
  is the maximum number of drinks sold, the average sold per day, or the total
  sold.

- We can extract single _columns_ from tables, and then use standard
  operations on those columns: some, like `max`, `min`, and `sum`, are built in to Python, and
  others come from a software library -- `statistics`.

  ```python
  import statistics as S

  sales = cafe_data.column("drinks-sold")
  max(sales)      # maximum sales
  S.mean(sales)   # average sales
  sum(sales)      # total sold
  ```

- Here, `import statistics as S` declares that you want to use code that comes from
  Python's `statistics` library (https://docs.python.org/3/library/statistics.html), and in order
  to not get confused between the functions provided from it and the functions
  available by default or defined by you, the `as S` gives the library a short
  name. This means that any function `function_name` from the `statistics` library is
  available as `S.function_name`. The choice `S` is arbitrary -- usually, programmers
  use a short abbreviation of the library's name. (If you leave off the `as ...`, as we did with
  `import math` on [Class 9](/class/9), the functions are available with the full name of the library: `statistics.mean`.)

- If you aren't worried about mixing up functions from the library, you can
  instead write:

  ```python
  from statistics import *
  ```

  This adds all the functions from the `statistics` library to the current program directory
  with no change of name, so we could write the above alternately as:

  ```python
  from statistics import *

  sales = cafe_data.column("drinks-sold")
  max(sales)     # maximum sales
  mean(sales)    # average sales
  sum(sales)     # total sold
  ```

  However, this makes it harder, when reading a program, to tell where each name came from, and if the library
  defines a name that you also define, one will hide the other -- so we'll usually use `import ... as ...`.

- A column is a type of data called a `list` -- if we print it out we can see
  that it looks like:

  ```python
  cafe_data.column("drinks-sold")
  ```

  This shows at the interactions as:

  ```python
  [45, 30, 55, 40, 60]
  ```

- Lists have order, but no column header, and unlike tables, only a single value
  per entry.

- We can define list values directly using the above syntax:

  ```python
  sample_list = [10, 20, 30]
  empty_list = []
  ```

- And lists can have any type of data in them. On lists of _numbers_ we can use
  built-in functions like `max` and `sum`, and functions from `statistics`, on them.
