## Notes (review before class)
**Pandas** is a popular Python library for tables. Of its many ways to do
things, these notes use the ones that match PLL tables. Start your file with
(the first run may take a while, as PLL loads pandas):

```python
import pandas as pd
```

### DataFrames and Series

- **DataFrame**: pandas' name for a table, with rows and columns.
- **Array**: a sequence of values accessed by position (0, 1, ..., up to one
  less than its length). Ordered, like a list, but created with a limit on how
  many elements it holds.
- **Series**: an array whose positions can also have **labels**.
- A row is a Series whose values are labeled with the column names (like a PLL
  row, a `dict` from column names to values); a DataFrame is a series of rows.

### Creating and Loading DataFrames

By hand, from a dictionary that maps column names to lists of values (column by
column, as with PLL's `table_from_columns`, rather than row by row). The bake
sale's price list:

```python
prices = pd.DataFrame({
    "item": ["cookies", "brownies", "lemon bars"],
    "price": [8.0, 10.0, 12.0],
})
```

From a CSV file, with `read_csv` and its file name or web address. These are the
bake-sale preorders from [Class 11](/class/11), as the form saved them, in
`bake-sale-orig.csv`, with new column names:

```python
bake = pd.read_csv("bake-sale-orig.csv", header=0,
                   names=["name", "email", "boxes", "item", "code", "delivery", "zip"])
```

- `header=0`: the headers are in the first row (numbered `0`). Use `header=None`
  if the file has no header row.
- `names`: the column labels to use instead of the file's headers (leave it out
  to keep them).
- Unlike `load_table`, which reads every value as a string, `read_csv` converts
  columns that contain only numbers to numbers. So `zip` becomes numbers, and
  loses its leading 0s: `02115` is `2115`.

Evaluating `bake` shows a table like this:

- `NaN`, in the empty `code` cells, is the standard Python value for missing

### Accessing Rows, Columns, and Cells

By label, or by (numeric) position:

```python
bake["boxes"]          # the boxes column, as a Series
bake["boxes"][2]       # the value in the boxes column, row 2
bake.loc[6]            # the row with label 6
bake.loc[6]["boxes"]   # the value in the row with label 6, boxes column
bake.iloc[6]           # the row at position 6
```

- `.loc` gets a row by its label; `.iloc` by its position (`i` for "integer").
- Rows and columns always have positions, and may have labels.
- `bake["boxes"][2]` is `'4'`, a string: because of Lina's `three`, `read_csv`
  read the whole column as strings (more below).
- A Series has statistics operations, like `.sum()` and `.mean()` (for PLL,
  `t.sum("col")` and `t.mean("col")`).

### Filtering Rows with Masks

PLL's `filter` takes a function from a row to a `bool`. In pandas, we give a
**mask**: an array of booleans, one per row, and get the rows whose entries are
`True`:

```python
keep = [True, False, True, False, False, False, True, False, False, False]
bake[keep]
```

- In square brackets, a column label selects a column; a mask selects rows (by
  position).
- The result keeps the original row labels (0, 2, and 6), while its positions
  are, as always, 0, 1, 2. (Try: does `bake` itself change?)

We compute masks, rather than writing them by hand, with an expression over a
Series:

```python
bake[bake["delivery"] == "delivery"]
```

- **Lifting**: applying an operation to every element of an array.
  `bake["delivery"] == "delivery"` doesn't ask whether a Series equals a string:
  it compares each element to `"delivery"`, making a new Series of booleans.
- The inner `bake` makes the mask; the outer one filters with it.
- It gives Marcus's, Ana Paula's and Grace's rows, but not Tomás's `Delivery`
  or Lina's `delivry`: the data still needs cleaning.

### Cleaning Data

Lifting also normalizes data (as in [Class 11](/class/11)), e.g. making all
promo codes lowercase:

```python
bake["code"] = bake["code"].str.lower()
```

- `lower()` is a string operation, not a Series one: `.str` says to apply the
  string operation to each element (for one string, just `"BAKE10".lower()`).
- Assigning to `bake["code"]` replaces the column. Unlike PLL's
  `transform_column`, which makes a new table, this **mutates** `bake` (as in
  [Class 25](/class/25)).

To make every unknown code (`none`, `NaN`, the space) the empty string, mask the
rows without a known code, then set their code:

```python
codes = ["bake10", "friend"]          # the valid codes
mask = ~bake["code"].isin(codes)      # rows with INVALID codes
bake.loc[mask, "code"] = ""
```

- `isin(codes)`, lifted, checks whether each value is in the list; `~` swaps
  `True` and `False` in a mask.
- To update a column in some rows: make a mask of the rows, select the cells
  with `.loc[mask, column]`, and use `=`. (Try: change the `"Delivery"` and
  `"delivry"` values to `"delivery"`.)
- Gotcha: `bake[mask]["code"] = ""` gives a `SettingWithCopyWarning`, and
  `bake` doesn't change (a subtlety of how pandas updates data).

### Repairing Values and Column Types

A row label works in place of a mask. To fix the `"three"` in Lina's row:

```python
bake.loc[6, "boxes"] = 3
```

`bake["boxes"].sum()` still fails: since `boxes` had text in it, `read_csv` read
all its values as strings (pandas shows them without quotation marks, so they
look like numbers), and the repair changed only one:

```python
type(bake["boxes"].loc[0])   # str
type(bake["boxes"].loc[6])   # int, for the corrected value
```

`astype` converts the values of a Series (like `transform_column` with `int`):

```python
bake["boxes"] = bake["boxes"].astype("int")
bake["boxes"].sum()   # now this works: 35
```

### Functions on DataFrames

A function on a DataFrame is designed with the same recipe, and tested on a
small DataFrame made by hand, whose answers you can work out:

```python
import pytest

first_orders = pd.DataFrame({
    "name": ["Priya Raman", "Marcus Bell", "Ana Paula Lima"],
    "boxes": [2, 1, 4],
    "item": ["cookies", "brownies", "lemon bars"],
    "delivery": ["pickup", "delivery", "delivery"],
})

def item_at(t: pd.DataFrame, pos: int) -> str:
    """the item ordered in the row at position pos of t"""
    return t.iloc[pos]["item"]    # PLL: t.row(pos)["item"]

def average_boxes(t: pd.DataFrame) -> float:
    """the average number of boxes in each order in t"""
    return t["boxes"].mean()      # PLL: t.mean("boxes")

def test_item_at():
    assert item_at(first_orders, 0) == "cookies"
    assert item_at(first_orders, 2) == "lemon bars"

def test_average_boxes():
    assert average_boxes(first_orders) == pytest.approx(7 / 3)
```

- The tests use `first_orders`, not `bake`: its answers can be worked out by
  hand, and nothing else in the program changes it.
- Try: let `big = first_orders[first_orders["boxes"] >= 2]`. Which rows does
  `big` have? Which of `item_at(big, 1)` and `big.loc[1]["item"]` works, and
  why?

### Pandas Beside PLL Tables

Pandas has too many ways of doing each job to have one template. Instead, use
the [table template](/class/recipe#template-tables) to decide what the answer
is (fewer rows, a new column, a changed column, a summary), then find the pandas
way of doing that job:

| The job | PLL table | pandas |
| --- | --- | --- |
| make a table by hand | `table(columns, rows)` | `pd.DataFrame({column: values})` |
| load a CSV | `load_table(url)` | `pd.read_csv(url)` |
| a column | `t.column("col")`, a list | `df["col"]`, a Series |
| a row | `t.row(i)` | `df.iloc[i]` |
| summarize a column | `t.sum("col")`, `t.mean("col")` | `df["col"].sum()`, `df["col"].mean()` |
| fewer rows | `t.filter(keep)` | a mask: `df[df["col"] == value]` |
| a changed column | `t.transform_column("col", f)` | `df["col"] = ...`, which mutates `df` |

The [Design Recipe](/class/recipe#pandas) page keeps the whole list. The rest of
the recipe doesn't change: a function on a DataFrame still has a Signature (its
type is `pd.DataFrame`), a Docstring, and Examples on a small DataFrame.
