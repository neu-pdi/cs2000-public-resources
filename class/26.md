## Reading (Done Before Class)
Now it's time to transfer what we learned about PLL tables to _pandas_, a
popular Python library for tables. Pandas has many ways to do common
operations; we present the ones that line up with what we did with PLL tables.
To use pandas, put this line at the top of your file (the first run may take a
while, as PLL loads pandas):

```python
import pandas as pd
```

### Pandas Table Basics

#### Core Datatypes: DataFrame and Series

Pandas uses the term _DataFrame_ for a table with rows and columns. DataFrames
are built out of two more basic types:

- An _array_ is a sequence of values that can be accessed by position (0, 1, ...
  up to one less than its length). Like lists, arrays are ordered; unlike lists,
  they are created with a limit on how many elements they contain.
- A _Series_ is an array in which the positions can also have _labels_.

In pandas, a row is a Series whose cell values are labeled with the column names
(similar to a PLL row, a `dict` from column names to values). A DataFrame is a
series of these rows.

#### Creating and Loading DataFrames

As with PLL tables, DataFrames can be created by hand or loaded from a file:

```python
data = {
    "day": ["mon", "tues", "wed", "thurs", "fri"],
    "max temp": [58, 62, 55, 59, 64],
}
temps = pd.DataFrame(data)
```

`data` is a dictionary that maps column names to lists of values (as for PLL's
`table_from_columns`), and `pd.DataFrame` creates a DataFrame from it. To load a
CSV file, give `read_csv` its file name or web address. Here we load the event
ticket orders from [Class 11](/class/11), changing the column names as we do:

```python
EVENTS_URL = "https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/dcic-events-orig.csv"
events = pd.read_csv(EVENTS_URL, header=0,
                     names=["name", "email", "numtix", "discount", "delivery", "zip"])
```

`header=0` says the headers are in the first row (numbered `0`), and `names`
gives the column labels to use instead of those headers. To keep the file's
headers, leave out `names=[...]`; if the file had no header row, we would write
`header=None`. Evaluating `events` shows:

```
               name             email numtix  discount delivery    zip
0        Josie Zhao       jo@mail.com      2  BIRTHDAY    email  90210
1        Sam Ochibe        s@sweb.com      1       NaN   pickup  30301
2       Bart Simple  bart@simpson.org      5   STUDENT      yes  60614
3    Ernie O'Malley    ernie.mail.com      0      none    email  10001
4  Alvina Velasquez   alvie@schooledu      3   student    emall  73301
5            Zander          zandaman     10       NaN    email   2115
6  Shweta Chowpatti      snc@this.org  three             pickup   2903
```

The column labels are across the top. Since we gave no labels for the rows,
pandas labeled them with numbers, down the left side. For now, each row's label
is the same as its position, but we will see that this is not always the case.
Some blank discount cells contain `NaN`, the standard Python value for missing
information; we will deal with these shortly.

#### Using Labels and Indices to Access Cells

Rows, columns, and cells can be accessed using either their (numeric) positions
or their labels:

```python
events["numtix"]          # the numtix column, as a Series
events["numtix"][2]       # the value in the numtix column, row 2
events.loc[6]             # the row with label 6
events.loc[6]["numtix"]   # the value in the row with label 6, numtix column
events.iloc[6]            # the row at position 6
```

`.loc` tells pandas that you are using a label to access a row; to use the
position instead, use `.iloc` (the `i` stands for "integer"). Both rows and
columns always have positions, and may have labels.

### Filtering Rows

With PLL tables, we filtered rows by writing a function from a row to a `bool`,
and `filter` produced a new table with the rows for which it returned `True`. In
pandas, we instead provide an array of booleans, one per row, and filtering
keeps the rows whose entries are `True`. For example, to keep rows 0, 2, and 6:

```python
keep = [True, False, True, False, False, False, True]
events[keep]
```

Just as `events["numtix"]` selects a column, `events[keep]` selects rows: a
single label in the square brackets gives us the column with that label, and an
array of booleans gives us the rows whose entries (by position) are `True`. Look
at the result: do you notice anything interesting? Its row labels are the
original ones (0, 2, and 6), while its positions are, as always, consecutive
numbers from 0. Does filtering this way keep the original `events` intact? Try
it out!

Arrays of booleans used for filtering are called _masks_. For a long DataFrame,
we wouldn't want to write a mask by hand, and we don't have to: we can compute
one with an expression over a Series. Say we want the rows with delivery method
`"email"`. We select the delivery column, and use it in a boolean expression:

```python
events["delivery"] == "email"
```

Wait: `events["delivery"]` is a Series, and `"email"` is a string, so what does
it mean to ask whether they are equal? Here, `==` doesn't mean "are these
equal?". Instead, Python applies `== "email"` to every element of the Series,
building a new Series of the results. Applying an operation to all the elements
of an array like this is called _lifting_. Now we can use this Series of
booleans to select those rows:

```python
events[events["delivery"] == "email"]
```

The inner use of `events` creates the mask; the outer one filters the table
with it.

### Cleaning and Normalizing Data

Lifting also helps with normalizing data. On [Class 11](/class/11), we converted
all of the discount codes to lowercase; in pandas:

```python
events["discount"] = events["discount"].str.lower()
```

On the right side of the `=`, we extract the Series of discount codes, and use
the string operation `lower()` to convert each one. For a single string, we
would write just `"BIRTHDAY".lower()`, but `lower()` isn't defined on Series:
the `str` tells Python to find it among the operations on strings. The left
side, `events["discount"] = ...`, replaces the contents of the `"discount"`
column with the Series on the right. This is like PLL's `transform_column`, but
with a fundamental difference: `transform_column` leaves the old table intact
and produces a new one, whereas in pandas the old column is replaced, mutating
the original table (as on [Class 25](/class/25)).

#### Clearing out unknown values

Next, the discount column should contain only known discount codes or empty
strings: the `none`, the `NaN`s, and the entry that is just a space should all
become `""`. Try planning how to do this with masks. You might end up with:

1. create a mask of the rows with known discount codes
2. invert that mask (swap its `False` and `True` values)
3. filter the DataFrame to the rows without a known discount code
4. replace the discount values in those rows with an empty string

For step 1, a lifted `isin` checks whether each value is in a list. For step 2,
the operator `~` swaps the values in a mask, and for step 3, we filter with it
(giving the mask a name, to keep the code easy to read):

```python
codes = ["birthday", "student"]          # the valid codes
mask = ~events["discount"].isin(codes)   # rows with INVALID codes
events[mask]
```

For step 4, we would like to write `events[mask]["discount"] = ""`, but pandas
responds with a `SettingWithCopyWarning`, and `events` doesn't change! This is a
subtlety about how data get updated under the hood. Instead, we use this form,
which works:

```python
events.loc[mask, "discount"] = ""
```

So, to update a column in some of the rows of a DataFrame: make a mask of the
rows to update, use `.loc` with the mask and the column name to select those
cells, and use `=` to give them their new value. Try following this pattern to
change all delivery values of `"yes"` to `"pickup"`.

#### Repairing Values and Column Types

In the last row, someone entered the string `"three"` in place of the number
`3`. We can repair this by hand, with the same pattern (using the row's label in
place of a mask):

```python
events.loc[6, "numtix"] = 3
```

Now try totaling the tickets sold, with `events["numtix"].sum()`. What do you
get? Why? Pandas displays strings without quotation marks, so the column looks
like it contains numbers, but the failure of `sum` shows otherwise. We can check
the types of its values with `type`:

```python
type(events["numtix"].loc[0])   # str
type(events["numtix"].loc[6])   # int, for the corrected value
```

Unlike `load_table`, which reads every value as a string, `read_csv` converts
columns that contain only numbers (like `zip`) to numbers. But the `numtix`
column also had other text, so it read all its values as strings, and our repair
changed just one. To change the type of the values in a Series (much like
`transform_column` with `int` on a PLL table), we use `astype`:

```python
events["numtix"] = events["numtix"].astype("int")
events["numtix"].sum()   # now this works
```

## Recap (20 mins)

Today we learn **Pandas**, Python's library for working with tables (called DataFrames). Everything you learned about PLL tables has a Pandas equivalent, but with different syntax.

### Creating tables literally (like PLL's `table(...)`)

```python
# PLL way:
# orders = table(
#     ["date", "dish", "quantity", "order_type"],
#     [
#         ["2023-07-01", "Pasta", 2, "dine-in"],
#         ["2023-07-01", "Salad", 1, "takeout"],
#     ],
# )

# Pandas way -- note that data is given column by column, rather than row by row.
import pandas as pd
data = {
    'date': ['2023-07-01', '2023-07-01', '2023-07-02'],
    'dish': ['Pasta', 'Salad', 'Burger'],
    'quantity': [2, 1, 3],
    'order_type': ['dine-in', 'takeout', 'dine-in']
}
orders = pd.DataFrame(data)
```

### Loading from CSV (like PLL's `load_table(...)`)

```python
# PLL way:
# orders = load_table("https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/restaurant_orders.csv")

# Pandas way -- note that, unlike load_table, it automatically converts
# columns that contain only numbers to numbers.
orders = pd.read_csv("https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/main/static/support/restaurant_orders.csv")
```

### Accessing data (like PLL's `.row` and `[...]`)

```python
# PLL way:
# orders.row(1)["dish"]

# Pandas way:
orders.iloc[1]         # Get row by index (like .row)
orders.iloc[1]['dish'] # Get single value from row (like .row(...)["dish"])
```

### Extracting columns as lists (like PLL's `.column`)

```python
# PLL way:
# quantities = orders.column("quantity")  # Extract column as list

# Pandas way:
quantities = orders['quantity'] # Extract column as Series -- not quite a list, but similar
```

### Built-in statistics (like PLL's `.mean("column")`)

```python
# PLL way:
# orders.mean("quantity")     # Direct table operation
# orders.sum("quantity")      # Direct table operation

# Pandas way:
orders['quantity'].mean()     # Series operation
orders['quantity'].sum()      # Series operation
```
