### Accumulators

The loop template's `result` is an **accumulator**: it gathers the answer as the
loop goes, one element at a time. What it holds can always be said in a
sentence about the elements seen so far, its **accumulator statement**:

- for a sum, "`total` is the sum of the elements seen so far";
- for `in_hours` (below), "`result` is the lengths seen so far, in hours".

That sentence gives both ends of the loop. Before the loop, no elements have been
seen, so the accumulator starts as the answer for an empty list. After the loop,
every element has been seen, so it is the answer.

Sometimes the answer needs to know something about the elements seen so far
that isn't the answer itself. Then it gets a second accumulator, with a
statement of its own. A hike's legs, the distances between its stops, give each
stop's distance from the start: legs of `[3, 2, 4]` miles put the stops at
`[3, 5, 9]`. Each stop's distance is the last one's, plus the next leg:

```python
def from_start(legs: list[float]) -> list[float]:
    """each stop's distance from the start, given the legs between the stops"""
    so_far = 0   # the distance from the start to the last stop seen
    result = []  # each stop seen so far, as its distance from the start
    for leg in legs:
        so_far = so_far + leg
        result = result + [so_far]
    return result

def test_from_start_with_no_legs():
    assert from_start([]) == []

def test_from_start_with_one_leg():
    assert from_start([3]) == [3]

def test_from_start_with_three_legs():
    assert from_start([3, 2, 4]) == [3, 5, 9]
```

- Each accumulator's statement is a comment where it starts, as a note on that
  variable. (What the function does goes in its Docstring, as always.)
- Each trip through the loop keeps both statements true: once `leg` is seen,
  `so_far` is the distance to the stop it ends at, and `result` has that stop
  too.
- `so_far` is never the answer, but without it, each stop's distance would need
  all the legs before it added up again.
- `differences` and `running_max`, in today's Practice, each need a second
  accumulator too. What is each one's statement?

## Live

Mirror pairs. For each problem, you and your partner write the Signature,
Docstring and Examples together. Then one of you writes the `for` loop version

## Practice

1. Design `in_hours`, which takes a list of lengths of time, in minutes, and
  gives a new list of the same lengths in hours. (Loop template, building.)
1. Re-implement it as `in_hours_map`, using `map`. Which do you find clearer?
  (List template, each one changed.)
1. Design `initials`, which takes a list of names and gives a list of each
  name's first letter. (`"Priya"[0]` is `"P"`: square brackets work on strings
  as on lists.) Then re-implement it as `initials_map`.
1. Design `passing_scores`, which takes a list of exam scores and gives just the
  scores of 60 or more, in order. (Loop template, building, with an `if`.) Then
  re-implement it as `passing_scores_filter`, with `filter`. (List template,
  fewer elements.)
1. Design `differences`, which takes a list of numbers and gives a list of each
  number minus the one before it: `differences([3, 5, 4, 8])` is `[2, -1, 4]`.
  You'll need _two_ variables that change: the result, as usual, and the
  previous number. Can you express it with `map` or `filter`? Which template fits
  it, and why doesn't the list template?
1. Design `running_max`, which gives, at each position, the largest number so
  far: `running_max([3, 1, 4, 1, 5])` is `[3, 3, 4, 4, 5]`. Can you express it
  with `map` or `filter`? Which template fits it?
1. Design `longest_streak`, which takes a list of daily temperatures, and gives
  the most days in a row above freezing (above 0): `longest_streak([2, 5, -1,
  3, 4, 6, -2])` is `3`. Write each accumulator's statement first. (How many do
  you need?)
1. Design `balances`, which takes a starting balance and a list of deposits
  (positive) and withdrawals (negative), and gives the balance after each one.
1. In each pair you wrote, which version would you rather read, and which
  would you rather change? `for` loops can do more, but a built-in like `filter`
  or `map` says at a glance which shape the answer has.
