## Notes (review before class)
### What the Recursive Call Doesn't Know

[Class 17](/class/17)'s `from_start` gave each stop's distance from the start of a
hike, given the legs between the stops, with a loop and an accumulator. From the
list template instead, the recursive call's answer for the rest is no help as it
is: it measures from the start of the _rest_, not of the hike. Every distance in
it has to be moved along by the first leg:

```python
def add_to_each(n: float, lst: list[float]) -> list[float]:
    """each element of lst, plus n"""
    match lst:
        case []:
            return []
        case [f, *r]:
            return [f + n] + add_to_each(n, r)

def from_start(legs: list[float]) -> list[float]:
    """each stop's distance from the start, given the legs between the stops"""
    match legs:
        case []:
            return []
        case [f, *r]:
            return [f] + add_to_each(f, from_start(r))

def test_from_start():
    assert from_start([]) == []
    assert from_start([3]) == [3]
    assert from_start([3, 2, 4]) == [3, 5, 9]
```

- It's right, but it does far more work than the loop: each call goes through
  the whole answer for the rest again, so 1,000 legs take about 500,000
  additions, where the loop took 1,000.
- The trouble is that each call knows only the legs from here on. How far the
  hike has already come is knowledge the recursive call has lost.

### Adding an Accumulator

The fix is to give the recursive call what it's missing, as a parameter: an
**accumulator**, as in [Class 17](/class/17), but passed from call to call. A
helper takes the legs from here on, and `so_far`, the distance from the start of
the hike to here:

```python
def from_start_acc(legs: list[float], so_far: float) -> list[float]:
    """each stop's distance from the start of the hike, given the legs from
    here on, where so_far is the distance from the start to here"""
    match legs:
        case []:
            return []
        case [f, *r]:
            return [so_far + f] + from_start_acc(r, so_far + f)

def from_start(legs: list[float]) -> list[float]:
    """each stop's distance from the start, given the legs between the stops"""
    return from_start_acc(legs, 0)

def test_from_start_acc():
    assert from_start_acc([], 7) == []
    assert from_start_acc([2, 4], 3) == [5, 9]

def test_from_start():
    assert from_start([]) == []
    assert from_start([3]) == [3]
    assert from_start([3, 2, 4]) == [3, 5, 9]
```

- What `so_far` means, its **accumulator statement**, is in the helper's
  Docstring: it is part of what the helper does.
- Each call adds one leg, so 1,000 legs take 1,000 additions, as in the loop.
- `from_start` is the function people call. It gives the accumulator its first
  value: at the start, the hike has come `0`.

### Loops and Accumulators, Side by Side

The loop of [Class 17](/class/17) and the helper have the same accumulator,
and each of its parts is in both:

| | The loop | The recursion |
| --- | --- | --- |
| The accumulator statement | `so_far` is the distance from the start to the last stop seen | `so_far` is the distance from the start to here |
| Its first value | `so_far = 0`, before the loop | `from_start_acc(legs, 0)`, the first call |
| Its next value | `so_far = so_far + leg`, inside the loop | `so_far + f`, the argument of the recursive call |
| What handles the rest of the list | the next trips through the loop | the recursive call |

A loop's variable changes from one trip to the next; a recursive call gets the
next value as an argument instead, and nothing changes. The statement says the
same thing in both.

### When the Accumulator Is the Answer

[Class 16](/class/16)'s Practice reversed a list with a loop, adding each
element to the front of the answer so far. With an accumulator, the recursion
does the same: `done` is the elements already passed, last first.

```python
def reverse_acc[T](lst: list[T], done: list[T]) -> list[T]:
    """the elements of lst, last first, then the elements of done"""
    match lst:
        case []:
            return done
        case [f, *r]:
            return reverse_acc(r, [f] + done)

def reverse[T](lst: list[T]) -> list[T]:
    """the elements of lst, last first"""
    return reverse_acc(lst, [])

def test_reverse():
    assert reverse([]) == []
    assert reverse([1, 2, 3]) == [3, 2, 1]
    assert reverse(["oak", "elm"]) == ["elm", "oak"]
```

- When the list is empty, every element has been passed, so `done` is the whole
  answer: the base case gives back the accumulator, as the loop gives back
  `result` after its last trip.
- From the template, without an accumulator, `reverse(r) + [f]` would copy the
  answer for the rest at every step, as `add_to_each` did.

### Designing with an Accumulator

The recipe's steps are the same, with these in the Template and Body steps:

1. **See the need**: the function needs to know something about the elements
   it has already passed, which the recursive call's answer doesn't tell it.
2. **The accumulator statement**: what the accumulator means, about the
   elements already passed, in the helper's Docstring.
3. **Its first value**: what the statement says before any element is passed.
   The main function calls the helper with it.
4. **Its next value**: what the statement says once `f` has been passed too.
   That's the recursive call's new argument.
5. **Use it**: in the answer, where it's needed; and in the base case, if, as for
   `reverse`, the accumulator is the answer.
