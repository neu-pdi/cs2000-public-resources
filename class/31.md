### Knowledge from Above

<!-- python setup
@dataclass
class Spring:
    pass

@dataclass
class River:
    name: str
    length: float
    left: RiverTree
    right: RiverTree

RiverTree = Spring | River

main_tree = River("Main River", 40,
                  River("North Fork", 22,
                        River("Cedar Creek", 9,
                              River("Birch Brook", 4, Spring(), Spring()),
                              River("Elk Creek", 5, Spring(), Spring())),
                        River("Pine Run", 7,
                              Spring(),
                              River("Fern Brook", 3, Spring(), Spring()))),
                  River("South Fork", 18, Spring(), Spring()))
-->

In a river tree ([Class 25](/class/25)), a river's `length` runs from its mouth,
where it joins the river below, to its upper end, where it forks. Which rivers'
upper ends are more than 60 miles from the main river's mouth? For North Fork,
it's 40 + 22 = 62 miles: its own length, plus the lengths of the rivers below
it.

A function from the tree template can't see that. The recursive call on North
Fork's subtree knows only North Fork and what is upstream of it, not that the
Main River is below it, 40 miles long. As in [Class 30](/class/30), the call
gets what it's missing as an accumulator: `so_far`, the distance from the main
river's mouth to the mouth of the subtree it's given.

```python
def far_rivers_acc(t: RiverTree, miles: float, so_far: float) -> list[str]:
    """the names of the rivers in t whose upper ends are more than miles from
    the main river's mouth, where so_far is the distance from the main river's
    mouth to t's"""
    match t:
        case Spring():
            return []
        case River():
            here = so_far + t.length
            upstream = far_rivers_acc(t.left, miles, here) + far_rivers_acc(t.right, miles, here)
            if here > miles:
                return [t.name] + upstream
            else:
                return upstream

def far_rivers(t: RiverTree, miles: float) -> list[str]:
    """the names of the rivers in t whose upper ends are more than miles from
    t's mouth"""
    return far_rivers_acc(t, miles, 0)

def test_far_rivers():
    assert far_rivers(Spring(), 10) == []
    assert far_rivers(main_tree, 100) == []
    assert far_rivers(main_tree, 70) == ["Cedar Creek", "Birch Brook", "Elk Creek", "Fern Brook"]
    assert far_rivers(main_tree, 60) == ["North Fork", "Cedar Creek", "Birch Brook", "Elk Creek", "Pine Run", "Fern Brook"]
```

- `here`, the distance to this river's upper end, is the accumulator's next
  value. Both forks get it: both start where this river forks.
- In a list, the accumulator follows the one path along the list. In a tree, it
  goes down every path from the root separately, and holds what's known about
  the path to where it is: here, how long it is.
- The statement is in the helper's Docstring, and the first value, `0`, is in
  `far_rivers`: at the main river's mouth, no distance has been covered yet.

### Bounds from Above

A BST's invariant ([Class 28](/class/28)) is about _every_ key in a subtree:
those on a node's left must be less than its key, and those on its right
greater. Checking each node against its children isn't enough:

<!-- python setup
@dataclass
class EmptyLeaf:
    pass

@dataclass
class Node:
    key: int
    val: str
    left: BST
    right: BST

BST = EmptyLeaf | Node

BST0 = EmptyLeaf()
BST1 = Node(1, "hello", BST0, BST0)
BST2 = Node(5, "bye", BST1, BST0)
BST3 = Node(6, "bye", BST2, Node(10, "cs2000", BST0, BST0))
-->

```python
not_a_bst = Node(6, "a", Node(4, "b", EmptyLeaf(), Node(8, "c", EmptyLeaf(), EmptyLeaf())), EmptyLeaf())
```

Here, 8 is greater than 4, its parent, as a right child should be. But it is in
6's left subtree, and 8 isn't less than 6. Whether a key is allowed depends on
every node on the path down to it: going left at a node, every key below must
be less than the node's; going right, greater. So the check takes the bounds
from above as accumulators: `low` and `high`, each `None` ([Class 24](/class/24))
where there is no bound yet.

```python
def within(k: int, low: int | None, high: int | None) -> bool:
    """whether k is greater than low and less than high, where None is no
    bound"""
    return (low == None or k > low) and (high == None or k < high)

def is_bst_acc(t: BST, low: int | None, high: int | None) -> bool:
    """whether t keeps the BST invariant, with every key in it greater than low
    and less than high, the bounds from the nodes above t (None for no bound)"""
    match t:
        case EmptyLeaf():
            return True
        case Node():
            return (within(t.key, low, high) and is_bst_acc(t.left, low, t.key)
                    and is_bst_acc(t.right, t.key, high))

def is_bst(t: BST) -> bool:
    """whether t keeps the BST invariant"""
    return is_bst_acc(t, None, None)

def test_within():
    assert within(5, None, None)
    assert within(5, 4, 6)
    assert not within(5, 5, None)
    assert not within(5, None, 5)

def test_is_bst():
    assert is_bst(BST0)
    assert is_bst(BST3)
    assert not is_bst(not_a_bst)
    assert not is_bst(Node(6, "a", EmptyLeaf(), Node(2, "b", EmptyLeaf(), EmptyLeaf())))
```

- The two subtrees get _different_ accumulators: going left, the node's key is
  the new upper bound; going right, the new lower one. What each subtree's
  keys must be depends on which way the path went.
- At the root, nothing is known yet: no bounds, `None` and `None`.
- Without accumulators, each node would need the largest key on its left and the
  smallest on its right, found by searching those subtrees again at every node.
