## Notes (review before class)
### Two Functions, One Difference

`count_flavor` ([Class 22](/class/22)'s Practice) counts the pancakes of any
flavor, given as a parameter: one function, where counting the blueberries and
counting the bananas would have been two, the same but for one string. Turning a
difference into a parameter is **abstraction**, and functions can differ in more
than a value. These two differ in a _test_:

```python
def short_words(words: list[str]) -> list[str]:
    """the words in words with fewer than 5 letters, in order"""
    match words:
        case []:
            return []
        case [w, *r]:
            if len(w) < 5:
                return [w] + short_words(r)
            else:
                return short_words(r)

def passing(scores: list[int]) -> list[int]:
    """the scores in scores of 60 or more, in order"""
    match scores:
        case []:
            return []
        case [s, *r]:
            if s >= 60:
                return [s] + passing(r)
            else:
                return passing(r)

def test_short_words():
    assert short_words([]) == []
    assert short_words(["oak", "maple", "elm"]) == ["oak", "elm"]

def test_passing():
    assert passing([]) == []
    assert passing([59, 60, 100]) == [60, 100]
```

Apart from their names, they differ in two places: the test in the `if`
(`len(w) < 5`, and `s >= 60`), and the types in their Signatures. Everything else
is the same, line for line.

### Functions Are Values

The test can be a parameter too, because a function is a value. A function's
name, without `()`, is the function itself; passing it along doesn't call it.
Since [Class 14](/class/14), `filter(keep, lst)` has been given a function, and
calls it on each element.

- A function's type is a `Callable`: `Callable[[str], bool]` is a function that
  takes a `str` and gives a `bool`. The types of its inputs go in the inner
  brackets, and its result type after them.
- A parameter whose value is a function is called like any function: `keep(f)`.

### Abstracting from Examples

The steps, for any two similar functions (or more):

1. **Compare** them, and mark each place where they differ.
2. **Abstract**: copy one, give it a new name, and replace each difference with
   a new parameter. A difference in a value becomes a value parameter; a
   difference in what's done becomes a function parameter.
3. **Check**: write each original as a call of the abstraction, with a helper
   for each function it passes. The originals' tests should still pass.
4. **Signature**: compare the originals' Signatures. Where their types differ,
   put a type variable ([Class 24](/class/24)). A function parameter's type is a
   `Callable`.
5. **Docstring and Examples** for the abstraction itself.

For `short_words` and `passing`, the difference is the test, so each test
becomes a helper of its own:

```python
def is_short(w: str) -> bool:
    """whether w has fewer than 5 letters"""
    return len(w) < 5

def is_passing(s: int) -> bool:
    """whether s is 60 or more"""
    return s >= 60
```

The abstraction takes the test as a parameter, `keep`. It's our own `filter`:

```python
def my_filter[T](keep: Callable[[T], bool], lst: list[T]) -> list[T]:
    """the elements of lst on which keep gives True, in order"""
    match lst:
        case []:
            return []
        case [f, *r]:
            if keep(f):
                return [f] + my_filter(keep, r)
            else:
                return my_filter(keep, r)

def test_my_filter():
    assert my_filter(is_short, []) == []
    assert my_filter(is_short, ["oak", "maple", "elm"]) == ["oak", "elm"]
    assert my_filter(is_passing, [59, 60, 100]) == [60, 100]
```

The originals become one line each, and their tests still pass:

```python
def short_words(words: list[str]) -> list[str]:
    """the words in words with fewer than 5 letters, in order"""
    return my_filter(is_short, words)

def passing(scores: list[int]) -> list[int]:
    """the scores in scores of 60 or more, in order"""
    return my_filter(is_passing, scores)
```

### Similarities in Signatures

The Signature comes from comparing the originals', with the helper's type for
the function parameter:

| Function | The test's type | The list's type | The result's type |
| --- | --- | --- | --- |
| `short_words` | `Callable[[str], bool]` | `list[str]` | `list[str]` |
| `passing` | `Callable[[int], bool]` | `list[int]` | `list[int]` |
| `my_filter` | `Callable[[T], bool]` | `list[T]` | `list[T]` |

- `str` and `int` differ, so they become `T`, the same `T` in all three places:
  the test takes the list's elements, and the result holds the same elements.
- `bool` is the same in both, so it stays.

`in_hours` and `initials`, from [Class 17](/class/17)'s Practice, differ in what's
done to each element, and in two types: the elements' and the results'. Their
abstraction is our own `map`, with two type variables:

```python
def my_map[T, R](change: Callable[[T], R], lst: list[T]) -> list[R]:
    """the results of change on each element of lst, in order"""
    match lst:
        case []:
            return []
        case [f, *r]:
            return [change(f)] + my_map(change, r)

def first_letter(name: str) -> str:
    """the first letter of name"""
    return name[0]

def test_my_map():
    assert my_map(first_letter, []) == []
    assert my_map(first_letter, ["Ana", "Bo"]) == ["A", "B"]
    assert my_map(is_short, ["oak", "maple"]) == [True, False]
```

- In the third test, `T` is `str` and `R` is `bool`: the result's element type
  can differ from the input's, which is why it needs a variable of its own.

### Helpers That Use a Parameter

What if the limit isn't always 5? A function with the limit as a parameter
needs a helper that uses it, and a helper written inside the function can: it
sees the function's parameters, as the helpers in the table templates of
[Class 8](/class/8) see what's around them.

```python
def shorter_than(words: list[str], n: int) -> list[str]:
    """the words in words with fewer than n letters, in order"""
    def keep(w: str) -> bool:
        return len(w) < n
    return my_filter(keep, words)

def test_shorter_than():
    assert shorter_than(["oak", "maple", "elm"], 5) == ["oak", "elm"]
    assert shorter_than(["oak", "maple", "elm"], 3) == []
```

- A helper that is one expression can be a `lambda` instead
  ([Class 10](/class/10)), which sees the parameters in the same way:
  `my_filter(lambda w: len(w) < n, words)`.

### A Single Point of Control

Say `my_filter` had a bug: it dropped the last element. Fixing it once fixes
`short_words`, `passing` and `shorter_than`, and every other function that calls
it. Had each been written in full, each would need the same fix, and one would
be missed. So abstract as soon as you notice you are writing a function for the
second time: copying a function and changing a line is the sign.
