## Notes (review before class)
### The Same Shape, Different Contents

A stack of pancakes ([Class 22](/class/22)) holds flavors. Here are the points
scored in a game, the latest first, as self-referential data of our own:

```python
@dataclass
class NoScores:
    pass

@dataclass
class Score:
    points: int
    earlier: "Scores"

Scores = NoScores | Score
```

Line it up against `Stack`: `Plate` is `NoScores`, `Pancake` is `Score`, and
`below` is `earlier`. Only one thing really differs, the type of what each
holds: a `str` for a flavor, an `int` for points. A flight's passengers
([Class 22](/class/22)'s Practice) would be the same again, with a passenger in
each. One data definition can cover all of them, with that type as a
parameter:

```python
@dataclass
class End[T]:
    pass

@dataclass
class Link[T]:
    first: T
    rest: "Chain[T]"

type Chain[T] = End[T] | Link[T]
```

- The `[T]` after a class's name makes it **generic**: `T` is a **type
  variable**, which stands for any one type. A `Chain[str]` is a chain of
  strings, like a stack of flavors; a `Chain[int]` is a chain of whole numbers,
  like scores.
- The last line is like `Stack = Plate | Pancake`. With a type variable in it,
  it needs the word `type` in front.
- `rest` is a `Chain[T]`, with the _same_ `T`: a chain of strings has a chain of
  strings as its rest, not a mix.

```python
flavors = Link("blueberry", Link("plain", End()))
points = Link(3, Link(10, Link(2, End())))
```

Python's lists are generic in the same way: `list[str]`, `list[int]`, or, for a
list of elements of any one type, `list[T]` (as in [Class 14](/class/14)'s
summary of list operations).

### Functions on Any List

`count_orders` ([Class 22](/class/22)) never looks at the elements: it would
count a list of anything, but its Signature says `list[int]`. With a type
variable, the Signature says what the function really does:

```python
def length[T](lst: list[T]) -> int:
    """how many elements lst has"""
    match lst:
        case []:
            return 0
        case [f, *r]:
            return 1 + length(r)

def test_length():
    assert length([]) == 0
    assert length([2, 4, 1]) == 3
    assert length(["oak", "elm"]) == 2
```

- The `[T]` after the function's name makes the function generic, or
  **polymorphic** (it has many forms): `T` is `int` in the second test, and
  `str` in the third.
- The tests use more than one type of element, since the Signature says it works
  for any.

### Type Variables Relate Types

A type variable says how the types in a Signature are related. Here, the result
has the same type as the list's elements, whatever that is:

```python
def last_or[T](lst: list[T], default: T) -> T:
    """the last element of lst, or default if lst is empty"""
    match lst:
        case []:
            return default
        case [f, *r]:
            if r == []:
                return f
            else:
                return last_or(r, default)

def test_last_or():
    assert last_or([], 0) == 0
    assert last_or([4, 1], 0) == 1
    assert last_or(["oak", "elm"], "none") == "elm"
```

- `default: T` says the default has the elements' type: `last_or(["oak"], 0)`
  breaks the Signature's promise, since `0` isn't a string.
- Without a sensible default, a function can give `None` ([Class 21](/class/21))
  for "no answer": a `T | None` is a `T`, or `None`.

```python
def first_or_none[T](lst: list[T]) -> T | None:
    """the first element of lst, or None if lst is empty"""
    match lst:
        case []:
            return None
        case [f, *r]:
            return f

def test_first_or_none():
    assert first_or_none([]) == None
    assert first_or_none(["oak", "elm"]) == "oak"
```

[Class 14](/class/14)'s summary gave `filter` and `map` this way: `filter`'s
result is a `list[T]` when its input is, the same type of element; `map`'s
result is a `list[R]` for some other type `R`, whatever the function it calls
gives.

### Generic in Two Types

A data definition can have more than one type variable. A pair holds two values,
of two types that may differ:

```python
@dataclass
class Pair[A, B]:
    left: A
    right: B

def swap[A, B](p: Pair[A, B]) -> Pair[B, A]:
    """p, with its left and right exchanged"""
    return Pair(p.right, p.left)

def test_swap():
    assert swap(Pair("elm", 3)) == Pair(3, "elm")
    assert swap(Pair(1, 2)) == Pair(2, 1)
```

- `Pair[str, int]` is a pair of a string and a whole number, and `swap` gives a
  `Pair[int, str]`. `Pair[int, int]` is fine too: two type variables may stand
  for the same type.

### When a Function Isn't Generic

`total_boxes` ([Class 22](/class/22)) adds the elements, so they must be numbers:
its Signature says `list[int]`, not `list[T]`. `T` promises that the function
works for _every_ type, so it can only use what every value can do. `length`
only counts, and `last_or` only passes elements along. A function that adds,
compares, or reads a field needs that type.

The same holds for data: `Chain[T]` doesn't care what it holds, but a data
definition whose functions read its elements' fields, like a flight's
passengers and their seats, is about that type.

### Comparing Without Knowing the Type

`==` compares too, so a generic function can't use it on two `T`s. It can be
given a function that compares them instead, the way `filter` is given one
([Class 14](/class/14)). The type of a function is a `Callable`:
`Callable[[T, T], bool]` takes two `T`s and gives a `bool`.

```python
def starts_with[T](lst: list[T], x: T, same: Callable[[T, T], bool]) -> bool:
    """whether same says lst's first element is the same as x"""
    match lst:
        case []:
            return False
        case [f, *r]:
            return same(f, x)

def test_starts_with():
    assert starts_with([], 3, lambda a, b: a == b) == False
    assert starts_with([3, 1], 3, lambda a, b: a == b) == True
    assert starts_with(["oak", "elm"], "ash", lambda a, b: len(a) == len(b)) == True
```

- `same(f, x)` calls the function `starts_with` was given, like any function.
- Whoever calls `starts_with` knows the type, so they choose what counts as the
  same: `==`, in a `lambda`, or, in the last test, having as many letters.

### Generic Data, Generic Template

The template for `Chain[T]` is the template for any self-referential data
([Class 22](/class/22)), with the type variable in its Signature:

```python
def _chain_temp[T](c: Chain[T]) -> ...:
    match c:
        case End():
            return ...
        case Link():
            ...
            c.first
            ...
            _chain_temp(c.rest)
            ...
            return ...

def chain_to_list[T](c: Chain[T]) -> list[T]:
    """the elements of c, in the same order, as a list"""
    match c:
        case End():
            return []
        case Link():
            return [c.first] + chain_to_list(c.rest)

def test_chain_to_list():
    assert chain_to_list(End()) == []
    assert chain_to_list(flavors) == ["blueberry", "plain"]
    assert chain_to_list(points) == [3, 10, 2]
```

### What PLL Checks

PLL checks a type like `list[int]` as the program runs, element by element:
`total_boxes([2, "4"])` stops, and says that item 1 isn't a whole number. It
checks a type variable by what it promises: a generic function can give back as
a `T` only a value it was given as a `T`. So `wrong_first` stops, since `5`
isn't one of them:

```python error
def wrong_first[T](lst: list[T], default: T) -> T:
    """the first element of lst, or default if lst is empty (but it isn't)"""
    return 5

wrong_first(["oak"], "none")
```

- A generic function can only pass its `T` values along: one that adds,
  compares (even with `==`), prints, or reads a field of a `T` stops too.
- A `Chain[int]` with a string in it is caught only where an annotation says
  `Chain[int]`: `Link(3, Link("x", End()))` on its own isn't.
- PLL checks only what runs, so test a generic function with more than one
  type, and with at least one that isn't a number.
