## Notes (review before class)
### The Design Recipe for Trees

Tree programs use the same recipe as lists, and as every function since
[Class 4](/class/4):

<DesignRecipe focus="Data definition, Template" />

- **Data definition**: including a base (leaf) case, and example trees, each
  built from smaller ones.
- **Template**: the cases and recursive calls, one for each subtree (as for
  `in_tree` in [Class 23's notes](/class/23)).
- The Recap's `height` goes through every step.

### Binary Search Trees

- A **binary search tree** (BST) stores _values_ at ordered _keys_ (often
  numbers), for quick lookup. Each node has a key, a value, and two subtrees.
- Its **invariant**, a rule the types can't express (so we write it as a
  comment): keys are unique; keys in a node's left subtree are less than the
  node's key, and keys in its right subtree are greater.
- So a lookup that misses at the root searches only _one_ subtree; if the
  subtrees are about the same size, each step rules out half the nodes.
- The worst case follows the longest path from the root to an empty leaf: the
  tree's **height** (computed with `max(a, b)`, the larger of two numbers).
- In a **balanced** tree (subtrees of about the same size, at every level), the
  height is about log₂ n, for n nodes; a list may need to look at all n. For
  n = 1,000,000, that's about 20 vs. 1,000,000.

## Recap (20 mins)

After Class 23's river networks, another binary tree: a BST with a number key
and a string value at each node. The program follows the recipe, for `height`:

- **Data definition**: `BST`, with its invariant as a comment, and example trees
  `BST0` to `BST3`, each built from the ones before.
- **Signature** and **Docstring**: from a `BST` to an `int`, the number of nodes
  on the longest path from the root to an `EmptyLeaf`.
- **Examples**: one for each example tree.
- **Template**: `bst_temp`, a `case` per variant, with a recursive call on each
  subtree.
- **Body**: a `Node`'s height is one more than the larger of its subtrees'
  heights, so `max` combines the two recursive calls.

Read through the program:

```python
@dataclass
class EmptyLeaf:
    pass

@dataclass
class Node:
    key: int
    val: str
    left: "BST"
    right: "BST"

BST = EmptyLeaf | Node
# Invariant: keys are unique, and all nodes in the left
# subtree have keys less than the key in the current node,
# all nodes in the right subtree have keys greater than
# the key in the current node

BST0 = EmptyLeaf()
BST1 = Node(1, "hello", BST0, BST0)
BST2 = Node(5, "bye", BST1, BST0)
BST3 = Node(6, "bye", BST2, Node(10, "cs2000", BST0, BST0))

# def bst_temp(bst: BST) -> ...:
#     match bst:
#         case EmptyLeaf():
#             ...
#         case Node(k, v, left, right):
#             ... k ...
#             ... v ...
#             ... bst_temp(left) ...
#             ... bst_temp(right) ...

def height(bst: BST) -> int:
    """returns the number of nodes on the longest path from the root of bst
    to an EmptyLeaf"""
    match bst:
        case EmptyLeaf():
            return 0
        case Node(k, v, left, right):
            return 1 + max(height(left), height(right))

def test_height():
    assert height(BST0) == 0
    assert height(BST1) == 1
    assert height(BST2) == 2
    assert height(BST3) == 3
```

- Draw `BST3`. Which keys are in its left subtree, and why must they be there?
  Which nodes would you visit looking for key 10? For key 7?
- What is `height(Node(20, "big", BST3, BST0))`?
- What would `height` compute if its last line were
  `return 1 + height(left) + height(right)`? Which example would catch that?
- Which parts of `bst_temp` does `height` drop?

## Class Exercises (35 mins)

1. The main goal of a BST is to be able to look up values at a given key. Design a function `retrieve` that takes a `BST`, a number, and returns a `str | None` (see [Class 20](/class/20)) -- if the given number exists as a key in the tree, your function should return `v`, the string value that is on the node with the key. If the given number doesn't exist, your function should return `None`. Start from `bst_temp`: which of its recursive calls does a `Node` need, and how does the invariant tell you?
2. In order for BSTs to have the performance characteristics that define them, they have to be balanced. This means not that each subtree is the _same size_ (this would only allow trees that had number of elements equal to a power of 2), but rather, that each subtree is close to the size of the other. Rather than measuring size, often BSTs compare _heights_, calculated as we did with our `height` function above. Design a function `is_balanced` that should take a `BST` and return a boolean that indicates if the tree is balanced: this means that at every level, the height of the left and right subtrees differs by at most 1. 

3. Programs are also often tree shaped! In this exercise, we consider something simpler than full programs -- arithmetic expressions. Design a data definition `Arith` that allows you to represent numbers, addition of two arithmetic expressions, multiplication of two arithmetic expressions, division of two arithmetic expressions, and subtraction of two arithmetic expressions. This should be a binary tree with one leaf constructor (for numbers) and _four_ node constructors (for the four types of binary operations). 

4. Define constants using your `Arith` to represent the following expressions (these are your data definition's examples):
  ```
  1 + 2
  1 * (3/4)
  (7-3) * (2 + (5/2))
  ```

5. Design a function `evaluate` (we can't call it `eval`, since Python already has a built-in function with that name) that takes an `Arith` and returns the single number to which it evaluates. Write its template first: a `case` for each of the five variants, with a recursive call on each field that is an `Arith`. If you use the three examples from exercise 4, your test cases should result in `3`, `0.75`, and `18`. 

## Wrap-up (5 mins)

- BSTs are a powerful idea, and there are sophisticated algorithms to handle inserting and deleting data from them while maintaining balance. The core of their performance is exactly as you've seen, however. 
- Trees also show up in many other problems!
- Template of the day: [recursive data](/class/recipe#template-recursive), for
  any tree: a `case` per variant, and a recursive call on each subtree. The body
  may use all of them (`height`) or only some (`retrieve`).
