## Notes (review before class)
### Structured Data

- Some data has several _attributes_ that belong together: a book has a title,
  an author, and a number of pages; a bake-sale order has a name, an item, and
  a number of boxes.
- **Structured data**: a single datum made of a _fixed_ number of parts, called
  **fields**, which can have different types (and can themselves be structured:
  a date has a day, month, and year).

### Defining Structured Data

Until now, the recipe's **Data definition** step was in words: "a number of
boxes", "a row with `time` and `amount` columns". From today it is code, and it
comes before any function on the data:

<DesignRecipe focus="Data definition, Template" />

A **dataclass** defines a new type, with a type annotation for each field
(PLL gives every file `dataclass`; in plain Python, the file must have
`from dataclasses import dataclass` near the top). A library program keeps a
record of each book:

```python
@dataclass
class BookRecord:
    title: str
    author: str
    pages: int
```

- The names of types we define start with a capital letter.
- `BookRecord` is also a **constructor**: a function that takes a value for each
  field, in order, and returns a new `BookRecord`.
- Always follow a data definition with a few named examples, which the
  Examples step of every function on the data uses again:

```python
the_dispossessed = BookRecord("The Dispossessed", "Ursula K. Le Guin", 387)
to_the_lighthouse = BookRecord("To the Lighthouse", "Virginia Woolf", 209)
brave_new_world = BookRecord("Brave New World", "Aldous Huxley", 268)
```

- In the directory, each example is a name for a `BookRecord` value, like any
  other.
- The new type can be used in annotations:
  `the_dispossessed: BookRecord = BookRecord(...)`. (Try annotating it as `str`
  instead, to see the error.)
- The constructor's inputs go in the fields' order:
  `BookRecord("Brave New World", 268, "Aldous Huxley")` is an error, and PLL
  says that `author` and `pages` look swapped.

### Field Access

`b.pages` is the `pages` field of `b`. A function on books, with the recipe:

- **Data definition**: `BookRecord`, and its examples, above.
- **Template**: a dataclass's parts are its fields, so the template lists them
  ([templates for structured data](/class/recipe#template-fields)), as the row
  template listed a row's columns ([Class 8](/class/8)):

```python
def _book_record_temp(b: BookRecord) -> ...:
    ...
    b.title
    ...
    b.author
    ...
    b.pages
    ...
    return ...
```

- **Signature** and **Docstring**: how many pages are left, after reading some.
  The function takes a number of pages read, too, which is a number, with one
  part of its own:

```python
def pages_left(b: BookRecord, pages_read: int) -> int:
    """how many pages of b are left to read, after reading pages_read of them"""
    ...
```

- **Examples**: tests, with the data definition's examples as inputs:

```python
def test_pages_left():
    assert pages_left(the_dispossessed, 0) == 387
    assert pages_left(to_the_lighthouse, 9) == 200
```

- **Body**: copy the template's body into `pages_left`. It only needs the
  pages, so the other two fields' lines go:

```python
def pages_left(b: BookRecord, pages_read: int) -> int:
    """how many pages of b are left to read, after reading pages_read of them"""
    return b.pages - pages_read
```

- Try: what are `brave_new_world.author` and `pages_left(brave_new_world, 68)`?
  If the library also recorded the year each book was published, which lines
  would change?
