### Filtering Lists

The `Promo Code` column holds strings, including `"none"`, which we put in
while cleaning; it isn't a real code:

```python
codes = cleaned_data.column("Promo Code")
# -> ['BAKE10', 'none', 'BAKE10', 'none', 'FRIEND', 'none', 'FRIEND', 'none', 'BAKE10', 'none']
```

As `filter` keeps some rows of a table, the built-in `filter` keeps some
elements of a list:

```python
def real_code(c: str) -> bool:
    """whether c is an actual promo code (not none)"""
    return not (c == "none")

def test_real_code():
    assert real_code("FRIEND")
    assert not real_code("none")

list(filter(real_code, codes))  # -> ['BAKE10', 'BAKE10', 'FRIEND', 'FRIEND', 'BAKE10']
```

- For lists, `filter` takes the function first and the list second.
- Wrap the result in `list(...)` to get an ordinary list (see the aside).
- The function can check anything about an element, not just equality (e.g.,
  whether a code starts with `"BAKE"`).

<Aside title="Converting to a List">

On its own, `filter` gives back a value that works out its elements only when
something asks for them (an idea we won't need), and that shows as something
unhelpful:

```python
filter(real_code, codes)  # -> <filter object at 0x10ab3f250>
```

`list` converts its argument into a list. `map`, below, needs the same.

</Aside>

<Aside title="Naming Conventions">

The list is `codes`, plural, though the column is `Promo Code`, singular: a
column's name says what one row holds, and a list's name says what it is, many
values.

</Aside>

### Getting Elements by Position

How many orders came from `school.edu` email addresses? A task plan
([Class 12](/class/12)): get the email addresses (`column`), keep the
`school.edu` ones (`filter`), and count them (`len`, which works on lists as
well as strings).

To check an address's domain, `split` ([Class 12](/class/12)) gives a list of
the pieces of a string around a separator. To get one element, write its
position in square brackets; positions start at `0`, so `[1]` is the second:

```python
"2027-03-05".split("-")             # -> ['2027', '03', '05']
"priya.r@mail.com".split("@")[1]    # -> 'mail.com'
```

```python
def school_address(email: str) -> bool:
    """whether email is a school.edu address"""
    return email.split("@")[1] == "school.edu"

def test_school_address():
    assert not school_address("priya.r@mail.com")
    assert school_address("mbell@school.edu")

emails = ["mbell@school.edu", "priya.r@mail.com", "kiran@school.edu"]
len(list(filter(school_address, emails)))  # -> 2
```

On the whole `Email` column, this stops at Sam's `"sam.r at mail.com"`: with no
`@`, it splits into a one-element list, so `[1]` is an error. What could you do
about that?

### Transforming Lists

`map` transforms each element, like `transform_column` on tables (`filter` only
keeps elements, unchanged); wrap it in `list(...)` too. To get the usernames
from a list of addresses:

```python
def extract_username(email: str) -> str:
    """the part of an email address before the @ sign"""
    return email.split("@")[0]

def test_extract_username():
    assert extract_username("priya.r@mail.com") == "priya.r"
    assert extract_username("mbell@school.edu") == "mbell"

list(map(extract_username, ["priya.r@mail.com", "mbell@school.edu"]))  # -> ['priya.r', 'mbell']
```

### `map` and `filter` Together

A magazine records the discount code used on each subscription order, and wants
to know what discount each order got:

```python
discount_codes = ["NEWYEAR", "student", "NONE", "student", "VIP", "none"]

def percent_off(code: str) -> int:
    """the percent discount that code gives (0 if it isn't a real code)"""
    if code == "VIP":
        return 30
    elif code.lower() == "student":
        return 20
    elif code == "NEWYEAR":
        return 10
    else:
        return 0

def test_percent_off():
    assert percent_off("VIP") == 30
    assert percent_off("student") == 20
    assert percent_off("STUDENT") == 20
    assert percent_off("none") == 0

discounts = list(map(percent_off, discount_codes))
big_discounts = list(filter(lambda p: p >= 20, discounts))
```

- `discounts` is `[10, 20, 0, 20, 30, 0]`: `map` made one number per code, in
  order, so `discounts[4]` is `30`, from `"VIP"`.
- `big_discounts` holds numbers, not codes: `[20, 20, 30]`. Its helper is a
  `lambda`, since it's one comparison.
- `percent_off` handles `"student"` in any capitalization, with `.lower()`, so
  its tests check two. But `percent_off("vip")` is `0`, and
  `"vip" in discount_codes` is `False`: the data definition has to say which
  codes can come in lower case.

### The List Template


A function on a list works with it in one of three ways, as a function on a
table does ([Class 9](/class/9)): keep some of the elements, change each one, or
combine them into one value. That's the **list template**
([templates for lists](/class/recipe#template-lists)), side by side with the
table template:

| The answer | For a table | For a list |
| --- | --- | --- |
| fewer of them | `t.filter(keep)` | `list(filter(keep, lst))` |
| each one changed | `t.transform_column("col", f)` | `list(map(f, lst))` |
| one value | a summary of a column ([Class 13](/class/13)) | `sum(lst)`, `len(lst)`, `max(lst)`, `S.mean(lst)` |

The first two have templates, like the table's, each with its helper as a local
function; for one value, there's a built-in to use:

```python
def _keep_elements_temp(lst: list) -> list:
    def keep(x: ...) -> bool:
        ...
        x
        ...
        return ...
    return list(filter(keep, lst))

def _change_elements_temp(lst: list) -> list:
    def change(x: ...) -> ...:
        ...
        x
        ...
        return ...
    return list(map(change, lst))
```

The question that picks it: does the answer have fewer elements, each element
changed, or one value? As for tables, the choice fixes the helper's Signature:
`keep` takes an element and gives a `bool`, and `change` takes an element and
gives its new value. Fill the helper in where it is, or design it as a function
of its own and pass that.

### Summary of List Operations

If `lst` is a `list[T]` (a list whose elements all have some type `T`):

- `list(filter(keep, lst))`, where `keep` is a function from `T` to `bool`:
  a `list[T]` of the elements on which `keep` returns `True`.
- `list(map(f, lst))`, where `f` is a function from `T` to some type `R`:
  a `list[R]` of the results of calling `f` on each element.
- `len(lst)`: the number of elements, an `int`.
- `lst[i]`: the element at position `i` (counting from `0`), as `t.row(i)` is
  for a table.
- `x in lst`: whether `x` is an element of `lst` (as `in` checks whether one
  string contains another): `"cookies" in ["cookies", "brownies"]` is `True`.

A **type variable** like `T` stands for any one type, and says how types are
related: `filter`'s result has the same element type as its input, while
`map`'s may have another. Python has
[more built-in functions](https://docs.python.org/3/library/functions.html).

A function from a list of addresses to their usernames, with the recipe:

<DesignRecipe focus="Template" />

- **Data definition**: a `list[str]` of email addresses, each with an `@`.
- **Template**: a list's templates, `_keep_elements_temp` and
  `_change_elements_temp`, or a built-in that combines the elements into one
  value. Which one depends on the answer, so the Body picks it.
- **Signature** and **Docstring**: from a `list[str]` to a `list[str]`:

```python
def usernames(addresses: list[str]) -> list[str]:
    """the username of each of the email addresses, in order"""
    ...
```

- **Examples**: tests on an empty list, and on one with two addresses:

```python
def test_usernames():
    assert usernames([]) == []
    assert usernames(["priya.r@mail.com", "mbell@school.edu"]) == ["priya.r", "mbell"]
```

- **Body**: the answer has each element changed, so it starts from
  `_change_elements_temp`, a `map`, whose `change` goes from an address to a
  username. That's `extract_username`, above, designed as a function of its own,
  with its own recipe:

```python
def usernames(addresses: list[str]) -> list[str]:
    """the username of each of the email addresses, in order"""
    return list(map(extract_username, addresses))
```

### Combining Lists and Tables

- Table methods mostly work on rows, and list functions on a column; an
  analysis of some rows and some columns uses both.
- There's often more than one plan. "How many orders from `school.edu`
  addresses were for 3 or more boxes?":
  1. `filter` the rows by address, then by boxes; count the rows (`length`).
  2. One `filter`, checking both; `length`.
  3. `filter` the rows by boxes; extract the emails (`column`); a list `filter`
     for `school.edu`; `len`.
- The answer is 2, but plans 1 and 2 stop at Sam's address, which `split`
  can't handle, while plan 3 never reaches it: Sam ordered 1 box. A plan that
  works on clean data may not work on the data you have.
- None is the one right answer. Are the intermediate results (the big orders,
  their emails) useful for anything else? Would you rather keep working on
  rows, and extract a list only for what tables can't do? Teams often agree on
  a style; otherwise, consider a few plans, then pick one.
- Soon we'll write list functions ourselves, and they won't seem so magical.
