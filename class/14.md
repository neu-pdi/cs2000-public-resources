### Filtering Lists

The `Discount Code` column holds strings, including `"none"`, which we added
while cleaning; it isn't a real code:

```python
codes = cleaned_data.column("Discount Code")
# -> ['BIRTHDAY', 'none', 'STUDENT', 'none', 'STUDENT', 'none', 'STUDENT']
```

As `filter` keeps some rows of a table, the built-in `filter` keeps some
elements of a list:

```python
def real_code(c: str) -> bool:
    """determines whether c is an actual discount code (not none)"""
    return not (c == "none")

def test_real_code():
    assert real_code("STUDENT")
    assert not real_code("none")

list(filter(real_code, codes))  # -> ['BIRTHDAY', 'STUDENT', 'STUDENT', 'STUDENT']
```

- For lists, `filter` takes the function first and the list second.
- Wrap the result in `list(...)` to get an ordinary list (see the aside).
- The function can check anything about an element, not just equality (e.g.,
  whether a string is all lowercase).

<Aside title="Converting to a List">

Alone, `filter` returns a special value that produces its elements one at a
time, as needed (an idea we won't cover), and shows as something unhelpful:

```python
filter(real_code, codes)  # -> <filter object at 0x10ab3f250>
```

`list` converts its argument into a list. `map`, below, needs the same.

</Aside>

<Aside title="Naming Conventions">

The list is `codes` (plural), though the column is `Discount Code` (singular): a
list holds many values, while a column name names the single value in one row.

</Aside>

### Getting Elements by Position

How many sales went to `web.com` email addresses? A task plan
([Class 12](/class/12)): get the email addresses (`column`), keep the `web.com`
ones (`filter`), and count them (`len`, which works on lists as well as
strings).

To check an address (rather than look at its last 8 characters), `split`
([Class 12](/class/12)) gives a list of the pieces of a string around a
separator. To get one element, write its position in square brackets; positions
start at `0`, so `[1]` is the second:

```python
"this-has-hyphens".split("-")  # -> ['this', 'has', 'hyphens']
"bonnie@pyret.org".split("@")[1]  # -> 'pyret.org'
```

```python
def web_com_address(email: str) -> bool:
    """determines whether email is from web.com"""
    return email.split("@")[1] == "web.com"

def test_web_com_address():
    assert not web_com_address("bonnie@pyret.org")
    assert web_com_address("parrot@web.com")

emails = ["parrot@web.com", "bonnie@pyret.org", "polly@web.com"]
len(list(filter(web_com_address, emails)))  # -> 2
```

### Transforming Lists

`map` transforms each element, like `transform_column` on tables (`filter`
only keeps elements, unchanged); wrap it in `list(...)` too. To get the
usernames from a list of addresses:

```python
def extract_username(email: str) -> str:
    """extracts the portion of an email address before the @ sign"""
    return email.split("@")[0]

def test_extract_username():
    assert extract_username("bonnie@pyret.org") == "bonnie"
    assert extract_username("parrot@web.com") == "parrot"

list(map(extract_username, ["parrot@web.com", "bonnie@pyret.org"]))  # -> ['parrot', 'bonnie']
```

### The List Template

A function on a list works with it in one of three ways, as a function on a
table does ([Class 9](/class/9)): keep some of the elements, change each one, or
combine them into one value. That's the **list template**
([templates for lists](/class/recipe#template-lists)), side by side with the
table template:

| The answer | For a table | For a list |
| --- | --- | --- |
| fewer of them | `t.filter(keep)` | `list(filter(keep, lst))` |
| each one changed | `t.transform_column("col", f)` | `list(map(f, lst))` |
| one value | a summary of a column ([Class 13](/class/13)) | `sum(lst)`, `len(lst)`, `max(lst)`, `S.mean(lst)` |

```python
# def list_fun(lst: list) -> ...:
#     return list(filter(keep, lst))   # fewer elements: keep(x) -> bool
#     return list(map(f, lst))         # each one changed: f(x) -> ...
#     return sum(lst)                  # one value (also len, max, min)
```

The question that picks it: does the answer have fewer elements, each element
changed, or one value? As for tables, the choice fixes the helper's Signature.

### Summary of List Operations

If `lst` is a `list[T]` (a list whose elements all have some type `T`):

- `list(filter(keep, lst))`, where `keep` is a function from `T` to `bool`:
  a `list[T]` of the elements on which `keep` returns `True`.
- `list(map(f, lst))`, where `f` is a function from `T` to some type `R`:
  a `list[R]` of the results of calling `f` on each element.
- `len(lst)`: the number of elements, an `int`.
- `lst[i]`: the element at position `i` (counting from `0`), as `t.row(i)` is
  for a table.
- `x in lst`: whether `x` is an element of `lst` (as `in` checks whether one
  string contains another): `"rice" in ["rice", "lentils"]` is `True`.

A **type variable** like `T` stands for some unspecified type, and shows
_relationships_ between types: `filter`'s output has the same element type as
its input; `map`'s may differ. Python has
[more built-in functions](https://docs.python.org/3/library/functions.html).

A function from a list of addresses to their usernames, with the recipe:

<DesignRecipe focus="Template" />

- **Data definition**: a `list[str]` of email addresses, each with an `@`.
- **Signature** and **Docstring**: from a `list[str]` to a `list[str]`:

```python
def usernames(addresses: list[str]) -> list[str]:
    """the username of each of the email addresses, in order"""
    ...
```

- **Examples**: tests on an empty list, and on one with two addresses:

```python
def test_usernames():
    assert usernames([]) == []
    assert usernames(["parrot@web.com", "bonnie@pyret.org"]) == ["parrot", "bonnie"]
```

- **Template**: the answer has each element changed, so it's a `map`, which
  needs a helper from an address to a username: `extract_username`, above,
  designed with its own recipe.
- **Body**:

```python
def usernames(addresses: list[str]) -> list[str]:
    """the username of each of the email addresses, in order"""
    return list(map(extract_username, addresses))
```

### Combining Lists and Tables

- Table methods mostly process rows, list functions columns; an analysis of
  some rows and some columns uses both.
- There's often more than one plan. "How many people with `.org` addresses
  bought more than 8 tickets?":
  1. `filter` rows by tickets, then by `.org`; count rows (`length`).
  2. One `filter`, checking both; `length`.
  3. `filter` rows by tickets; extract emails (`column`); list `filter` for
     `.org`; `len`.
- None is the one right answer. Are intermediate results (the large orders,
  their emails) useful elsewhere? Do you prefer working on rows, extracting
  lists only for what tables can't do? Which uses fewer resources? (Filtering
  a table costs no more than filtering a list; more later.) Teams may set
  design standards; otherwise, consider several approaches, then pick one.
- Soon we'll write list functions ourselves, and they won't seem so magical.

## Recap (20 mins)

A magazine records the discount code used on each subscription order (perhaps
from a column of a table), and wants to know what discount each order got. Read
through the program:

```python
discount_codes = ["NEWYEAR", "student", "NONE", "student", "VIP", "none"]

def percent_off(code: str) -> int:
    """the percent discount that code gives (0 if it isn't a real code)"""
    if code == "VIP":
        return 30
    elif code.lower() == "student":
        return 20
    elif code == "NEWYEAR":
        return 10
    else:
        return 0

def test_percent_off():
    assert percent_off("VIP") == 30
    assert percent_off("student") == 20
    assert percent_off("STUDENT") == 20
    assert percent_off("none") == 0

discounts = list(map(percent_off, discount_codes))
big_discounts = list(filter(lambda p: p >= 20, discounts))
```

- What is `discounts`? What is `discounts[4]`, and which code produced it?
- Does `big_discounts` hold codes or numbers? What is `len(big_discounts)`?
- Why does the test check both `"student"` and `"STUDENT"`? What are
  `percent_off("vip")` and `"vip" in discount_codes`?
- Which shape of the list template makes `discounts`, and which makes
  `big_discounts`? Which template does `percent_off` fill in?
