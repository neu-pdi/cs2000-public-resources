## Problem 3

We use emojis to represent ourselves and our thoughts; the people who design
them have to decide what an emoji looks like, and which ones there are.

Below is a stakeholder matrix for emoji design: groups of people who have
something at stake in it, on the left, and what they value, on the right. Fill
in the two stakeholders. You are _not_ designing an emoji: you are working out
who would want emojis to have each of these qualities.

| Stakeholders | Interest/Value |
| -- | -- |
| Stakeholder 1 | Simplicity |
| Stakeholder 2 | Representation |

## Problem 4

Last summer, you noticed a lot of kids selling lemonade at little stands. You
noticed two that were next to each other that had different pricing and
different materials. You were curious which strategy would work better, so in
this problem you will model both stands.

### Part A

The first stand was getting 16 fluid ounce bottles of lemonade from a shop right
around the corner, for \$2 each, and was selling 4 fluid ounce cups for \$1 each.
For simplicity, we'll ignore the cost of the cups, refrigeration, etc., and you
can assume the corner shop never runs out of 16 fluid ounce bottles.

Design a function `lemonade_stand_1` that takes a number of cups sold as input
and returns the total profit. Be sure to take into account that the 16 fluid
ounce bottles cannot be purchased in part, so there may be extra left over!
Hint: the Python operator `%` (which calculates the remainder of division) may
be useful.

### Part B

The second stand decided to buy the lemonade in bulk, getting a gigantic 5
gallon (640 fluid ounce) container for \$20. To try to undercut the other stand,
they decided to sell their 4 fluid ounce cups for \$0.75 each. But, since they
bought their lemonade from a store that is far from home, when they run out,
they will stop being able to sell lemonade.

Design a function `lemonade_stand_2` that takes a number of cups (attempted to
be) sold as input and returns the total profit. Note that this input may be any
positive integer, so if it exceeds their capacity, the function should simply
return their profit before they closed the stand. Note that if they sell the
entirety of their lemonade, there is no penalty for being unable to sell
additional cups. As before, we aren't considering cost of cups, refrigeration,
etc.

### Part C

Now, you'd like to design a function `which_stand_better` that, given a number
of cups sold, returns the number 1 if lemonade stand 1 would make more money at
that number of cups, or 2 if lemonade stand 2 would make more money with that
number of cups sold. If they are tied, return 0.

## Problem 5

You've found a malfunctioning encryption device that scrambles secret messages
into code, and its documentation is missing. Your mission is to work out what
each of its ten black-box functions does, so that you can write them yourself.

The device has ten functions, `support.encryptor1` through
`support.encryptor10`. Each takes a `str` and gives back a new, "encrypted"
`str`. For each, there is a tester, `support.test_encryptor1`,
`support.test_encryptor2`, and so on, that checks whether your version matches
the original on all inputs.

For each encryptor:

1. **Experiment.** Call `support.encryptorN` on a variety of strings, and work
   out the rule it follows. Keep a log, in comments, of what you tried and what
   came out: you're a detective.
2. **Recreate.** Write your own function that does the same thing, using
   [Python's string operations](https://docs.python.org/3/library/stdtypes.html#string-methods)
   (`len`, slicing with `s[start:end]`, `s.find(...)`, and so on):

   ```python skip
   def my_encryptor1(s: str) -> str:
       ...
   ```

3. **Verify.** Pass your function to its tester. If it finishes without errors,
   your version is right!

   ```python skip
   support.test_encryptor1(my_encryptor1)
   ```

Recreate as many of the encryptors as you can. Here is one that gives just the
first character of a string (`s[0]` is the character at position 0 of `s`). Its
tests check that it fails on an empty string, which has no character at position
0, with `pytest.raises`: the code indented under it must cause an error of the
given kind, here an `IndexError`.

```python
import pytest

def encryptor0(s: str) -> str:
    """returns the first letter of the string"""
    return s[0]

def test_encryptor0():
    # Doesn't work on empty strings
    with pytest.raises(IndexError):
        encryptor0("")
    # Otherwise, returns first letter
    assert encryptor0("a") == "a"
    assert encryptor0(" ") == " "
    assert encryptor0("hello") == "h"
    assert encryptor0("1, ") == "1"
```

Hints:

- Vary the strings you try. In what ways can strings differ?
- Think of where you see text, like a book or a report. What symbols other than
  letters are in it?
- Positions in a string start at 0, not 1.
- Encryptor 7 is one of the trickiest. Try strings of different lengths that
  start with the same letters. What do you notice?
