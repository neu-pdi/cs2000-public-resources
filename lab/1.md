## Purpose

Practice Python's string operations, by working out what a function does from
what it gives back, and then writing it yourself.

## Pairing

Work in pairs, with one laptop open: the **driver** types, and the **copilot**
reads ahead, suggests what to try, and catches mistakes. Both of you say what
you're thinking. Switch roles at each encryptor. This is how your
[pairing sessions with a TA](/syllabus#pair-programming-sessions) work, with you
as the driver. Attendance is taken (see [Labs](/syllabus#labs)).

## The Encryptors

You've found a malfunctioning encryption device that scrambles secret messages
into code, and its documentation is missing. Your mission is to work out what
each of its ten black-box functions does, so that you can write them yourself.

Put this line under your file's `#level` line:

```python skip
#bundle support https://raw.githubusercontent.com/neu-pdi/cs2000-public-resources/refs/heads/python/static/bundles/lab1-support.json
```

It gives your file the device, as `support`, with no `import`. The device has
ten functions, `support.encryptor1` through `support.encryptor10`. Each takes a
`str` and gives back a new, "encrypted" `str`. For each, there is a checker,
`support.check_encryptor1`, `support.check_encryptor2`, and so on, that tries
your version and the original on the same strings.

For each encryptor:

1. **Experiment.** Call `support.encryptorN` on a variety of strings, and work
   out the rule it follows. Keep a log, in comments, of what you tried and what
   came out: you're a detective.
2. **Recreate.** Write your own function that does the same thing, using
   [Python's string operations](https://docs.python.org/3/library/stdtypes.html#string-methods)
   (`len`, slicing with `s[start:end]`, `s.find(...)`, and so on):

   ```python skip
   def my_encryptor1(s: str) -> str:
       ...
   ```

3. **Verify.** Pass your function to its checker. When your version gives what
   the original gives on every string the checker tries, it says so
   (`'All 5 tests passed!'`, for encryptor 1). Otherwise it stops at the first
   string where they differ, and says what each gave.

   ```python skip
   support.check_encryptor1(my_encryptor1)
   ```

Recreate as many of the encryptors as you can. Here is one that gives just the
first character of a string (`s[0]` is the character at position 0 of `s`). Its
tests check that it fails on an empty string, which has no character at position
0, with `pytest.raises`: the code indented under it must cause an error of the
given kind, here an `IndexError`.

```python
import pytest

def encryptor0(s: str) -> str:
    """returns the first letter of the string"""
    return s[0]

def test_encryptor0():
    # Doesn't work on empty strings
    with pytest.raises(IndexError):
        encryptor0("")
    # Otherwise, returns first letter
    assert encryptor0("a") == "a"
    assert encryptor0(" ") == " "
    assert encryptor0("hello") == "h"
    assert encryptor0("1, ") == "1"
```

Hints:

- Vary the strings you try. In what ways can strings differ?
- Think of where you see text, like a book or a report. What symbols other than
  letters are in it?
- Positions in a string start at 0, not 1.
- Encryptor 7 is one of the trickiest. Try strings of different lengths that
  start with the same letters. What do you notice?
