## Pairing

Work in pairs, with one laptop open: the **driver** types, and the **copilot**
reads ahead, suggests what to try, and catches mistakes. Both of you say what
you're thinking. Switch roles at each problem. This is how your
[pairing sessions with a TA](/syllabus#pair-programming-sessions) work, with you
as the driver. Attendance is taken (see [Labs](/syllabus#labs)).

## Loops, Then `map` and `filter`

Design each of Problems 1 to 4 with a `for` loop first, then again with `map` or
`filter` (and no variables that change). Some take a single `map` or `filter`;
others need another function too, like `len`.

## Problem 1

`absolute_values`: each number in a list, made non-negative (with `abs`).

## Problem 2

`exactly_three_chars`: only the strings in a list that have exactly 3
characters.

## Problem 3

`all_even`: whether every number in a list is even.

## Problem 4

`count_in_range`: how many numbers in a list are between a minimum and a
maximum, both included.

## Problem 5

Design `c_to_f`, which takes a list of temperatures in Celsius, and gives them in
Fahrenheit (the formula is `c * 9/5 + 32`). Which of `map` and `filter` fits?

## Problem 6

Design `long_words_upper`, which takes a list of words, and gives the words
longer than 4 characters, in upper case. Which happens first, `filter` or `map`?
Does the order matter?

## Problem 7

Design `sum_positives`, which adds up only the positive numbers in a list, with a
`for` loop (no `map` or `filter`).

## Problem 8

A function can give back two values at once, as a **tuple**: values in
parentheses, separated by commas, like `("hello", 2000)`.
`return word, len(word)` returns one (the parentheses can be left out there),
its type is `tuple[str, int]`, and `longest, size = longest_word_info(words)`
takes the result apart into two names. Design `longest_word_info`, which takes a
list of strings that isn't empty, and gives the longest one, and its length.
