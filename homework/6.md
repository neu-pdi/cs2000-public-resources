## Project 3: Talk Me Through It (continued)

:::info[Your repository]

Keep working in the repository you made for Project 3 in [Homework 5](/homework/5#your-repository).

:::

[Homework 5](/homework/5) gave you a conversation, built from a table and run
with `input()`. This homework, the end of Project 3, keeps a record of each
conversation as it happens, runs it more than once, and reports on the
conversations it has had. The tree itself doesn't change: what changes is the
record.

### Required pieces

As before: every function by the whole [recipe](/class/recipe), and your
pieces listed at the top of `project.py`, continuing Homework 5's list.

9. **A record of one conversation** (Class 27). A dataclass that records a
   conversation as it happens: the options chosen so far (a list), how many
   steps it has taken, and its outcome, once it reaches one. Then a function
   that adds one answer to a record, by changing that record, rather than making
   a new one. Test it as Class 27 tests changes: set up a record, call the
   function, then check the record's fields.
10. **Recording as it goes.** Change `talk` so that it also takes a record, and
    adds each answer to it as the person goes. At an outcome, it saves the
    outcome in the record, and prints the options chosen, as well as the
    outcome.
11. **Aliasing** (Class 27). Say every conversation starts from one starting
    record, `START`. Show with a test what goes wrong: the second conversation's
    record begins with the first one's answers. In a comment by the test,
    explain why, in terms of the directory and the heap: after the two
    conversations, which names refer to which records? Then fix it, so that each
    conversation gets a record of its own, and show with the same test that it's
    fixed.
12. **More than one conversation, and a report** (Classes 7, 12, and 27). After
    each conversation, ask whether to have another: another recursive call, not
    a loop. Keep a log: a list of the conversations' records, which each
    conversation adds its record to. At the end, make a table from the log, and
    report how many conversations reached each outcome, and the mean number of
    steps they took.
13. **Tests** for every function that doesn't call `input()`.
14. **A piece of your own**, as in Homework 5: a function that does something
    none of the other pieces (in either homework) do. For example, it could
    find the options people choose most often; give an outcome that depends on
    the record (a different message for a short conversation); or make a second
    report from the log. Your project must use
    it, and its Docstring says what it does for the people using your
    conversation.
15. **The README, finished.** Writing, in `README.md`: who the conversation is
    for, what it helps them do, what the report showed, and how to start a
    conversation (which file to run, and what to call). Write it for someone
    who has never seen this course: it's how you'll describe the project to
    anyone else.

If you finish with time to spare: draw a picture for each step, from shapes (as
in Project 1). Or run the conversation with a reactor instead of `input()`,
with options clicked (as in Project 2).

### In the crit

About 15 minutes. Start by having two conversations with your program, and
showing its report (3 minutes). Then the panel picks several pieces from your
list (from either homework), and you walk through each in the recipe's order.
Then the panel's questions.
